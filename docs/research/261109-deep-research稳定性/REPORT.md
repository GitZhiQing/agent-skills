## 摘要

提升 `deep-research` 稳定性，优先补齐：**显式状态与恢复、可观测的工具适配、重复运行评测**。纯提示词可改善决策和登记，但恢复、鉴权、幂等与注入防御必须由运行时保证。[S1][S2][S8][S9]

搜索建议“**ddgs 无密钥默认 + Tavily 首个备援 + Exa 第二适配器**”。Tavily 错误语义贴合现状；Exa 较复杂；Brave 需信用卡，暂不作首选。[S13][S16][S17][S18][S21][S22]

## 主要发现

### 1. 把“稳定”拆成可测指标

- **协议一致性**：确认、调整、取消、预算和落盘是否每次一致。
- **执行韧性**：超时、空结果、限流、配额耗尽、单 URL 失败后能否降级恢复。
- **内容可靠性**：完整性、深度、无依据断言率、引用准确性与有效引用数。DeepResearch Bench 将报告质量 RACE 与引用/检索 FACT 分开，值得借鉴。[S11][S12]
- **成本波动**：query、token、耗时、费用及其重复运行方差。

单次成功率看 pass@1；要求连续 k 次都成功应看 pass^k，而非“至少成功一次”的 pass@k。[S4]

### 2. 确认门应是显式状态机

LangGraph 与 OpenAI Agents 都将审批建模为可序列化、可恢复的暂停状态；未决审批保持 pending。恢复可能重放节点，因此副作用须后置或幂等，快照还需防伪造、并发和重放。[S1][S2][S25]

当前 skill 可定义 `proposed → confirmed/adjusted → running → paused/done/cancelled` 状态表，覆盖部分回答、模糊同意、确认后取消和中途调档。Azure 中文指南同样要求区分“批准推进”与“返回修改”，并在强制检查点外置状态。[S26]

还应先消除本地冲突：低档报告结构与 V-8、非源码 META 基线写法、SPEC/TESTS 与 SKILL 版本均不一致。规则矛盾会直接制造解释方差。

### 3. 统一工具故障语义

让 `deep-research` 只依赖 `search(query)`、`fetch(urls)`、标准结果、逐项错误和用量记录，provider 放进独立 web-access 适配层。故障至少区分超时、空结果、401、402、429、432/433/434、5xx 和单 URL 失败，分别规定重试、等待、切换与降级交付。

保留检查点、trace、外部产物引用和工具失败反馈，避免长任务从头重跑。[S3][S26] 登记簿应在首轮搜索前初始化，持续记录 query 台账、预算、规范化 URL、抓取状态和排除原因，兼作恢复点与评测证据。

### 4. 网页安全不能只靠提示词

OWASP 指出，内容定界和过滤不是可强制执行的安全边界。研究 Agent 应默认只读、最小权限，由执行层校验工具与参数；高风险动作需绑定对象和参数的一次性审批。注入测试须走真实抓取通道，并同时记录越权调用与正常请求误报。[S8][S9] `references/` 可补隔离规则，但不能宣称纯提示词已证明“不会执行注入”或“不会外发数据”。

### 5. 用干净上下文做重复对照评测

Agent Skills 官方建议 `evals.json`、客观断言、带证据的 PASS/FAIL、新旧版本对照，并记录通过率、耗时和 token；每次运行使用干净上下文。[S5][S6][S7]

可先将 V-1、V-4、V-5、V-8a、V-14、V-29 等转成 10~15 个核心场景，每个先跑 3 次，报告 pass@1、pass^3、故障恢复率和引用指标。机械检查用脚本，内容质量用分维度 LLM rubric 并抽样人工校准；结合 transcript 区分 skill、测试和评分器问题。[S4][S7]

### 6. 搜索 API 对比（政策核验于 2026-11-09）

| 方案 | 免费政策与门槛 | 搜索 / 正文能力 | 故障与配额语义 | 建议 |
| --- | --- | --- | --- | --- |
| ddgs | 无 key；受上游限流 | 多后端搜索；extract 支持 Markdown [S20] | 默认 HTTP 超时 5 秒；本地另有一次重试与 curl 回退，无上游 SLA | 无密钥默认，不作唯一执行路径 |
| Tavily | 每月 1000 credits；无需信用卡，需注册和 key [S16] | 搜索 1~2 credits；Extract 批量 1~20 URL，返回 Markdown [S17][S18] | 429/432/433/434 区分限速、计划与容量；支持 `Retry-After`、超时和 `failed_results` | **首个适配实测的备援** |
| Exa | 每月重置 10 美元 credits，约 2500 次 Lite；无需支付方式，需 key [S13] | lite/auto/deep、域名/日期过滤；正文、highlights、summary [S14][S15] | 402、429、live crawl 超时、逐 URL statuses；内容类型分别计费 | 第二适配器，验证精细过滤场景 |
| Brave | 每月赠 5 美元 credits；Search 为 5 美元/1000 请求，折算约 1000 次；需信用卡和 key [S21][S22] | Web Search、LLM Context；freshness、国家/语言和 snippets [S23] | 标称 50 请求/秒；限额、剩余量、重置响应头完整 [S21][S24] | 暂缓首选，需要其索引时再测 |

本次 15 个 query 中 8 轮超时或空结果；这只是当前环境的小样本，**不能推断 ddgs 整体故障率**，但说明统一日志、备用通道和降级交付确有必要。免费额度、单价和能力均非 SLA。

### 7. 分优先级落地路线

| 优先级 | 改进与本地落点 | 验收信号 |
| --- | --- | --- |
| P0 | `SKILL.md` 阶段 3~4、`docs/TESTS.md`：确认状态表；消除低档结构、META、版本冲突 | 部分回答、模糊确认、取消各连续 3 次一致；无确认前检索 |
| P0 | `execution-discipline.md`、`delivery-template.md`：初始化 query/预算/来源台账；META 记录当前阶段 | 中途可恢复；query 不超档；结论可回溯或标未知 |
| P0 | 独立 provider 适配层与故障矩阵；先验证 Tavily，保留 ddgs | 超时、429、余额、单 URL 失败按矩阵降级；密钥只读环境变量 |
| P0 | `execution-discipline.md` §4 与测试集：间接注入、外发诱导和误报 | 替代工具零越权调用；正常研究误拦率可追踪 |
| P1 | `evals/evals.json`、版本快照、干净上下文；分离能力集与回归集 | 输出 pass@1/pass^3、引用指标、无依据断言率、成本方差 |
| P1 | Tavily 实测后再验证 Exa；Brave 可选 | 同任务比较召回、正文成功率、延迟、费用和恢复率 |
| P2 | 仅高档、开放且可并行任务引入多 Agent | 相对单编排有净收益才保留 |

多 Agent 不是第一步：它适合开放式广度研究，但会增加 token 和协调故障；应采用满足要求的最低复杂度。[S3][S26]
