# Skills 开发与维护规范

版本：v2.0

适用范围：本仓库全部 skill 及仓库级维护脚本（`scripts/`）。README Skills 目录表与维护者本地台账（`SKILLS.local.md`）的格式标准也定义于本文档（§5），两者与本文档冲突时以本文档为准。格式字段以 [Agent Skills 官方规范](https://agentskills.io/specification) 为准（指针见 [spec/agent-skills-spec.md](../spec/agent-skills-spec.md)），本文档只写官方规范之上的仓库约定。机器可校验的规则由 `scripts/skills-lint.sh` 与 `scripts/skills-doctor.sh` 强制。

## 1. 范围与原则

- **一个 skill 一个目录，全部位于根 `skills/` 子目录下**，`SKILL.md` 是唯一入口与权威元数据来源；"skill 的定义" = `skills/` 下含 SKILL.md 的子目录（对齐 Agent Skills 社区惯例与 skills CLI 的发现规则，lint L-layout 强制）。
- **skill 目录自包含**：把单个 skill 目录拷走仍可用（代码 skill 自带 `bin/`、`scripts/`、`pyproject.toml`）；仓库级维护脚本放在根 `scripts/`，不进入 skill 目录。
- **分发单一来源**：各 agent 的 skills 目录（目标清单见 §6）只放指向本仓库的 junction/symlink，不拷贝。
- **渐进披露**：常驻上下文只有 `name` + `description`；`SKILL.md` 在触发时加载；条件分支、模板与长清单放 `references/`，按需读取（§2.1）。
- **文档分工**：`README.md` 面向人的仓库说明并承载对外唯一的 skill 目录表；`AGENTS.md` 面向 AI 会话的入口；本规范定义标准；`CONTRIBUTING.md` 给最短上手路径；`template/` 提供骨架；`spec/` 只放官方规范指针。维护者个人台账与状态记录在 `SKILLS.local.md`（本地文件，不入库）。

## 2. 目录结构标准

| 文件 / 目录 | 状态 | 说明 |
| --- | --- | --- |
| `SKILL.md` | **必需** | 入口与元数据，标准见 §3；目标 ≤500 行 / ≤16KB（§2.1） |
| `README.md` | **必需** | 面向人的目录导览：定位与触发场景、工作方式概要、安装方式、文档链接；CLI skill 另含用法、参数、排障。lint 强制存在（L-readme-file）；不写版本号，不复制 SKILL.md 全文 |
| `docs/测试集.md` | **条件必需** | 行为含可断言协议（何时触发 / 何时不触发 / 步骤约束）的 skill 必须有；新骨架默认生成；编号约定见 §7 |
| `docs/需求与设计文档.md` | 条件必需 | 决策多、有开放问题或多方案权衡的 skill 应有。md2pdf 使用 `docs/SPEC.md` + `docs/DECISIONS.md` 变体（范围契约 + 决策记录），等价有效 |
| `references/` | 条件必需 | 条件分支、输出模板、长清单、领域手册；只在 `SKILL.md` 指向时按需加载，距入口一层（§2.1） |
| `.claude-plugin/plugin.json` | **必需** | Claude Code plugin 元数据；`name` == 目录名，`version` 与 frontmatter 一致；lint 强制 |
| `bin/`、`scripts/`、`pyproject.toml` | 仅代码 skill | 位置无关启动器、实现脚本、依赖声明；形态见 §2.2 |
| `docs/` 其他文档（研究/灵感文档等） | 自由 | 建议在本地台账明细"文档"行登记 |

判定示例：theme-commit（纯提示词，但 4 步协议可断言）→ SKILL.md + README.md + docs/测试集.md + references/；ddgs-web-access（CLI）→ 全套；deep-research（纯提示词、协议复杂）→ SKILL.md + README.md + 测试集 + 设计文档 + references/。

### 2.1 渐进披露预算

三级加载，逐级放大：

1. **metadata（约 100 token）**：`name` + `description` 常驻，所有 skill 启动时可见。description 决定是否触发，写法见 §3.1。
2. **SKILL.md 正文（触发时加载）**：只放"每次都要执行的流程、硬规则、边界"和一张"按需读取"表。目标 **≤500 行且 ≤16KB**；超出时 lint warn。中文按 UTF-8 约 3 字节/字、约 1–1.5 字/token，16KB 约 4k–5.5k token；属上限而非目标。
3. **references（按需加载）**：条件分支（如"无口播时"、"批量时"）、交付模板、长清单、领域手册。规则：
   - 必须距 `SKILL.md` **一层**（`references/foo.md`），不建嵌套引用链；
   - `SKILL.md` 用"**何时**读**哪个**文件"指路（例："做源码调研前读 `references/执行纪律.md`"），禁止"详见 references/"；
   - 单个 reference >100 行时在文件头加目录；
   - 移动内容时只搬移、不改语义；搬移后升次位版本并回归。

脚本是第四层：确定性的重复操作写成 `scripts/` 下的可执行文件，其源码不进入上下文，只有 stdout 进入；脚本设计与输出约束见 §8.1。

### 2.2 Python 两种形态

| 形态 | 适用 | 结构 | 示例 |
| --- | --- | --- | --- |
| uv 包型 | 需要第三方依赖（网络、渲染、解析） | `pyproject.toml` + `src/<pkg>/`（或单文件）+ `bin/` 启动器；依赖由 uv 首次调用自动安装 | ddgs-web-access（单文件 CLI + pyproject）、md2pdf（src 布局） |
| 纯标准库脚本型 | 只依赖系统工具（ffmpeg 等），零 pip 依赖 | `scripts/` + `tests/`；环境依赖写进 frontmatter `compatibility` 与 README | video-insight |

不为统一而迁移：选择依据是"是否需要第三方依赖"，不是目录美观。两种形态都要求：位置无关启动（不依赖当前工作目录）、`--help`、退出码 0/1/2、状态走 stdout / 错误走 stderr。

## 3. SKILL.md Frontmatter 标准

| 字段 | 状态 | 标准 |
| --- | --- | --- |
| `name` | **必需** | 官方约束：1–64 字符，仅小写字母/数字/连字符，不以连字符开头或结尾、无连续连字符（`^[a-z0-9]+(-[a-z0-9]+)*$`），且与目录名一致。lint 强制（L-frontmatter / L-spec） |
| `description` | **必需** | 官方约束：1–1024 字符，不含 `<` / `>`。本仓库要求**三段式**：① 一句话定位（做什么）② 正向触发（场景 + 触发词）③ 反向不触发（什么情况下明确不用）。agent 依据 description 决定是否加载，三段式直接对应"何时用 / 何时不用"的判断输入。lint 强制非空、上限与尖括号，过短（<30 字符）warn |
| `metadata.version` | **必需** | semver（`X.Y.Z`），全部 skill 一律标注（纯提示词同样有迭代），规则见 §4。lint 强制 |
| `metadata.category` | **建议** | 领域标签，开放值集（现有：web / git / research / workflow / media / document / system），新值先更新本规范此处再使用；新 skill 应填写，缺失时 lint warn |
| `license` | 建议 | 许可名（如 `MIT`），对齐官方可选字段 |
| `compatibility` | 按需 | **标量字符串**，≤500 字符；描述系统依赖、网络与账号要求 |
| `allowed-tools` | 按需 | 空格分隔的工具授权串（官方实验字段），标量字符串，不用 YAML 列表 |
| 其他扩展字段 | 先立后用 | 新字段先进本规范再使用，保证三端 agent 语义统一（未知字段会被忽略，但本仓库内含义必须唯一） |

### 3.1 description 三段式

```yaml
description: >-
  <一句话定位：为 agent 解决什么问题。>
  当用户<正向场景；触发词如"…""…">时使用。
  当用户<反向场景：什么情况下明确不用>时，不要使用本 skill。
```

- 正向触发要含**具体关键词**，中文触发词之外补 1–2 个英文触发词（如 "web search" / "commit" / "video analysis"），提高英文会话的触发率。
- 反向不触发写**近邻反例**（共享关键词但需要别的能力），不要写"其他情况"这类空话。
- 用第三人称陈述，不写 "I can help you" / "你可以用它"；不含 XML 标签与尖括号。
- description 变更属于触发条件变化：按 §4 升版本，并按 §7.2 做一次触发校准。

## 4. 版本规则

- **唯一权威来源**：`SKILL.md` frontmatter `metadata.version`。以下位置必须与其一致，lint 强制：
  - `pyproject.toml` 的 `version`（若存在）；
  - `.claude-plugin/plugin.json` 的 `version`；
  - `.claude-plugin/marketplace.json` 对应 plugin 条目的 `version`；
  - 本地台账（`SKILLS.local.md`，存在时）。
  README Skills 表不展示版本号。
- 语义：`0.x` 表示生态未定/首版；措辞优化、小修 → 补丁位 +1；行为协议变化（增删阶段、触发条件、命令接口、渐进披露拆分）→ 次位 +1；破坏性变更（调用方式 / 输出格式）在 0.x 阶段也按次位对待、进入 1.0 后升主位。
- 变更时机：改动行为语义的**同一批**变更里升版本，并同步上述所有位置与台账（明细"版本"行注明日期与一句话原因）。
- 版本同步检查表：改 frontmatter → 改 pyproject（若有）→ 改 plugin.json → 改 marketplace 条目 → 回填台账 → 跑 lint。

## 5. skill 目录与台账标准

### 5.1 README 公开目录表（入库，lint 强制）

- README 的 `## Skills` 表是仓库对外唯一的 skill 目录：列定义 `Skill`（链接到目录，文本为目录名）| `类型` | `说明`。**不在 README 展示版本号**；版本权威来源是 SKILL.md frontmatter。
- **何时必须更新**（lint 强制）：新增 / 删除 skill；说明文案变化随批更新。版本变更只改 frontmatter / pyproject / plugin / marketplace / 本地台账，不改 README 表。
- lint 校验：表 ↔ 磁盘双向一致（L-readme）；README 不校验版本列。

### 5.2 维护者本地台账（SKILLS.local.md，不入库）

- 可选的维护者私有文件（根 .gitignore 以 `*.local.md` 排除），记录不适合公开的本机信息：分发状态（以 doctor 输出为准回填）、链接日期、git 提交号锚点、信息核实日期、个人下一步计划。
- 结构沿用：`## 总览` + `## 明细`（每 skill 一节 `### <name>`），字段行按 skill 形态取用：`目录 / name`、`版本`、`类型 / 分类`、`依赖`（代码 skill）、`命令入口`（代码 skill）、`触发`（纯提示词）、`安装链接`、`文档`、`git`、`许可`、`状态`。
- lint 在该文件**存在时**校验总览 ↔ 磁盘双向一致与版本一致（L-ledger），不存在时输出 info 并跳过——外部克隆视角全绿。
- 台账是手工维护的：lint 只校验机器可查部分，简介等人工内容不做自动生成。

## 6. 分发标准

### 6.1 分发目标清单

- 目标 = **内置主流清单** ⊕ **`agents.local.conf` 本地自定义**（6.2）；**目录存在才生效**，不存在的目标自动跳过、不影响其余目标。
- 内置清单（name → 全局 skills 目录，`~` 为用户主目录）：

| name | 全局目录 | 覆盖的 agent |
| --- | --- | --- |
| zcode | `~/.zcode/skills` | ZCode |
| agents | `~/.agents/skills` | 跨端通用目录：Codex（新版）、Zed、Goose、Amp、Crush、Windsurf、Roo、Junie 等直接读取 |
| claude | `~/.claude/skills` | Claude Code |
| cursor | `~/.cursor/skills` | Cursor（2.4+） |
| codex | `~/.codex/skills` | Codex CLI 旧版全局位（新版读 `~/.agents/skills`） |
| copilot | `~/.copilot/skills` | GitHub Copilot（VS Code agent / CLI / 云端 coding agent） |
| gemini | `~/.gemini/skills` | Gemini CLI（v0.23+，实验特性） |
| opencode | `~/.config/opencode/skills` | opencode（亦兼容读 `~/.agents`、`~/.claude`） |
| windsurf | `~/.codeium/windsurf/skills` | Windsurf / Cascade（亦读 `~/.agents`） |
| cline | `~/.cline/skills` | Cline（v3.48+） |
| roo | `~/.roo/skills` | Roo Code（亦读 `~/.agents`） |
| qwen | `~/.qwen/skills` | Qwen Code |
| kilo | `~/.kilo/skills` | Kilo Code（v4.141+） |
| junie | `~/.junie/skills` | JetBrains Junie（亦读 `~/.agents`） |
| trae | `~/.trae/skills` | Trae |

- 入表标准：官方支持 Agent Skills（agentskills.io 格式）且全局目录固定可探测；只读 `~/.agents/skills` 的 agent 不单列（agents 行已覆盖），其原生位可用 `agents.local.conf` 补充（如 `amp ~/.config/agents/skills`）。清单依据 2026-09 各官方文档核实，随生态演进更新。
- 权威实现是 `scripts/lib.sh` 的 `builtin_agent_targets()`；doctor 矩阵列名即清单 name。修改清单时，ddgs-web-access 独立安装脚本（`scripts/install.sh` / `uninstall.sh`）的默认清单需同步。

### 6.2 本地自定义（agents.local.conf）

- 仓库根的可选文件（.gitignore 排除，仅本机生效），每行一条，`#` 为注释：

```
# 新增 / 覆盖同名内置目标（路径以 ~ 或 / 开头，可含空格）
amp       ~/.config/agents/skills
myagent   /d/tools/myagent/skills
# 禁用内置目标
!cursor
```

- 语法错误（名称不合法 / 路径非绝对）fail-fast：link / unlink / doctor 输出 `ERROR: agents.local.conf:<行号>` 并以退出码 2 终止；禁用未知名仅 warn 不报错。

### 6.3 分发与巡检

- 统一入口：`bash scripts/skills-link.sh [--agent <name|name=path>]... <name>... | --all`；卸载 `bash scripts/skills-unlink.sh`（参数相同；只删确认指向本仓库的链接，真实拷贝不动）。
- `--agent` 语义：`name` 只操作该目标（可重复、可选多个）；`name=path` 临时指定/覆盖目标目录——任意绝对路径均可，含把 skill 链进其他项目 `.agents/skills` 等项目级目录的一次性场景。未知名报错并列出可用名称；同名 `name` 与 `name=path` 同时给出以先出现者为准。
- ddgs-web-access 自带的 `scripts/install.sh` / `uninstall.sh` 仅为"单个 skill 目录拷走独立使用"的场景保留（默认清单与 6.1 一致，可传位置参数指定目录），本仓库内分发一律用根脚本。
- 巡检：`bash scripts/skills-doctor.sh`。四种状态：`linked`（指向本仓库，健康）/ `missing`（无链接）/ `foreign`（拷贝或指向别处）/ `broken`（链接存在但读不到 SKILL.md）。**坏链接在 agent 侧不会报错**，任何链接变更后必跑 doctor，并据结果回填本地台账（SKILLS.local.md）"分发状态"列。

### 6.4 Agent 代装

把下面这段发给任意支持 Agent Skills 的 coding agent；它会执行安装命令、读取完整输出，并自行解析支持文件路径完成安装：

```text
Run `npx skills add "https://github.com/GitZhiQing/agent-skills"` and follow the generated instructions now. Read its complete output, redirecting it to a temporary file first if necessary. Resolve relative paths from the supporting-files directory it provides.
```

## 7. 回归标准

### 7.1 测试集

- 改动任何 skill 的 SKILL.md、references 或代码后，按该 skill `docs/测试集.md` 回归。
- 测试集编号采用「**类别前缀-序号**」（如 ddgs-web-access 的 S-/F-/P-/I-/E-，deep-research 的 V-，维护脚本的 L-/D-/K-/N-）；新场景追加编号，不重排不复用。
- 每个用例 = 场景说明 + `▶` 触发方式（命令行或用户指令）+ `- =` 断言列表（含期望行为与明确禁止项）。
- ddgs-web-access：搜索 / 抓取调用间隔 ≥2 秒（多引擎聚合，过频限流）。
- 纯提示词 skill 的测试集是行为协议断言，人工会话执行。
- 渐进披露拆分后，断言应指向"SKILL.md 有读取指引 + reference 文件包含该规则"，而不是要求规则字面出现在 SKILL.md。

### 7.2 触发校准（description 变更时）

description 是唯一的触发机制，改措辞后至少做一轮轻量校准：

- 准备 8–10 条**应触发**与 8–10 条**不应触发**的真实用户说法；反例取近邻场景（共享关键词但需要别的能力）。
- 每条跑 3 次（新会话），记录触发率；应触发组目标 ≥0.8，不应触发组目标 ≤0.2。
- 结果与调整理由写入该 skill `docs/测试集.md` 的「触发校准」附录（日期 + 查询 + 结果），不新建独立文件。
- 只改 description 的措辞也按 §4 升补丁位版本。

### 7.3 代码型 skill 的最小验证

- 每次改动至少跑 `--help` 冒烟（CLI）或 `python -m unittest discover`（有 `tests/` 的 skill）。
- video-insight 的 163 条单测是基线；真实 API 用例在无 Key 时自动跳过，不得把跳过当通过。
- 质量门类检查（如 md2pdf canary S-3）按对应测试集执行，失败即阻塞交付。

## 8. 维护脚本

### 8.1 脚本设计规则

适用于 skill 内的 `scripts/` 与仓库级 `scripts/`：

- **非交互是硬要求**：脚本不得等待 stdin、不得弹确认；需要确认的决策留给 agent 或 `--yes` 参数。
- **自描述**：`--help` 输出用法、参数、退出码；错误信息说明"哪里错、期望什么、怎么补"。
- **输出纪律**：数据/结果走 stdout，诊断与进度走 stderr；供 agent 消费的结果优先 JSON（单行或 `--json`），并控制单次输出量（必要时支持 `--output` 落盘）。
- **幂等与安全**：重复执行不产生重复副作用；破坏性操作支持 `--dry-run`，默认值保守。
- **退出码**：0 成功 / 1 业务失败 / 2 用法错误；与 ddgs-web-access 一致。
- **依赖声明**：uv 包型写 `pyproject.toml` 并锁版本；单文件 Python 可用 PEP 723 内联依赖 + `uv run`；纯标准库脚本在 README 写明系统依赖。
- **路径**：脚本内引用资源一律相对 skill 根解析，不依赖当前工作目录。

### 8.2 脚本清单与退出码

| 脚本 | 用途 | 退出码 |
| --- | --- | --- |
| `scripts/skills-lint.sh` | 结构与元数据一致性校验（§2–§5 的机器可查项） | 0 通过 / 1 失配 / 2 用法 |
| `scripts/skills-doctor.sh` | agent 目录链接健康矩阵 | 0 健康 / 1 有 broken / 2 用法 |
| `scripts/skills-link.sh [--agent <name\|name=path>]... <name>... \| --all` | 分发链接（幂等，目标清单见 §6） | 0 完成 / 1 创建失败 / 2 用法 |

## 9. 新增 skill 流程

1. `bash scripts/skills-new.sh <name> [--with-design]` — 从 `template/` 生成 `SKILL.md`、`README.md`、`docs/测试集.md`、`.claude-plugin/plugin.json`（可选设计文档）。
2. 填写 SKILL.md 的三段式 description 与正文；按 §2 判定是否补设计文档；条件分支放 `references/`。
3. 在 README Skills 表补一行（不写版本号）。
4. 在 `.claude-plugin/marketplace.json` 补一个 plugin 条目（name / source / description / version / author / keywords）。
5. 本机维护者另在 SKILLS.local.md 补总览一行 + 明细一节（填写版本 0.1.0）。
6. 代码型 skill 在 `.github/workflows/ci.yml` 增加对应测试 job（Windows-only 用 `windows-latest`）；纯提示词 skill 仍按测试集人工回归。
7. `bash scripts/skills-lint.sh` — 应全绿（exit 0）；新增 skill 的 category 未填时按 warn 处理并补齐。
8. `bash scripts/skills-link.sh <name>` 分发，`bash scripts/skills-doctor.sh` 确认 linked，本地台账回填分发状态。
9. 按 `docs/测试集.md` 做首轮回归；description 按 §7.2 校准。

## 10. Git 提交信息规范

- **Subject**：`type(scope): 摘要`，使用 ASCII 冒号。`type` 取 `feat` / `fix` / `docs` / `refactor` / `test` / `chore` / `build`；`scope` 为 skill 名或 `repo` / `docs` / `scripts` / `marketplace`。
- 摘要用中文声明式动词开头，≤50 字，不以句号结尾；**不写版本号**，版本变化放 body。
- **Body**：subject 后空一行，用 `- ` 列表逐条说明；每条一个变更，不写过程叙述。
- 混合主题提交按主要变更定 type/scope，其余明细放 body；不做 hunk 级拆分。主题分组仍由 `theme-commit` skill 负责，提交信息按本规范执行。
- 示例：

  ```text
  feat(deep-research): 增加源码调研协议

  - 阶段 1 识别源码调研，确认门列出源码获取计划
  - 阶段 4 clone 到 sources/ 并固定完整 commit SHA
  - 版本升至 0.6.0
  ```

- 2026-10-19 已按本规范重写 `main` 历史（51 条提交重写为 47 条，合并 4 条相邻噪声）；旧 SHA 不再有效，外部 clone 需重新同步。
- 具体执行流程（预检、计划预览、快速检查、提交后核对）见 [theme-commit](../skills/theme-commit/SKILL.md)。
