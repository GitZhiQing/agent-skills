# Skills 开发与维护规范

版本：v1.1（2026-09-10：skill 目录迁入 `skills/` 子目录，lint 新增 L-layout）

适用范围：本仓库全部 skill 及仓库级维护脚本（`scripts/`）。SKILLS.md 台账的格式标准也定义于本文档（§5），台账与本文档冲突时以本文档为准。机器可校验的规则由 `scripts/skills-lint.sh` 与 `scripts/skills-doctor.sh` 强制，本文档说明规则本身与判定依据。

## 1. 范围与原则

- **一个 skill 一个目录，全部位于根 `skills/` 子目录下**，`SKILL.md` 是唯一入口与权威元数据来源；"skill 的定义" = `skills/` 下含 SKILL.md 的子目录（对齐 Agent Skills 社区惯例与 skills CLI 的发现规则，lint L-layout 强制）。
- **skill 目录自包含**：把单个 skill 目录拷走仍可用（CLI skill 自带 `bin/`、`scripts/`）；仓库级维护脚本放在根 `scripts/`，不进入 skill 目录。
- **分发单一来源**：各 agent 的 skills 目录（`~/.zcode/skills`、`~/.agents/skills`、`~/.claude/skills`、`~/.cursor/skills`）只放指向本仓库的 junction/symlink，不拷贝。
- 文档三层分工：`README.md` 面向人的仓库说明，`AGENTS.md` 面向 AI 会话的入口，`SKILLS.md` 是台账（全部 skill 的元信息索引），本规范定义标准。

## 2. 目录结构标准

| 文件 / 目录 | 状态 | 说明 |
| --- | --- | --- |
| `SKILL.md` | **必需** | 入口与元数据，标准见 §3 |
| `docs/测试集.md` | **条件必需** | 行为含可断言协议（何时触发 / 何时不触发 / 步骤约束）的 skill 必须有；编号约定见 §7 |
| `docs/需求与设计文档.md` | 条件必需 | 决策多、有开放问题或多方案权衡的 skill 应有 |
| `README.md` | 条件必需 | CLI skill / 有运行时依赖的必需（用法、参数、排障）；纯提示词 skill 可省（SKILL.md 自身即文档） |
| `bin/`、`scripts/`、`pyproject.toml` | 仅 CLI skill | 位置无关启动器、自带安装/卸载脚本、依赖声明（参考 ddgs-web-access） |
| `docs/` 其他文档（竞品调研、灵感源等） | 自由 | 建议在 SKILLS.md 明细"文档"行登记 |

判定示例：theme-commit（纯提示词，但 4 步协议可断言）→ SKILL.md + docs/测试集.md；ddgs-web-access（CLI）→ 全套；deep-research（纯提示词、协议复杂）→ SKILL.md + 测试集 + 设计文档。

## 3. SKILL.md Frontmatter 标准

| 字段 | 状态 | 标准 |
| --- | --- | --- |
| `name` | **必需** | 与目录名一致，kebab-case（`^[a-z0-9][a-z0-9-]*$`）。lint 强制 |
| `description` | **必需** | **三段式**：① 一句话定位（做什么）② 正向触发（场景 + 触发词）③ 反向不触发（什么情况下明确不用）。agent 依据 description 决定是否加载本 skill，三段式直接对应"何时用 / 何时不用"的判断输入。lint 强制非空，过短（<30 字符）warn |
| `metadata.version` | **必需** | semver（`X.Y.Z`），**全部 skill 一律标注**（纯提示词同样有迭代），规则见 §4。lint 强制 |
| `metadata.category` | 建议 | 领域标签，开放值集（现有：web / git / research），新值在台账明细"类型 / 分类"行注明 |
| `license` | 建议 | 许可名（如 `MIT`），对齐 Agent Skills 开放规范的可选字段。lint 不强制 |
| `compatibility`、`allowed-tools` | 按需 | **标量字符串**（开放规范要求，不用 YAML 列表）：compatibility ≤500 字符描述环境依赖；allowed-tools 为空格分隔的工具授权串（参考 ddgs-web-access） |
| 其他扩展字段 | 先立后用 | 新字段先进本规范再使用，保证三端 agent 语义统一（未知字段会被忽略，但本仓库内含义必须唯一） |

## 4. 版本规则

- **唯一权威来源**：SKILL.md frontmatter `metadata.version`。`pyproject.toml` 的 `version`（若存在）与 SKILLS.md 总览"版本"列必须与其一致，lint 强制。
- 语义：`0.x` 表示生态未定/首版；措辞优化、小修 → 补丁位 +1；行为协议变化（增删阶段、触发条件、命令接口）→ 次位 +1；破坏性变更（调用方式 / 输出格式）在 0.x 阶段也按次位对待、进入 1.0 后升主位。
- 变更时机：改动行为语义的**同一批**变更里升版本，并同步台账（明细"版本"行注明日期与一句话原因）。

## 5. SKILLS.md 台账标准

- 结构固定四层：标题 + 说明（含信息核实日期）/ `## 总览` / `## 明细` / 维护指引。
- **总览**列定义：`Skill`（链接到目录，文本为目录名）| `版本`（与 frontmatter 一致）| `类型`（Python CLI / 纯提示词）| `简介` | `斜杠调用` | `分发状态`（以 doctor 输出为准回填）。
- **明细**每 skill 一节 `### <name>`，字段行按 skill 形态取用：`目录 / name`、`版本`、`类型 / 分类`、`依赖`（CLI）、`命令入口`（CLI）、`触发`（纯提示词）、`安装链接`、`文档`、`git`、`许可`（有 License 时）、`状态`。
- **何时必须更新**（前两项 lint 强制，其余为人工纪律）：新增 / 删除 skill；版本变更；分发状态变化（以 doctor 输出为准）；文档索引变化；信息核实日期。
- 台账是**手工维护**的：lint 只校验机器可查部分（总览 ↔ 磁盘双向一致、版本三处一致），简介等人工内容不做自动生成。

## 6. 分发标准

- 统一入口：`bash scripts/skills-link.sh <name>... | --all`；卸载 `bash scripts/skills-unlink.sh`（只删确认指向本仓库的链接，真实拷贝不动）。
- ddgs-web-access 自带的 `scripts/install.sh` / `uninstall.sh` 仅为"单个 skill 目录拷走独立使用"的场景保留，本仓库内分发一律用根脚本。
- 巡检：`bash scripts/skills-doctor.sh`。四种状态：`linked`（指向本仓库，健康）/ `missing`（无链接）/ `foreign`（拷贝或指向别处）/ `broken`（链接存在但读不到 SKILL.md）。**坏链接在 agent 侧不会报错**，任何链接变更后必跑 doctor，并据结果回填台账"分发状态"列。

## 7. 回归标准

- 改动任何 skill 的 SKILL.md 或代码后，按该 skill `docs/测试集.md` 回归。
- 测试集编号采用「**类别前缀-序号**」（如 ddgs-web-access 的 S-/F-/P-/I-/E-，deep-research 的 V-，维护脚本的 L-/D-/K-/N-）；新场景追加编号，不重排不复用。
- 每个用例 = 场景说明 + `▶` 触发方式（命令行或用户指令）+ `- =` 断言列表（含期望行为与明确禁止项）。
- ddgs-web-access：搜索 / 抓取调用间隔 ≥2 秒（多引擎聚合，过频限流）。
- 纯提示词 skill 的测试集是行为协议断言，人工会话执行。

## 8. 维护脚本用法与退出码

| 脚本 | 用途 | 退出码 |
| --- | --- | --- |
| `scripts/skills-lint.sh` | 结构与元数据一致性校验（§2-§5 的机器可查项） | 0 通过 / 1 失配 / 2 用法 |
| `scripts/skills-doctor.sh` | agent 目录链接健康矩阵 | 0 健康 / 1 有 broken / 2 用法 |
| `scripts/skills-link.sh <name>... \| --all` | 分发链接（幂等） | 0 完成 / 1 创建失败 / 2 用法 |
| `scripts/skills-unlink.sh <name>... \| --all` | 安全卸载链接 | 0 完成 / 1 删除失败 / 2 用法 |
| `scripts/skills-new.sh <name>` | 新 skill 骨架 | 0 创建 / 2 用法 |

统一约定：状态输出 `ok:` / `warn:` / `skip (...)` / `linked:` / `removed:` 走 stdout；`ERROR:` 与提示走 stderr；退出码 0-1-2 与 ddgs-web-access CLI 一致。脚本为纯 bash + coreutils，零外部依赖；公共函数在 `scripts/lib.sh`。脚本自身的测试集见 [维护脚本测试集.md](维护脚本测试集.md)。

## 9. 新增 skill 流程

1. `bash scripts/skills-new.sh <name>` — 生成标准骨架（含三段式 description 模板与测试集模板）。
2. 填写 SKILL.md 正文与 description，按 §2 判定补 `docs/` 文档。
3. 在 SKILLS.md 补总览一行 + 明细一节（版本 0.1.0）。
4. `bash scripts/skills-lint.sh` — 应全绿（exit 0）。
5. `bash scripts/skills-link.sh <name>` 分发，`bash scripts/skills-doctor.sh` 确认 linked，台账回填分发状态。
