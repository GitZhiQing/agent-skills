## 1. 定位与运行方式

**本测试集回答的问题**：一个 coding agent 在真实任务里，这套工具是否"用得上、结果对、报错可理解"。

**前置条件**：uv >= 0.5、可联网（首次调用自动安装依赖，约 30-60s）；代理场景需本机有代理服务；标注"环境相关"的场景在对应环境缺失时跳过，不算缺陷。

**运行方式**：人工逐条执行，把结果填入 §7 记录表。命令一律用 `uv run --project ddgs-web-access` 前缀（在仓库根目录执行；下文中以 `▶` 开头的是命令，`=` 开头的是关键断言）。该前缀与 `bin/` 启动器形式等价（`bash <skill_dir>/bin/ddgs-web-search ...`），安装到 agent 后建议用启动器形式复跑（I 组场景固定使用启动器/脚本形式）。

**Windows / Git Bash 注意事项**：
- URL 一律加双引号（尤其含括号的 URL，如维基百科词条 `https://en.wikipedia.org/wiki/Python_(programming_language)`，不加引号会被 bash 解释）；
- 用 `echo $?` 检查退出码；stderr 与 stdout 分开观察（`2>/dev/null` 看 stdout，`2>&1 >/dev/null` 看 stderr）。

**判定规则**：某场景所有 `=` 断言满足即通过；"环境相关"场景失败时记录环境，不判定为回归缺陷。

## 2. 搜索场景（S）

### S-1 权威来源查证（基础场景）

```
▶ uv run --project ddgs-web-access ddgs-web-search "python 3.13 what's new" -m 5
```

- = 输出 ≥3 个结果块，每块 3 行（标题 / URL / 摘要）
- = 至少 1 个 href 属于 python.org 或 docs.python.org
- = 每个 URL 以 http(s):// 开头且可点击（无转义垃圾）
- = exit 0

### S-2 时效性搜索（timelimit 生效）

```
▶ uv run --project ddgs-web-access ddgs-web-search "python 3.14 release" -t m -m 5
```

- = 输出非空，exit 0
- = 人工抽查：多数结果的发布时间在近一个月内（多引擎对时间过滤支持不一，允许个别引擎忽略）

### S-3 区域差异（region 生效）

```
▶ uv run --project ddgs-web-access ddgs-web-search "nhs waiting times" -r uk-en -m 5
▶ uv run --project ddgs-web-access ddgs-web-search "nhs waiting times" -r us-en -m 5
```

- = uk-en 结果集中出现 nhs.uk 域的结果
- = 两组结果集合不同（区域参数确实改变检索）

### S-4 引擎对比（backend 生效）

```
▶ uv run --project ddgs-web-access ddgs-web-search "uv run" -b wikipedia -m 3
▶ uv run --project ddgs-web-access ddgs-web-search "uv run" -b bing -m 3
```

- = wikipedia 模式结果全部为 en.wikipedia.org（或相关维基域）
- = 两组结果不同（`auto` 默认聚合全部引擎，偏维基百科系）

### S-5 链接收集（--urls 机器可读）

```
▶ uv run --project ddgs-web-access ddgs-web-search "python 3.13" -m 5 --urls
```

- = 输出每行一个 href，无序号/无标题
- = 行数 ≤ 5，全部以 http(s):// 开头
- = 可管道串联：`... --urls | head -3 | xargs -I{} echo "fetching {}"`（验证机器消费无阻碍）

### S-6 JSON 逃生口（结构可用）

```
▶ uv run --project ddgs-web-access ddgs-web-search "python 3.13" -m 3 --format json | python -m json.tool
```

- = 输出为合法 JSON 数组，元素键为 title / href / body
- = 与 `--urls` 同传时报错 exit 2（互斥校验）

### S-7 空结果路径（无结果不是错误）

```
▶ uv run --project ddgs-web-access ddgs-web-search "asdfqwerzxcvbnmghjkl asdfqwerzxcvbnm" -b wikipedia -m 3
```

- = stdout 为空
- = stderr 出现 `no results found.`
- = exit 0（空结果是合法业务结果；若反复出现则按限流处置，见 SKILL.md 纪律）

### S-8 限流纪律（调用间隔）

```
▶ date +%s; uv run --project ddgs-web-access ddgs-web-search "python" -m 1 >/dev/null; date +%s
▶ date +%s; uv run --project ddgs-web-access ddgs-web-search "python" -m 1 >/dev/null; date +%s
```

- = 两次开始时刻相差 ≥2s（纪律由调用方保证，工具本身不强制）

### S-9 异常自动重试（瞬时错误自愈）

```
▶ time uv run --project ddgs-web-access ddgs-web-search "python" -m 1 --proxy "http://127.0.0.1:1"; echo $?
```

- = stderr 出现 `retrying in 2s`（第一次失败后自动重试一次）
- = 两次尝试均失败后 exit 1（坏代理必然失败，验证重试上限为 1 次）
- = 总耗时 ≥2s（含重试等待）；stdout 为空、无 traceback

## 3. 抓取场景（F）

### F-1 文档站 Markdown（核心场景）

```
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://docs.python.org/3/library/asyncio.html" -f text_markdown
```

- = 输出含页面标题（`asyncio — Asynchronous I/O`）与 `# ` 标题
- = 正文段落完整（含 "asyncio is a library to write" 等原文句子）
- = 链接保留为 `[text](url)` 形式
- = 不含导航样板（无 "Navigation" 面包屑标题）
- = exit 0

### F-2 维基百科信息框（表格转换）

```
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://en.wikipedia.org/wiki/Python_(programming_language)" -f text_markdown --max-chars 3000
```

- = 输出以页面标题行开头
- = 含 Markdown 表格（`| --- |` 表头分隔行）与 `| Paradigm |` 行
- = 不含 "Main menu" / "Navigation" 等侧栏样板
- = exit 0

### F-3 博客正文（真实文章）

```
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://simonwillison.net/2024/Oct/9/free-threaded-python-with-asyncio/" -f text_markdown
```

- = 输出含标题 `Free Threaded Python With Asyncio` 与发布日期 `9th October 2024`
- = 正文首句与原文一致（"Jamie Chang expanded..."）
- = 外部链接保留为 `[text](url)` 形式
- = exit 0

### F-4 纯文本（无 Markdown 符号）

```
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://example.com" -f text_plain
```

- = 含 "Example Domain" 与正文句子
- = 不含 `#` 标题符号、`[text](url)` 链接语法、`**` 强调符号

### F-5 原始 HTML（透传）

```
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://example.com" -f text --max-chars 200
```

- = 输出以 `<!doctype html>` 或 `<html` 开头
- = 截断提示出现在 stderr（`truncated at 200 chars`），stdout 无日志混入

### F-6 二进制抓取（content 写文件）

```
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://example.com" -f content
```

- = stdout 输出一个 `.bin` 文件路径
- = 文件存在且大小 > 0

### F-7 404 错误（可理解的失败，不触发自动回退）

```
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://example.com/404-not-found"; echo $?
```

- = exit 1
- = stderr 含 `DDGSException` 与 `HTTP 404`（默认模式）；`--curl` 模式为 `curl: exit 22`
- = stderr **不含** `retrying with curl`（404 死链不自动回退，curl 结果相同）
- = stdout 为空

### F-8 批量与单 URL（分隔符语义）

```
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://example.com" "https://example.org" -f text_plain --max-chars 80
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://example.com" -f text_plain --max-chars 80
```

- = 批量输出含两段内容，以 `===== <url> =====` 分隔，顺序与参数一致
- = 单 URL 输出不含任何 `=====` 行
- = 批量中混入 404 时：成功页面照常输出，stderr 单独报错，整体 exit 1

### F-9 磁盘缓存（避免重复网络请求）

```
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://example.com" -f text_plain --max-chars 80
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://example.com" -f text_plain --max-chars 80
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://example.com" -f text_plain --max-chars 80 --no-cache
```

- = 第二次调用 stderr 出现 `cache hit`，内容与第一次一致（截断参数变化不影响缓存，缓存存全量内容）
- = `--no-cache` 不命中
- = 项目 `.cache/` 目录下存在缓存文件（键为 `sha256(mode|fmt|url)`）
- = 换 `-f text_markdown` 抓同一 URL 不命中缓存（不同格式不同缓存条目）

### F-10 截断边界（token 控制）

```
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://www.python.org/" -f text_plain --max-chars 100
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://www.python.org/" -f text_plain --max-chars 0 --no-cache | wc -c
```

- = `--max-chars 100` 时 stdout 正文恰为 100 字符，stderr 有截断提示（含 `truncated at 100 chars` 与 `(continue with --start 100)`）
- = `--max-chars 0` 输出全量（字符数明显大于 100）
- = 默认（不传）时截断阈值为 5000

### F-11 curl 回退（双通道一致性）

```
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://www.python.org/" -f text_markdown --max-chars 300
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://www.python.org/" -f text_markdown --max-chars 300 --curl
```

- = 两通道均 exit 0，输出均含页面标题文本（转换器不同，正文细节允许差异）
- = `--curl` 模式 404：exit 1 且 stderr 含 `curl: exit 22`
- = `--curl` 模式同样命中/写入缓存（mode 维度隔离，互不串用）
- = 环境相关：对本机 ddgs 抓取失败的站点（403 反爬等）执行 `--curl` 能拿到内容——这是该参数的核心价值场景

### F-12 非 UTF-8 页面解码（环境相关）

```
▶ uv run --project ddgs-web-access ddgs-web-fetch "<charset=gbk 的中文站点>" --curl -f text_plain --max-chars 200
```

- = 输出为可读中文，无 `�` 乱码（依赖 `<meta charset>` 声明路径，utf-8/gbk/latin-1 回退）
- = 找不到合适站点时跳过，不算失败

### F-13 超时兜底（不挂起）

```
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://10.255.255.1/" --timeout 1; echo $?
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://10.255.255.1/" --curl --timeout 1; echo $?
```

- = 两次调用均在数秒内返回，不无限挂起
- = 默认模式 exit 1（TimeoutException 或连接错误）；`--curl` 模式 exit 1（`curl: exit 28` 或连接错误）
- = 断言以"有限时间内退出且 exit=1"为准，具体错误类型随网络环境浮动

### F-14 自动 curl 回退（环境相关：默认模式失败的站点）

```
▶ uv run --project ddgs-web-access ddgs-web-fetch "<已知 ddgs extract 失败的站点 URL>"
▶ uv run --project ddgs-web-access ddgs-web-fetch "<同上 URL>"   # 二次调用
```

- = 首次调用 stderr 出现 `retrying with curl`，随后 stdout 输出 curl 转换的正文，exit 0（"一次调用就成功"）
- = 二次调用（15 分钟内）stderr 出现 `cache hit` 且**不再**出现 `retrying with curl`（默认模式缓存查找覆盖 curl 键）
- = 找不到 ddgs 必失败的站点时跳过，不算失败（可用 F-13 的不可达地址观察回退提示格式，但该地址 curl 也失败、最终 exit 1）

### F-15 --start 分页（长文分段读）

```
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://www.python.org/" -f text_plain --max-chars 200 --no-cache
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://www.python.org/" -f text_plain --max-chars 200 --start 200 --no-cache
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://www.python.org/" -f text_plain --start 999999; echo $?
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://example.com" --start -1; echo $?
```

- = 第一段恰为 200 字符，第二段为第 201-400 字符（内容与第一段不重叠，可直接拼接还原原文）
- = `--start 999999` 超出长度：stderr 提示 `beyond end of content`，stdout 为空，exit 0
- = `--start -1`：exit 2（参数校验）

## 4. 代理场景（P，环境相关：需本机有可用代理服务）

### P-1 显式代理

```
▶ uv run --project ddgs-web-access ddgs-web-search "python" -m 1 --proxy "http://127.0.0.1:<port>"
▶ uv run --project ddgs-web-access ddgs-web-fetch "https://example.com" -f text_plain --proxy "http://127.0.0.1:<port>"
```

- = 走代理成功，exit 0
- = socks5 代理（如 `socks5h://127.0.0.1:9150`）同样可用（ddgs/curl 均支持）

### P-2 环境变量代理

```
▶ HTTPS_PROXY="http://127.0.0.1:<port>" uv run --project ddgs-web-access ddgs-web-search "python" -m 1
▶ DDGS_PROXY="http://127.0.0.1:<port>" uv run --project ddgs-web-access ddgs-web-search "python" -m 1
```

- = 两者均生效（优先级：`--proxy` > `DDGS_PROXY` > `HTTPS_PROXY` > `HTTP_PROXY`）
- = `--proxy` 显式传入时覆盖环境变量（可在代理坏掉时验证：显式传可用代理成功，环境变量指向坏代理被忽略）

### P-3 代理不可达（错误可读）

```
▶ uv run --project ddgs-web-access ddgs-web-search "python" -m 1 --proxy "http://127.0.0.1:1"; echo $?
```

- = exit 1，stderr 含连接失败信息（如 `ConnectError` / `exit 7`），agent 能据此判断是代理问题而非网络问题

## 5. 安装与分发场景（I，覆盖 v0.5 启动器与安装脚本）

以下场景使用启动器/脚本形式（区别于其余组的 `uv run` 形式，两者等价）。

### I-1 一键安装（幂等、可重复）

```
▶ bash "<skill_dir>/scripts/install.sh"
▶ bash "<skill_dir>/scripts/install.sh"   # 重复执行
▶ ls -d ~/.zcode/skills/ddgs-web-access ~/.claude/skills/ddgs-web-access ~/.agents/skills/ddgs-web-access
```

- = 每个**已存在**的 agent skills 目录下出现指向仓库的链接（Windows junction / Unix 符号链接）
- = 重复执行不报错、不重复创建（输出 skip 已存在）
- = 不存在的目录（如 `~/.cursor/skills`）自动跳过

### I-2 任意目录、任意链接路径调用

```
▶ cd 到仓库外的任意项目目录
▶ bash ~/.zcode/skills/ddgs-web-access/bin/ddgs-web-search "python" -m 1 --urls
▶ bash ~/.claude/skills/ddgs-web-access/bin/ddgs-web-fetch "https://example.com" -f text_plain --max-chars 40
▶ cmd /c "<仓库>\bin\ddgs-web-search.cmd" --help   # Windows cmd 变体
```

- = 三个命令均 exit 0（cmd 变体至少能输出帮助）
- = 缓存仍写入仓库 `.cache/`，调用目录不产生 `.cache`
- = 链接路径与仓库直连路径行为一致

### I-3 卸载安全（只删本仓库的链接）

```
▶ bash "<skill_dir>/scripts/uninstall.sh"
```

- = 指向本仓库的链接被删除
- = 仓库本体不受影响（链接 ≠ 复制）
- = 手工造一个指向其他位置的假链接再运行：被跳过并提示 `not pointing to this repo`

## 6. 端到端 Agent 场景（E，供 skill 评估 / skill-creator 流程使用）

以下场景以"agent 提示词"形式给出，评估时观察 agent 的工具选择、调用参数、结果利用与错误处置。断言关注**行为**而非逐字输出。

### E-1 搜索 + 抓取 + 总结（复合主链路）

> 查一下 Python 3.13 的新特性，给我 3 个权威来源，每个用一句话说明；然后抓取其中最权威的页面，总结成 5 条要点，每条注明出处链接。

- = 先调用 `ddgs-web-search`（合理使用 `-m`，如 3-5）
- = 再调用 `ddgs-web-fetch`（仅抓取 1 个页面，不重复）
- = 最终输出 5 条要点，均带来源链接
- = 不出现参数错误（exit 2）或对错误输出的误读

### E-2 时效性检索

> 搜索过去一个月内关于 asyncio 的英文技术文章，列出标题和链接，按时间排序。

- = 使用了 `-t m` 与 `-r us-en`（或等价参数）
- = 输出为标题+链接列表，无摘要冗余

### E-3 错误解读

> 抓取 https://example.com/404-not-found 失败了，看看报错信息，告诉我发生了什么、可能的原因。

- = 正确解读 exit 1 与 `HTTP 404` 错误，不重复重试相同 URL
- = 回答区分"页面不存在"与"网络/代理问题"

### E-4 缓存识别

> 把 https://example.com 的正文给我，然后再说一下刚才那次抓取有没有走缓存。

- = 第二次调用 stderr 出现 `cache hit` 被正确识别（回答提到缓存命中）
- = 未发起重复网络抓取（可观察 `.cache/` 文件 mtime）

### E-5 限流纪律

> 连续搜索"python asyncio"、"rust tokio"、"node event loop"、"go goroutine"、"c# async" 五个主题。

- = 五次调用间隔 ≥2s（抽查时间戳）
- = 五次全部成功或失败原因可解释（限流时能退避重试，而非机械循环）

### E-6 curl 回退（进阶）

> 抓取 https://www.python.org/ 试一下，如果默认方式不行就换 curl 方式，并说明两种方式的区别。

- = 优先默认模式；失败时加 `--curl` 重试
- = 对两种方式的输出差异有合理解释（转换器不同、样板剥离）

- 多引擎聚合下个别引擎可能超时被跳过，结果数 < `--max-results` 属正常
- markdownify 的表格/嵌套列表转换是"接近完整"而非 100%，个别复杂页面有结构损失
- 样板剥离为启发式（nav/header/footer/aside + breadcrumb/related/sidebar 等提示词），个别站点可能误伤正文区块
