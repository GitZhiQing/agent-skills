# deep-research

先校准、再消耗调研资源的深度调研 skill：先确认"用户到底在问什么"，把搜索资源花在确认过的问题上。开始检索前，调研目标、调研计划与输出目录必须经用户确认。产出双文件——**REPORT.md**（调研报告，结论层）+ **REFERENCES.md**（素材登记簿，证据层），落盘于所选输出根目录下的 `<YYMMDD>-<主题>/`。需要研究源码时，先把仓库 clone 到该目录的 `sources/` 并固定 commit SHA，再基于本地源码分析并给出文件:行号证据。

## 何时触发

- 触发词："帮我调研""深入研究""全面了解""对比分析""查清楚…的现状""research" "deep research"等；
- 或问题术语有歧义、领域冷门、表述模糊时主动使用；
- 不触发：一次搜索可答的单点查询、只需阅读已给出的代码片段或单点调试、用户明确要求不联网且不涉及源码分析。

## 工作方式（阶段）

| 阶段 | 做什么 |
| --- | --- |
| 0 环境检查 | 探测可用的 web 搜索/抓取工具并报告组合；探测工作区结构（已有 `research/`、`docs/`、`notes/`、代码仓标志、父目录可写性）并生成输出目录候选；源码调研追加探测 git，无 web 有 git 可降级本地源码调研；两者皆无则如实说明并终止 |
| 1 预调研校准 | 术语歧义 / 领域冷门 / 表述模糊时做 ≤3 次判向预检索，提炼 2~4 个候选方向；明确的问题免预检索 |
| 2 选项式澄清 | 选项优先于开放提问，最多 3 轮；未收敛则选定最优假设（显式声明）进入确认门 |
| 3 目标与计划确认门 | 工具组合 + 调研目标 + 输出目录候选（2~3 个，含推荐与理由）+ 调研计划（范围 / 子问题 / 检索 / 源码 / 报告 / 交付）+ 档位建议（低 / 中 / 高）+ 一句话理由，合并一次呈现，等待用户回应；源码获取计划含仓库 URL、固定 ref、本地路径，确认前不 clone、不建目录 |
| 4 执行 | 即建 `<OUT>/<YYMMDD>-<主题>/` 目录（`<OUT>` 为确认的输出根目录），每轮搜索后增量登记 REFERENCES.md；源码调研先 clone 到 `sources/` 并固定 commit，再基于本地源码分析；多语言交叉验证、来源分层、矛盾显式化 |
| 5 交付 | REPORT.md + REFERENCES.md 双文件（报告头部回显调研目标与输出目录，含假设声明与"未覆盖与不确定"必选节）；源码调研加「源码基线」节与「源码快照」表 |
| 6 延续 | 追问沿登记簿 / 本地源码快照作答并引用 `[S#]` / `[C#:path:line]`；质疑某结论时只复查其支撑证据链 |

硬规则：未获用户回应（确认 / 调整 / 显式委托）前禁止发起任何正式检索与源码获取、禁止创建输出目录；初始请求中的"直接开始"不提前放行；禁止用模型内部知识冒充调研结果。

## 源码调研

- **识别**：实现原理 / 架构 / 调用链 / 行为溯源 / 源码对比，或答案必须靠代码行为验证时启用；源码调研建议不低于中档。
- **获取与固定**：确认后 clone 到 `<OUT>/<YYMMDD>-<主题>/sources/<repo>/`（默认浅克隆、不递归子模块），记录完整 commit SHA、tag / 版本与获取日期；已有本地仓库 HEAD 与所需 ref 一致才原地复用，否则用 worktree / 拷贝。
- **本地分析**：先读 README / 构建文件 / 目录结构建代码地图，再沿入口 / 调用链定位；不整仓通读；代码结论用 `[C#:path:line]` 引用，区分源码实证 / 文档说明 / 推断。
- **安全与保留**：只读分析，不执行仓库内安装 / 构建 / 测试脚本；`sources/.gitignore` 写 `*` 防止误入库，快照保留至调研结束供追问复查。

## 输出目录

阶段 0 只读探测工作区，阶段 3 给出 2~3 个输出根目录候选并标推荐项；回复「确认」采用推荐，回复编号或路径即改选。推荐规则：

- 已有 `research/` → 沿用；
- 代码仓且无 `research/` → 优先仓外目录（如 `~/research/` 或工作区同级 `research/`），避免调研产物污染代码库；
- 文档 / 笔记仓 → 仓内 `research/` 或 `docs/research/`；
- 无法判断 → 工作区 `research/`。

最终调研目录为 `<OUT>/<YYMMDD>-<主题>/`；输出目录在确认前不创建，确认后不再变更（用户中途改需求除外）。

## 目录命名

`<OUT>/<YYMMDD>-<主题>/`（如 `<OUT>/261018-国产开源数据库格局/`）：`YYMMDD` 取创建当天（跨日不改名）；主题 slug 简短可读，中文关键词可用；同日同主题重复调研追加 `-2`、`-3`；报告与登记簿内日期用 `YYYY-MM-DD`。

## 依赖

宿主须具备 web 搜索 / 抓取能力：原生 WebSearch / WebFetch 类工具，或已安装的搜索 skill（如 [ddgs-web-access](../ddgs-web-access/)）。源码调研另需 git；无 git 时可退回官方源码包。web 工具缺失但 git 可用时，可降级为仅本地源码调研并声明未做外部资料交叉验证。
