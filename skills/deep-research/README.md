# deep-research

先校准、再消耗调研资源的深度调研 skill：先确认"用户到底在问什么"，把搜索资源花在确认过的问题上。产出双文件——**REPORT.md**（调研报告，结论层）+ **REFERENCES.md**（素材登记簿，证据层），落盘于 `research/<主题>-<日期>/`。

## 何时触发

- 触发词："帮我调研""深入研究""全面了解""对比分析""查清楚…的现状""research" "deep research"等；
- 或问题术语有歧义、领域冷门、表述模糊时主动使用；
- 不触发：一次搜索可答的单点查询、用户明确要求不联网。

## 工作方式（阶段）

| 阶段 | 做什么 |
| --- | --- |
| 0 环境检查 | 探测可用的 web 搜索/抓取工具并报告组合；无任何工具则如实说明并终止 |
| 1 预调研校准 | 术语歧义 / 领域冷门 / 表述模糊时做 ≤3 次判向预检索，提炼 2~4 个候选方向；明确的问题免预检索 |
| 2 选项式澄清 | 选项优先于开放提问，最多 3 轮；未收敛则选定最优假设（显式声明）进入确认门 |
| 3 确认门 | 工具组合 + 调研理解 + 档位推荐（low / high / max）+ 一句话理由，合并一次呈现，等待用户回应 |
| 4 执行 | 即建 `research/<主题>-<日期>/` 目录，每轮搜索后增量登记 REFERENCES.md；多语言交叉验证、来源分层、矛盾显式化 |
| 5 交付 | REPORT.md + REFERENCES.md 双文件（报告含假设声明与"未覆盖与不确定"必选节） |
| 6 延续 | 追问沿登记簿作答并引用 `[S#]`；质疑某结论时只复查其支撑证据链 |

硬规则：未获用户回应（确认 / 调整 / 显式委托）前禁止发起任何正式检索；禁止用模型内部知识冒充调研结果。

## 依赖

宿主须具备 web 搜索 / 抓取能力：原生 WebSearch / WebFetch 类工具，或已安装的搜索 skill（如 [ddgs-web-access](../ddgs-web-access/)）。
