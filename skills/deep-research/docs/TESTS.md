## 1. 定位与运行方式

- **前置条件**：agent 环境已加载 deep-research skill（本仓库 junction 或复制安装），且具备某种 web 搜索 / 抓取能力（原生工具或 ddgs-web-access）。源码调研场景（V-18~V-23）另需 `git` 可用与可访问的公开仓库。输出目录场景（V-24~V-26）需一个可写工作区或可指定的外部目录，V-26 另需一个不可写路径。V-11 例外：需一个无任何搜索工具的环境（或明确指示 agent 本次禁用全部搜索手段）；V-23 例外：需无 web 工具但 git 可用的环境；V-29 需分别在有、无结构化提问工具的宿主中验证；V-30 需一个声明自主执行的宿主，或明确指示 agent 模拟该场景。
- **执行方式**：按下述场景原文（`▶` 行）发起对话，对照 `=` 断言逐条核对 agent 行为。多轮场景按 `→` 提示继续输入。
- **判定规则**：
  - 单场景：全部 `=` 断言通过为"通过"；任一失败为"偏离"，记录失败断言编号与实际行为；
  - 断言中的"≤/≥"按字面验收；"包含"指语义包含（措辞可不同，要素必须在）；
  - 环境相关场景（标注 *）缺失环境时跳过，不算缺陷。
- **间隔纪律**：场景若触发真实搜索，遵守所用工具的调用纪律（ddgs-web-access：间隔 ≥2s）。

## 2. 校准段场景（阶段 0~3）

### V-1 明确单点问题免预检索但必过确认门

```
▶ 帮我调研一下 Python 3.13 的发布日期
```

= 首次回复包含工具组合说明（工具名 + 搜索/抓取分工）
= 首次回复包含执行环境说明（Agent 名称 + LLM 模型；无法自识别时标注「未知」而非猜测）
= 未触发预调研校准（无候选方向选项、无预检索调用）
= 首次回复含调研目标（"我理解你要调研的是…"式一句话）与调研计划（范围 / 子问题 / 检索 / 交付）
= 首次回复含 2~3 个输出目录候选，恰有一个标注推荐与一句话理由
= 确认门以 Q1~Q4 frontier 呈现（目标 / 目录 / 档位 / 执行方式），每项附推荐答案
= 档位建议为低档 + 一句话理由
= 该回复以等待用户确认结束（优先用结构化提问工具收口；无工具时文本等待），未附带任何已开始的正式检索结果
=（用户确认后）交付为所选输出根目录下 `<YYMMDD>-<主题>/` 中的 REPORT.md + REFERENCES.md + META.md 三文件

### V-2 歧义术语触发预检索

```
▶ 帮我调研一下苹果的新动向
```

= 触发预调研校准（识别"苹果"多义：公司 / 水果品类 / 其他）
= 预检索（搜索+抓取合计）≤3 次，且查询词带领域限定（判向式，非收集式）
= 输出 2~4 个候选方向，每项 ≤2 行；优先用结构化提问工具勾选，无工具时为文本可勾选列表
= 无预检索资料的长篇摘录（单处引用 ≤1 行）

### V-3 冷门领域模糊表述

```
▶ 深入研究一下 WebGPU 在工业组态软件里的可行性
```

= 触发校准，候选方向含领域限定语（如图形渲染层 / 计算后端 / 生态成熟度）
= 选项中至少覆盖"调研目的"或"范围边界"之一维度的澄清

### V-4 澄清不收敛走最优假设（确认门仍先呈现）

```
▶ 调研一下 RISC-V MCU 的现状
→（对澄清选项不回应，直接回复：你看着办）
→（确认门回复后）就按这个计划来
```

= 澄清轮数 ≤3 后停止追问
= 第一次"你看着办"被识别为选择最优假设（非确认门回应），但确认门仍先呈现推荐调研目标与计划，不自行开始调研
= 确认门回复后的"就按这个计划来"按确认处理，按推荐方案执行
= META.md 含"假设"字段且非空；不出现"经委托采用推荐档"字样

### V-5 确认门单轮确认

```
▶ 帮我调研 <任意主题>
→（确认门回复后）好，开始吧
```

= 确认门只占 1 轮交互（Q1 目标 / Q2 目录 / Q3 档位 / Q4 执行方式 + 按推荐组合的计划同屏）
= 宿主有结构化提问工具时，确认门以该工具收口（至少含执行方式「确认 / 调整 / 取消」；输出目录与档位可同时提供）；无工具时退回文本等待
= 不重复追问档位或计划
= META.md 的确认来源为"结构化提问结果"或"用户文本"，并含档位名（低/中/高）；不出现"未确认"或委托字段

### V-15 初始直接开始与未获回应均不开跑

```
▶ 帮我调研 <任意主题>，直接开始，别问
→（对首轮确认门回复不回应，观察 agent 行为）
```

= 首轮仍呈现调研目标、输出目录候选、调研计划与档位建议，以等待用户确认结束（初始"直接开始"不提前放行，不视为确认）
= 宿主有结构化提问工具时，工具返回取消 / 未选择被视为未确认，不自行开跑；无工具时文本结束回合等待
= 未获回应前未发起任何正式检索（预检索判向除外，且 ≤3 次）
= 未获回应前未创建输出目录
= 回复中无"默认采用推荐档，现在开始"类自行放行表述

### V-16 确认门计划调整

```
▶ 帮我调研 2026 年国产开源数据库格局
→（确认门回复后）范围缩小到 OLAP，子问题只保留前三节，档位降到低
```

= 确认门回复含调研目标、输出目录候选与调研计划（范围 / 子问题 / 检索 / 报告 / 交付）
= 若使用结构化提问工具，用户选择「调整」后可通过选项 / 备注或随后文本说明，不额外增加确认门轮次
= 用户调整后按新范围、子问题与低档预算执行，不要求二次确认
= META.md 的调研目标与档位反映调整结果（低档）
= 调整前未发起正式检索

### V-24 输出目录候选与推荐（代码仓）

```
▶ 帮我调研 <某主题>（在一个有 .git 与构建文件、但没有 research/ 的代码仓库中）
```

= 首轮确认门含 2~3 个输出目录候选，恰有一个标注推荐并给一句话理由
= 代码仓且无 research/ 时，推荐项为仓外目录（如 `~/research/` 或工作区同级 `research/`），理由含"避免污染代码库"类含义
= 候选路径经只读可写性检查；不可写候选未占推荐位
= 确认门回应前未创建任何候选目录
= 用户确认（文本回复「确认」或在结构化提问中选择推荐项）后采用推荐目录，REPORT.md / REFERENCES.md / META.md 落在 `<推荐根>/<YYMMDD>-<主题>/`，META.md 记录绝对路径

### V-25 已有 research/ 沿用与自选路径

```
▶ 帮我调研 <某主题>（工作区已有 research/）
→ 选 B（或在结构化提问中选 B / 通过「其他」填写自定义路径）
```

= 推荐项为 `<工作区>/research/`，理由为沿用既有惯例
= 备选含仓外目录与自定义路径
= 选择 B 或自定义路径后，产物落在所选根目录下的 `<YYMMDD>-<主题>/`，未在推荐目录创建本次产物
= META.md 记录所选输出目录的绝对路径
= 确认门回应前未创建目录

### V-26 输出目录不可写

```
▶ 帮我调研 <某主题>，输出到 <只读路径>
```

= 探测或确认门识别该路径不可写，不将其作为推荐项
= 用户坚持时，执行段如实报告无法创建并请用户改选，不静默落到其他目录
= 提供可写备选并改选后，产物正常落盘到所选目录
= 确认门回应前未创建目录

## 3. 执行与交付场景（阶段 4~5）

### V-6 中文主题双语交叉（中档）

```
▶ 帮我调研 2026 年国产开源数据库的最新格局，要系统一点
```

= 推荐档位为中档或高档（复杂 + 时效敏感）
= 登记簿同时含 zh 与 en 来源（或注明"对侧语言无来源"）
= 登记簿"类型"列全部非空，且三层（官方/权威媒体/社区观点）至少出现两层

### V-7 矛盾显式化

```
▶ 对比调研一下 <某有争议话题，两来源说法冲突>（自选真实主题，如某框架的性能争议）
```

= 报告中并列呈现冲突双方及各自 [S#]
= 未悄悄替用户取舍（结论未单方采信）
= 高档时存在针对性补查（登记簿出现佐证条目或排除条目）

### V-8 交付完整性（任意档位跑完后检查）

```
▶（任一已完成场景的交付物）
```

= 存在所选输出根目录下的 `<YYMMDD>-<主题>/` 独立目录，内含 REPORT.md、REFERENCES.md 与 META.md 三文件（YYMMDD 为创建当天）
= META.md 含调研目标、输出目录（绝对路径）、档位、日期、执行环境（Agent + LLM）、工具与假设声明
= REPORT.md 正文不含元信息块，直接以摘要开始
= REPORT.md 含四节：摘要 / 主要发现 / 来源引用 / 局限与未覆盖（标题在，内容可空）
= 关键结论均带 [S#]，可对应到 REFERENCES.md 表格行（行含完整 URL + 访问日期）
= REFERENCES.md 条目数 ≥ 报告引用数
= 事实与观点可辨识（观点性结论有标注或限定语）

### V-8a 增量登记时序抽查 *

```
▶（中/高档调研执行中途）现在把登记簿给我看一下
```

= 所选输出目录下的 `<YYMMDD>-<主题>/REFERENCES.md` 文件在中途即已存在且非空（非结束后才落盘）
= 含低编号的"已排除"条目（排除发生在过程中而非最后统一补写）

### V-12 高档分阶段与中断

```
▶ 全面调研 <宽泛主题>，要决策级的完整报告
→（大纲确认环节回复）大纲可以，先做前两节
→（第二节汇报后）先停，把已有的给我
```

= 存在大纲确认交互点（分节 + 来源策略）
= 中断后交付已完成节 + REFERENCES.md（文件随过程已在盘）
= 已完成部分仍满足 V-8 断言

### V-17 目录命名与同日防冲突

```
▶ 帮我调研 <同一主题>（当天完成交付）
→ 再次发起同一主题调研（同一天，确认后执行）
```

= 首次目录为所选输出根目录下的 `<YYMMDD>-<主题slug>/`，YYMMDD 为创建当天
= 同日同主题第二次调研使用同一输出根目录下的 `<YYMMDD>-<主题slug>-2/`，不覆盖首次目录
= REPORT.md / REFERENCES.md / META.md 内日期为 YYYY-MM-DD
= 主题 slug 简短可读，无空格与路径分隔符

**源码调研场景（阶段 3~6）**

### V-18 源码调研先 clone 后分析

```
▶ 帮我调研 fastapi/fastapi 的依赖注入是怎么实现的，给出源码证据
```

= 首次回复识别为源码调研，确认门含源码获取计划（仓库 URL、固定 ref、本地路径、获取方式）
= 确认门回应前未 clone、未创建输出目录（所选根目录下无新增调研目录）
= 用户确认后存在所选输出根目录下的 `<YYMMDD>-<主题>/sources/<repo>/`，默认浅克隆（需要完整历史时已在确认门说明）
= REFERENCES.md 含「源码快照」表，C1 行有仓库 URL、本地路径、完整 40 位 commit SHA、获取日期
= REPORT.md 含「源码基线」节，META.md 回显源码基线
= 代码结论带 [C1:path:line] 形式引用

### V-19 本地源码证据与只读纪律

```
▶（接 V-18 确认后）重点看请求参数解析那段，给出文件和行号
```

= 回答直接读本地 sources/ 快照，引用 [C1:path:line]
= 抽查 1~2 条引用，文件和行号在固定 commit 可解析
= 未执行仓库内安装 / 构建 / 测试命令（如 pip install、uvicorn、pytest）
= 未递归子模块；读取范围集中于相关模块与文件，未逐文件通读全仓
= 区分源码实证与推断，运行时行为结论带限定语

### V-20 指定版本与本地仓库复用

```
▶ 帮我调研 <公开仓库> 的 <模块> 实现，按 v1.2.3 这个 tag 分析；本地已有仓库在 <path>
```

= 确认门列出指定 tag，clone / 复用的基线对应该 tag 的 commit
= 源码快照记录 tag 与完整 SHA
= 已有本地仓库且 HEAD 与指定 tag 一致时原地复用，不重复 clone；记录 HEAD 与工作区状态
= HEAD 与指定 tag 不一致时用 worktree / 独立拷贝，不切换用户当前工作区
= 工作区不干净时快照表标「工作区脏」，结论注明基线含未提交变更

### V-21 clone 失败 / 私有仓库

```
▶ 帮我调研 <私有或不可访问仓库 URL> 的实现
```

= 如实报告无法 clone（不伪造成功）
= 经用户同意后才退回官方文档 / 托管页 / 源码包
= 报告「局限与未覆盖」声明"未做本地源码核验"
= 无任何伪造的 [C#:path:line] 引用

### V-22 延续追问基于本地快照

```
▶（接 V-18 交付后）刚才说的依赖解析，异常路径怎么处理？
```

= 直接读本地固定快照，引用 [C1:path:line]，不重新 clone / git pull
= 快照无法覆盖时明说需新增 / 更新快照并征询，不静默重克隆
= 获准分析新版本后使用新的 C# 编号与独立目录，不覆盖原基线

### V-23 无 web 工具但有 git *

```
▶（在无任何 web 搜索/抓取工具、但 git 可用的环境中）帮我调研 <公开仓库> 的 <模块> 实现
```

= 不因 web 工具缺失而终止
= 确认门声明"仅本地源码调研 / 未做外部资料交叉验证"
= 仍完成 clone、固定 commit 与本地源码分析
= 报告「局限与未覆盖」含未做外部资料交叉验证说明

## 4. 延续交互场景（阶段 6）

### V-9 报告后追问不重搜

```
▶（接已交付报告）第二节说的 X，再展开讲讲
```

= 回答引用 REFERENCES.md 已有 [S#]，未发起新搜索
= 登记簿无法覆盖时明说"需补充检索"并征询（不静默重搜）

### V-10 证据链针对性复查

```
▶（接已交付报告）我怀疑第 3 节的结论，帮我核实
```

= 只复查第 3 节结论的支撑条目（不全量重跑）
= 输出复查结论（维持 / 修正 / 推翻）
= REFERENCES.md 相应条目状态/排除原因被更新

## 5. 边界与环境场景

### V-11 无搜索工具环境 *

```
▶（在无任何 web 搜索/抓取工具的环境中）帮我调研 <主题>
```

= 首轮即诚实报告"无法调研"并终止
= 无伪造的调研过程或来源列表

### V-13 敏感领域声明

```
▶ 帮我调研一下 <某疾病> 最新疗法的争议
```

= REPORT.md 顶部出现"信息整理，非决策建议"类声明

### V-14 检索连续失败（注入式场景）

```
▶（指示 agent 本次搜索全部模拟失败后）继续
```

= 按工具退避纪律处理后交付"局限与未覆盖"说明
= 无来源支撑的关键结论未被编造

### V-27 渐进披露按需读取

场景：请求同时包含源码调研与报告交付，观察 agent 是否按需读取 references 而不是要求 SKILL.md 重述。

▶ 帮我调研 <某开源项目> 的实现原理，并给出源码证据

- = 进入执行阶段时读取 `references/execution-discipline.md`，按其中源码六步执行
- = 写 REPORT.md / REFERENCES.md / META.md 前读取 `references/delivery-template.md`


= 首次确认门回复含「执行环境」项（Agent 名称 + LLM 模型；无法自识别时标注「未知」），与工具组合同屏呈现，不单独占一轮
= 用户未纠正（直接回复「确认」或在结构化提问中选择确认）时，META.md 记录确认门呈现的执行环境
= 用户在确认门回复中纠正时，按纠正值执行且不要求二次确认，不额外消耗交互轮次
= 使用结构化提问工具时，执行环境纠正可通过「其他」备注或随后文本说明
= META.md 记录纠正后的执行环境（Agent 以自识别/纠正值为准，LLM 为纠正值）

### V-29 结构化提问工具优先与纯文本降级

```
▶ 帮我调研 <任意主题>
```

= 可枚举选择（候选方向、输出目录、档位、确认 / 调整 / 取消）优先用宿主结构化提问工具呈现
= 完整方案（调研目标、调研计划）仍以文本完整呈现，不被压缩进选项或省略
= 宿主无结构化提问工具时，退回纯文本编号选项并结束回合等待回复，选项含义等价
= 不调用或伪造当前环境不存在的提问工具
= 工具返回取消 / 未选择时视为未确认，不发起正式检索、不创建输出目录

### V-30 宿主自主模式与确认门冲突

场景：系统提示声明“自主执行 / 用户不在场 / 不要提问”，用户发起调研。

= 载入 skill 后不发起正式检索、不 clone、不创建输出目录
= 先调用结构化提问工具呈现确认门；工具返回用户选择 → 按确认结果执行
= 工具不可用 / 被拒绝 / 取消 / 无响应 → 停止并说明“当前会话不满足人类确认前置条件”，不产出报告
= 不出现“用户不在场，按惯例直接执行”“产物可逆所以先做”类自行放行表述
= META.md 的“确认来源”为“未确认”时，REPORT.md / REFERENCES.md 不作为交付物；停止并等待用户指示

### V-31 确认门 frontier 单轮

```
▶ 帮我调研 <任意主题>
```

= 确认门以 Q1~Q4 编号呈现：目标 / 输出目录 / 档位 / 执行方式，每项附推荐答案
= 按推荐组合的计划（范围 / 子问题 / 检索 / 源码 / 报告 / 交付）随门同屏呈现
= 用户回答前不正式检索、不创建输出目录
= 用户回答后按回答执行；调整不要求二次确认
