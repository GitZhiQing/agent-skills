## 1. 选择 JSON

报告页底部的「复制选中路径」会复制一段带说明的 JSON 代码块：

```text
【windows-disk-cleanup 选择】
```json
{
  "skill": "windows-disk-cleanup",
  "schema": 1,
  "scan_id": "20261027-102033-1920",
  "scan_file": "E:\\data\\zcode\\wdc-appdata3\\scan.json",
  "root": "C:\\Users\\wangj\\AppData\\Local",
  "mode": "recycle",
  "confirmed": true,
  "paths": [
    "C:\\Users\\wangj\\AppData\\Local\\npm-cache"
  ]
}
```
```

字段含义：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `skill` | 建议 | 固定 `windows-disk-cleanup`；其他值会被拒绝 |
| `schema` | 是 | 当前为 `1`；不匹配直接拒绝 |
| `scan_id` | 是 | 必须与 `scan.json` 的 `scan_id` 一致 |
| `scan_file` | 建议 | 本次扫描的 `scan.json` 绝对路径；缺失时在 selection 文件同目录找 `scan.json` |
| `root` | 建议 | 扫描根目录；用于人工核对，不替代 `scan.json` 的 root |
| `mode` | 是 | `recycle`（移入回收站）或 `permanent`（彻底删除） |
| `confirmed` | 是 | 报告页确认框是否勾选；执行时必须有 `true` 或 `--confirm` |
| `paths` | 是 | 勾选条目的绝对路径；至少 1 条，去重，最多 5000 条 |

`paths` 是**报告中的条目路径**，不是子文件路径。不要手工往 JSON 里加路径；`delete` 会逐条比对 `scan.json`。

## 2. Agent 落盘与预演

用户把上述代码块粘贴回来之后：

1. 原样保存到本次扫描输出目录的 `selection.json`（UTF-8）。不要只摘出 paths，也不要改 `scan_id`。
2. 先预演：

   ```bash
   bash "$S/bin/windows-disk-cleanup" delete \
     --selection "$OUT/selection.json" --dry-run --json
   ```

3. 检查返回 JSON：
   - `invalid` 非空 → **停止**，把每条 `reason` 告诉用户，不要执行删除。
   - `missing` 非空 → 说明条目在执行前已不存在，可继续但要在最终报告里说明。
   - `covered` 非空 → 父子重叠，删除时以父目录为准（只删父目录）。
   - `requires_allow_review: true` → 选择包含 `review` 待确认项；执行时必须加 `--allow-review`。
   - `confirmed: false` → 用户没有在报告页勾确认框；让用户重新复制，或在用户明确确认后加 `--confirm`。
   - `estimated_h` 是预演估算，不是实际释放量。

4. 预演通过后才执行：

   ```bash
   bash "$S/bin/windows-disk-cleanup" delete \
     --selection "$OUT/selection.json" --yes --json
   ```

## 3. 校验规则

`delete` 不信任 selection 文件，逐条做以下检查；任何一条 `invalid` 都会让整批拒绝执行（不会删一半）：

| 检查 | 不通过时的原因 |
| --- | --- |
| `scan_id` 与 `scan.json` 一致 | 选择过期/来自另一次扫描 |
| 路径是绝对路径 | 相对路径无法确定位置 |
| 路径在 `scan.root` 内 | 越界删除 |
| 路径在 `scan.entries` 中 | 手工添加、路径写错、扫描后移动 |
| 条目 `selectable: true` 且 `recommendation != keep` | 报告标记为保留项 |
| `safety.protected_reason()` 返回空 | Windows/Program Files/ProgramData/用户根目录/凭据/.git/系统托管文件 |
| 路径不是 reparse point | 符号链接/目录联接不跟随、不删除 |
| 父子重叠只保留父目录 | 子目录标记为 `covered`，不重复删除 |
| 当前是否存在 | 不存在则 `skipped_missing`，不报错但不计入释放量 |

保护是**独立于扫描规则**的：即使有人手动改 `scan.json` 把 `C:\Windows\System32` 标成 `selectable: true`，`safety.py` 仍会拒绝。允许清理的系统白名单只有：

- `%WINDIR%\Temp`、`%WINDIR%\SystemTemp`
- `%WINDIR%\SoftwareDistribution\Download`（DataStore 只读，不执行）
- `%WINDIR%\Logs`、`%WINDIR%\Panther`、`%WINDIR%\LiveKernelReports`、`%WINDIR%\Minidump`、`%WINDIR%\MEMORY.DMP`
- `%WINDIR%\System32\LogFiles`
- `%WINDIR%\ServiceProfiles\LocalService\AppData\Local\FontCache`
- `%ProgramData%\Microsoft\Windows\WER`、`%ProgramData%\Microsoft\Network\Downloader`、`%ProgramData%\NVIDIA Corporation\Downloader`、`%ProgramData%\Microsoft\Windows\RetailDemo`
- 用户 `AppData\Local\Temp` 及规则库里明确标记的浏览器/应用/开发缓存
- 用户 `Downloads`（谨慎项，整目录删除前应让用户逐项确认）

不允许：驱动器根、`Windows` 整体、`System32/SysWOW64/WinSxS/servicing/Installer/DriverStore/config/catroot2`、`Program Files`、`ProgramData` 根、用户配置文件根、`AppData`/`Local`/`Roaming` 根、桌面/文档/图片/视频/音乐/OneDrive、`.git/.ssh/.gnupg/.aws/.azure/.kube/.docker`、页面/休眠/交换文件、回收站目录本身。

## 4. 确认与删除

执行需要同时满足：

1. `selection.confirmed == true`（报告页勾选）**或** CLI 带 `--confirm`（用户在聊天中明确确认）。
2. CLI 带 `--yes`；不带 `--yes` 永远只预演。
3. 选择含 `review` 项时必须带 `--allow-review`；这是第二道闸，不是替代用户确认。
4. `invalid` 为空；否则整批拒绝。
5. 至少有一条可执行项（`planned` 非空）。

`--mode` 可以覆盖 selection 里的方式，但不会降低确认要求。`recycle` 与 `permanent` 都必须显式确认。

## 5. 删除模式

### recycle（默认，推荐）

- 通过 Windows PowerShell + `Microsoft.VisualBasic.FileIO.FileSystem` 调用 shell 的回收站 API。
- 路径消失、文件进入回收站；**不会立即增加可用空间**，清空回收站后才释放。
- 适合系统项、用户数据、谨慎项；文件可在回收站恢复。
- 需要 Windows PowerShell 5.1+；找不到 PowerShell 时整批失败，提示改用 `--mode permanent`。

### permanent（更快，不可恢复）

- Python 直接删除目录树：先删文件，再自底向上删目录；遇到只读文件先清只读位再重试。
- 不跟随 junction/symlink；链接本身按链接删除，不触碰目标。
- 适合 `node_modules`、`.venv`、构建产物、临时缓存；删除后只能重新生成/下载。
- 长路径（≥248 字符）自动加 `\\?\` 前缀；仍失败时在报告里列出。

## 6. 失败处理

| 现象 | status | 处理 |
| --- | --- | --- |
| 文件被程序占用 | `failed` 或 `partial` | 关闭对应程序后重试；不要为绕过占用去删父目录 |
| 权限不足/拒绝访问 | `failed` | 以管理员身份重跑同一条命令；系统项常见 |
| 路径过长 | `failed` | 已尝试长路径前缀；仍失败时用 `\\?\` 路径手动排查 |
| 父目录已选、子项也选 | `skipped_covered` | 正常，只删父目录；报告中注明 |
| 条目在扫描后已被移走 | `skipped_missing` | 正常，不计入释放量 |
| 回收站不可用/被禁用 | `failed` | 改用 `--mode permanent`，或先启用回收站 |
| 部分子文件删除失败 | `partial` | 报告 `freed` 是实际减少量；列出前 3 条错误 |

失败不会回滚已删除的条目；报告会区分 `deleted` / `moved_to_recycle_bin` / `partial` / `failed` / `skipped_*`。退出码：全部成功 0；存在 `failed/partial` 为 1；选择/参数错误为 2。

## 7. 审计与边界

每次扫描输出目录包含：

| 文件 | 内容 |
| --- | --- |
| `scan.json` | 全量条目、规则命中、统计、错误列表、扫描参数 |
| `report.html` | 用户勾选页面（内嵌报告条目；完整数据仍在 scan.json） |
| `selection.json` | 用户粘贴的选择（Agent 落盘） |
| `cleanup.json` | 逐项结果、释放量、前后可用空间、错误 |
| `cleanup-report.html` | 清理报告页面 |

硬边界：

- 不自动勾选、不替用户决定删除项；扫描与报告都是只读。
- 不绕过 `delete` 直接用 `Remove-Item`/`rd /s`/`shutil.rmtree` 删用户路径。
- 不停止服务、不杀进程、不关闭 Defender、不改注册表、不运行 DISM/cleanmgr/Storage Sense 来“帮助”删除。
- 不删除扫描根目录本身（除非根目录命中安全规则并且用户在报告里明确选中）。
- 不把“回收站模式成功”说成“空间已释放”；清空回收站前空间仍被占用。
- 不宣称规则库覆盖所有软件；未识别目录必须以 `review` 呈现。

## 8. 命令速查

```bash
S="<skill 目录>"
OUT="<输出目录>"

# 环境检查
bash "$S/bin/windows-disk-cleanup" doctor --root "D:\\" --json

# 扫描（只读）
bash "$S/bin/windows-disk-cleanup" scan \
  --root "D:\\" --output-dir "$OUT" --min-size 50 --json

# 预演用户选择
bash "$S/bin/windows-disk-cleanup" delete \
  --selection "$OUT/selection.json" --dry-run --json

# 执行（回收站）
bash "$S/bin/windows-disk-cleanup" delete \
  --selection "$OUT/selection.json" --yes --json

# 执行（彻底删除）
bash "$S/bin/windows-disk-cleanup" delete \
  --selection "$OUT/selection.json" --yes --mode permanent --json

# 含待确认项
bash "$S/bin/windows-disk-cleanup" delete \
  --selection "$OUT/selection.json" --yes --allow-review --json
```
