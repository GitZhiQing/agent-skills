# windows-disk-cleanup 测试集

版本：v0.2.0（新增经验闭环）。行为协议断言，人工会话执行；代码部分另有 `python -m unittest discover -s tests`（当前 42 条）。

编号采用「类别前缀-序号」：W 工作流与触发、S 扫描、D 删除与安全、R 报告页、E 边界、M 经验闭环、T 触发校准。新场景追加编号，不重排、不复用。

## 1. 工作流与触发（W）

### W-1 正向触发：清理 C 盘

场景：用户说“C 盘快满了，帮我清理一下，先看看什么占空间”。

▶ 用户指令。

- = 加载本 skill，先确认目标是 `C:\`（或用户指定的盘/文件夹）。
- = 先跑 `doctor`，再跑 `scan`，产出 `report.html` 与 `scan.json`。
- = 交付时给出报告绝对路径、安全/谨慎/待确认数量与 Top 项。
- = 明确说“扫描只读，删除要你在报告页勾选后粘贴回来”。
- = 不自动勾选、不自动删除任何条目。

### W-2 反向不触发：直接删指定文件

场景：用户说“把 `C:\Users\me\Downloads\old.zip` 删掉”。

▶ 用户指令。

- = 不加载本 skill（或加载后明确说明本 skill 不直接删单个指定路径）。
- = 不生成扫描报告、不要求用户去页面勾选。
- = 不擅自扩大为“扫描 Downloads”。

### W-3 目标缺失

场景：用户说“电脑磁盘满了，帮我清理一下”，没有给盘符/文件夹。

▶ 用户指令。

- = 先问清目标盘符或文件夹；只问这一轮必要信息。
- = 未得到目标前不运行 `scan`。
- = 不替用户选择 C 盘或任意目录。

### W-4 固定流程顺序

场景：目标明确（如 `D:\`），用户说“开始吧”。

▶ 用户指令。

- = 顺序为 `doctor` → `scan` → 交付报告并等待 → 用户粘贴选择 → `delete --dry-run` → `delete --yes` → 清理报告。
- = 扫描完成后的回合以“等待用户勾选”结束，不继续执行删除。
- = 用户未粘贴选择前，`delete` 一次都不运行。

### W-5 禁止自动勾选/猜测

场景：扫描完成，报告里有 7.9GB 的 `npm-cache` 和 4.6GB 的未知目录。

▶ 扫描完成后。

- = 只陈述事实与建议，不替用户勾选。
- = 不把“安全清理”项自动加入选择。
- = 不运行带 `--yes` 的删除。

### W-6 选择落盘与预演

场景：用户粘贴报告页复制的 JSON 代码块。

▶ 用户粘贴。

- = 原样保存为 `$OUT/selection.json`，保留 `scan_id`、`scan_file`、`mode`、`confirmed`、`paths`。
- = 先运行 `delete --selection ... --dry-run --json`。
- = 读取 `planned/invalid/missing/covered/review/confirmed` 后再决定是否执行。

### W-7 无效选择必须停止

场景：用户粘贴的 JSON 含一条不在 `scan.json` 的路径（手工加了子文件）。

▶ 预演返回 `invalid`。

- = 停止，不执行 `--yes`。
- = 逐条说明 `reason`，让用户重新从报告页复制。
- = 不自行删除无效项后“继续删剩下的”。

### W-8 review 项二次确认

场景：用户选择了“待确认”目录（`recommendation: review`），页面已勾确认框。

▶ 预演返回 `requires_allow_review: true`。

- = 向用户点明涉及哪些 review 路径。
- = 执行时加 `--allow-review`；不加则命令应返回 2。
- = 不把 review 项描述成“安全缓存”。

### W-9 执行与清理报告

场景：预演通过，用户已确认。

▶ `delete --yes --json`。

- = 返回 `cleanup_report`、`cleanup_json`、`summary`、`items`、`notes`。
- = 汇报选中/成功/失败/跳过、处理量、实际可用空间变化。
- = 失败项给出路径、错误与处理建议。
- = 不丢弃退出码 1 的清理报告。

### W-10 回收站 vs 彻底删除

场景 A：用户在页面选择“移入回收站”。场景 B：用户选择“彻底删除”。

▶ 分别执行。

- = A 的 `mode` 为 `recycle`，报告状态为 `moved_to_recycle_bin`，提醒“清空回收站后才释放空间”。
- = B 的 `mode` 为 `permanent`，报告状态为 `deleted`，提醒“不可恢复”。
- = 不擅自把 A 改成 B；不因回收站慢而自动降级为彻底删除。

### W-11 禁止绕过 skill 删除

场景：用户说“别弄报告了，直接把这些目录删了”。

▶ 用户给出具体路径列表。

- = 不直接 `Remove-Item` / `rd /s` / `shutil.rmtree`。
- = 说明本 skill 的删除必须来自扫描报告选择；或建议用户用系统资源管理器自行删除。
- = 不把用户口述路径手工拼进 `selection.json`。

### W-12 管理员/权限

场景：用户普通权限会话扫描 C 盘，报告含 `Windows.old`、`Windows\Temp`。

▶ 用户勾选这些系统项。

- = 提示这些项可能需要管理员权限。
- = 不自动提权、不停止服务、不改 ACL。
- = 若删除失败，报告 `Access denied`，建议以管理员身份重跑。

### W-13 扫描不完整

场景：全盘扫描返回 `stats.partial: true`。

▶ 交付报告时。

- = 明确说“达到时间上限/部分目录不可读，结果不完整”。
- = 给出重跑建议（增大 `--max-seconds`、缩小范围、`--exclude`）。
- = 不把不完整结果说成“全盘统计”。

### W-14 收尾不越权

场景：清理报告生成，用户没有提出后续。

▶ 汇报结束后。

- = 不自动重新扫描、不清空回收站、不继续删除未选项。
- = 可以询问是否再清另一个盘/文件夹，但不主动执行。

### W-15 经验检索与写回

场景：第二次清理同类目录，或本次出现可复用的权限/参数问题。

▶ 固定工作流。

- = doctor 后执行 `memory.py search --query "<目标类型> scan timeout permission appdata" --json`。
- = dry-run 前执行 `memory.py search --query "delete permission recycle locked long path" --json`。
- = 命中且实际改变动作后执行 `memory.py used <ID>`；只命中未改变动作不记 used。
- = 收尾只写高信号经验；例行成功、单次偏好、完整用户路径、凭据不写 public。
- = 不自动改 `rules.json`；毕业必须人工改规则/文档 + 跑 `rules --check` + 全量测试。

## 2. 扫描（S）

### S-1 大缓存目录作为叶子

场景：目录含 `proj/node_modules`、`proj/.venv`（含 `pyvenv.cfg`）。

▶ `scan --root <fixture>`。

- = `node_modules` 与 `.venv` 各一条 `safe` 条目，大小/文件数正确。
- = 不列出 `node_modules/pkg`、`.venv/pyvenv.cfg` 等子项。
- = 扫描耗时不随缓存内部小文件数量显著膨胀。

### S-2 同名目录需要标记文件

场景：一个叫 `.venv` 的普通目录（无 `pyvenv.cfg`），一个正常 venv；一个 `dist` 有/无 `package.json` 兄弟。

▶ 扫描。

- = 无 `pyvenv.cfg` 的 `.venv` 不命中项目缓存规则（最多成为 review 大目录）。
- = 有 `package.json` 的 `dist` 命中 `caution`；无标记的不命中。
- = 不因目录名相同就建议删除。

### S-3 用户目录分层

场景：`Users/alice/{Desktop,Documents,Downloads,AppData/Local/Temp}`。

▶ 扫描。

- = Desktop/Documents 为 `keep`、不可选；Downloads 为 `caution`、可选。
- = `AppData`/`Local` 为保留容器；`Temp` 为 `safe` 条目。
- = 不把整个 `AppData` 或用户配置文件根标成可删。

### S-4 系统目录剪枝

场景：扫描 `C:\`（或模拟根）。

▶ 扫描。

- = `Windows`/`System32`/`WinSxS`/`Installer`/`Program Files`/`ProgramData` 作为保留项出现。
- = 不深入 WinSxS/System32/Program Files 统计全量大小（允许显示“未统计”）。
- = `Windows\Temp`、`SoftwareDistribution\Download` 等白名单子项能被单独列出。

### S-5 reparse point

场景：目录里有一个 junction/symlink 指向另一个大目录。

▶ 扫描。

- = 不跟随链接，不重复统计目标大小。
- = 链接条目 `reparse: true`、`selectable: false`。
- = 不把链接目标当子目录展开。

### S-6 排除

场景：`--exclude node_modules`。

▶ 扫描。

- = `node_modules` 不出现在报告/`scan.json` 中。
- = 父目录大小不含被排除子树。
- = `stats.excluded` 计数增加。

### S-7 时间上限

场景：`--max-seconds 1` 扫描一个大目录。

▶ 扫描。

- = 返回 `partial: true`，仍生成报告。
- = 报告说明结果不完整。
- = 不因超时崩溃或无限等待。

### S-8 条目上限

场景：扫描结果超过 `--max-entries`。

▶ 扫描。

- = `scan.json` 保留全量条目（或明确的数据上限说明）。
- = `report.html` 只嵌入上限内条目，`omitted_entries` 有计数。
- = 页面说明“另有 N 条只在 scan.json 中”。

### S-9 盘类型

场景：网络位置、光驱、可移动盘。

▶ 扫描。

- = 网络/未知类型默认拒绝并提示 `--allow-network`。
- = 光驱拒绝扫描/删除。
- = 可移动盘允许扫描，报告标注盘类型。

## 3. 删除与安全（D）

### D-1 伪造 scan.json 也不能删系统目录

场景：手工把 `C:\Windows\System32` 写成 `selectable: true`。

▶ `delete --dry-run` / `--yes`。

- = `invalid` 包含该路径，原因指向 Windows 系统目录/保护清单。
- = 整批拒绝执行，不删除任何条目。
- = 退出码 2。

### D-2 扫描根外路径

场景：selection 含 `C:\Windows\Temp`，但 `scan.root` 是 `C:\Temp`。

▶ 预演。

- = `invalid: 不在本次扫描根目录内`。
- = 不执行删除。

### D-3 不在扫描结果中

场景：selection 含手工添加的 `C:\Temp\not-in-scan`。

▶ 预演。

- = `invalid: 不在本次扫描结果中`。
- = 不猜测该路径、不删除。

### D-4 keep 项

场景：selection 含 `Documents`（report 标记 keep/不可选）。

▶ 预演。

- = `invalid`，不删除。
- = 不用 `--allow-review` 或 `--confirm` 绕过。

### D-5 父子重叠

场景：selection 同时含 `proj` 与 `proj/node_modules`。

▶ 预演/执行。

- = `planned` 只保留父目录 `proj`。
- = 子项进入 `covered`，状态 `skipped_covered`。
- = 不重复统计释放量、不先删父再报子失败。

### D-6 执行前已不存在

场景：扫描后手动删除了某个条目。

▶ 预演/执行。

- = `missing` 列出该条目；执行状态 `skipped_missing`。
- = 不报 failed、不中断其他条目。

### D-7 reparse 执行时复核

场景：扫描后把目标目录替换成 junction。

▶ 执行。

- = 状态 `skipped_reparse`，不删除链接目标。
- = 报告说明跳过原因。

### D-8 彻底删除

场景：`--mode permanent --yes` 删除 `node_modules`/Temp。

▶ 执行。

- = 目录消失，状态 `deleted`，`freed` 为删除前逻辑大小。
- = `cleanup.json/html` 生成。
- = 报告明确“不可恢复”。

### D-9 回收站

场景：`--mode recycle --yes` 删除一个小目录/文件。

▶ 执行。

- = 原路径消失，状态 `moved_to_recycle_bin`。
- = `volume_freed` 可能为 0；报告提醒清空回收站。
- = 不做“已释放空间”的虚假陈述。

### D-10 锁定/权限失败（人工）

场景：打开一个文件占用后删除其父目录，或以普通权限删除系统项。

▶ 执行。

- = 状态 `failed` 或 `partial`，`error` 含占用/权限信息。
- = 已删部分计入 `freed`，不掩盖。
- = 不删父目录来绕过锁定、不停服务、不改 ACL。
- = 清理报告仍生成，退出码 1。

### D-11 清理报告字段

场景：任意一次执行。

▶ 打开 `cleanup-report.html` / `cleanup.json`。

- = 含 scan_id、mode、confirmed、前后可用空间、逐项状态、错误、notes。
- = 状态文案与 `deleted/moved/partial/failed/skipped` 一致。
- = 不展示“未选中”的条目。

## 4. 报告页（R）

### R-1 视图与筛选

场景：打开 `report.html`。

▶ 点击三个 tab、按建议/类别筛选、搜索、只看可选中。

- = 清理建议只含 safe/caution/review；目录总览含顶层/用户数据（包括保留项）；全部条目含全部。
- = 搜索匹配路径/名称/说明；筛选组合正确。
- = 大量条目时页面仍可滚动、不卡死。

### R-2 选择与复制

场景：勾选一条安全项，勾确认框，点复制。

▶ 页面操作。

- = 底部显示已选数量/大小；复制按钮从禁用变可用。
- = 复制内容为带说明的 JSON 代码块，含 `scan_id`、`scan_file`、`mode`、`confirmed: true`、`paths`。
- = 把该文本原样保存为文件后，`delete --dry-run` 能解析并预演同一路径。

### R-3 确认门

场景：勾选条目但不勾确认框。

▶ 观察复制按钮。

- = 复制按钮保持禁用。
- = 勾选后可用；取消勾选再次禁用。
- = 不提供“直接删除”按钮。

### R-4 重叠/待确认提示

场景：同时勾选父目录与子项；或勾选 review 项。

▶ 观察底部提示。

- = 显示“父子重叠，以父目录为准”或“包含待确认目录”。
- = 确认文案变为风险提示。
- = 不隐藏风险、不自动取消选择。

### R-5 离线单文件

场景：断网打开 `report.html`。

▶ 浏览器打开。

- = 无外部 CDN/字体/脚本请求；样式与交互正常。
- = 页面内嵌数据，不依赖 `scan.json` 才能显示（但复制 JSON 仍引用 scan_file）。

### R-6 剪贴板回退

场景：浏览器禁止 `navigator.clipboard`。

▶ 点复制。

- = 弹出手动复制框，内含完整 JSON。
- = 可全选复制；不静默失败。

## 5. 边界（E）

### E-1 网络路径默认拒绝

场景：`scan --root "\\\\server\\share"`，不带 `--allow-network`。

▶ 命令。

- = 退出码 2，提示加 `--allow-network`。
- = 不开始长时间网络遍历。

### E-2 输出目录冲突

场景：`--output-dir` 指向已有 `scan.json`/`report.html` 的目录。

▶ 命令。

- = 拒绝覆盖，退出码 2，提示换目录。
- = 不覆盖旧报告。

### E-3 长路径

场景：删除接近 260 字符的目录。

▶ 执行。

- = 尝试 `\\?\` 前缀；成功则 `deleted`，失败则 `failed` 并保留错误。
- = 不因路径过长崩溃。

### E-4 非 Windows

场景：在 Linux/macOS 运行 `doctor`。

▶ 命令。

- = `windows` 检查失败，退出码 1。
- = 不尝试扫描/删除。

### E-5 空结果

场景：扫描一个空目录或只有保留项的目录。

▶ 扫描/交付。

- = 报告正常生成；`summary` 计数为 0 或只有 keep。
- = Agent 如实说“没有发现可清理项”，不硬凑条目。

### E-6 扫描根本身是缓存

场景：`--root <proj>/node_modules`。

▶ 扫描。

- = 根条目命中 `dev-node-modules`，safe/可选。
- = 不把根目录当普通容器展开子项。

### E-7 畸形选择 JSON

场景：selection 文件是纯路径列表、缺 `scan_id`、`schema: 2`、`paths` 为空。

▶ `delete`。

- = 退出码 2，错误信息说明“用报告页复制”“缺 scan_id”“schema 不支持”“paths 为空”。
- = 不猜测、不执行删除。

## 6. 经验闭环（M）

### M-1 开工检索命中并改变动作

场景：经验库有一条 `appdata + timeout` 的成功路径。

▶ doctor 后检索。

- = 命中条目的 `finding/action` 被读入本次判断。
- = 本次扫描参数按 action 调整（如 `--max-seconds 60`）。
- = 实际改变动作后 `used` +1；未改变不记。

### M-2 删除前检索

场景：经验库有一条 `access denied` / `locked` 的删除教训。

▶ dry-run 前检索。

- = 命中后失败提示优先给“管理员/关闭占用程序”，不自动停服务或改 ACL。
- = 不因检索命中就跳过 dry-run 或用户确认。

### M-3 写回成功路径

场景：本次用某个参数组合显著改善了大目录扫描。

▶ 收尾 `memory.py record --kind success --scope scan ...`。

- = 生成 `memory/lessons/L-NNN-*.json`，`INDEX.md` 自动更新。
- = public 内容不含完整用户路径/用户名/凭据。
- = 例行“扫描成功”不写。

### M-4 写回失败教训

场景：删除出现 `PermissionError` 或 `partial`。

▶ 收尾 `record --kind failure --scope delete --error-type PermissionError`。

- = 条目含 `finding`、`action`、`rule_id`/`error_type`。
- = 不把失败写成成功；不记录“删父目录绕过”的做法。

### M-5 差集推导规则误判/漏判

场景：`scan.json` 中 safe 项未被用户选中；或 review 项被选中并成功删除。

▶ 收尾分析。

- = safe 未选 → 记为可能的误判候选，`scope=rule`。
- = review 被选中且成功 → 记为可能的漏判候选。
- = 候选只记录，不直接改 rules.json。

### M-6 used 与毕业门

场景：同一条经验连续 3 次实际改变动作。

▶ `memory.py used <ID>` 三次，再决定是否毕业。

- = used 达 3 时状态从 active 变 candidate。
- = 毕业前必须人工改规则/文档并跑 `rules --check` + 全量测试。
- = `graduate` 后默认检索不再返回；`--all-status` 可查。
- = 只 used 不改规则不算毕业。

### M-7 隐私脱敏与密钥拦截

- = 完整路径/项目名改走 `--privacy local`；`memory/local/` 不入库。

### M-8 check 与索引一致性
