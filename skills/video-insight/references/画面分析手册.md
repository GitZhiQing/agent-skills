# 画面分析手册 · 方法卡片与检查清单

> 十张方法卡片（S1–S10）覆盖从通览到取色的判断手法；检查清单是逐类画面元素的过法。
> 命令已封装进 scripts/，这里只讲**读什么、判断什么、坑在哪**。

## 一、方法卡片

### S1 拼版总览（extract_frames.py --fps 1 --tile 4x2）
- **读什么**：信息增长节奏（图表何时画满/何时开始重复）、模板复用痕迹（同系列视频版式是否一致）、大块留白与常驻元素。
- **精度**：±0.5s。每格的精确时间戳在 data/frames_overview.json（t_exact 直接来自 ffmpeg showinfo）。
- **坑**：最后一张拼版可能有黑块填充（frame_index 超出实际帧数的 cell，t_exact 为 null）——不是视频黑屏。

### S2 字幕时间轴长条（extract_frames.py，strip 图）
- **读什么**：一次通读全片字幕轨。专抓四类硬伤：**漏字**（与 transcript.txt 逐句对照）、**孤字/孤词折行**（第二行只剩一两个字）、**挂时长**（同一字幕连续占了几格=几秒）、**关键词高亮不一致**。
- **方法**：以 transcript.srt 为字幕真值，逐格核对画面上实际显示的字；两者 diff 出的每个差异都是 P1 级问题。
- **坑**：字幕条默认裁切按 720×1280 模板（y=71.5%H, h=9.4%H）；版式不同先看一张 keyframe 确认字幕位置，再 `--strip-crop` 重跑。

### S3 帧差量化（detect_changes.py → changes.json）
- **读什么**：events（画面何时动、峰值多大）对齐文案分段；stills（≥1s 静止期）暴露"口播在讲、画面不动"。
- **判断**：变化密度（events_per_sec）前后对比；核心论点段落若落在最长静止期上，通常是 P0 问题。
- **口径**：阈值 0.55 为参考会话标定值；换视频类型（如真人出镜、运镜多）可适当上调，报告中写明所用阈值。

### S4 定帧回查（grab_frames.py --at）
- **何时用**：对每个要下断言的时间点，落笔前必回查一次（证据纪律 R1）。
- **读什么**：全分辨率核对拼版看不清的细节——标注形态、图例遮挡、CTA 元素、刻度压字。

### S5 局部放大（grab_frames.py --crop ... --zoom 6）
- **何时用**：字幕逐字、轴刻度、小数点、图例小字。文字用 `--flags neighbor`（像素锐利），照片用 lanczos。
- **判断**：放大后仍读不清的，如实写"不可读"，这就是问题本身（如成交量刻度被量柱压住）。

### S6 面板亮度代理（palette.py 的 mean_luma_0_255）
- **读什么**：同一面板不同时刻的 mean_luma 对比——白底面板越空亮度越高，可量化"前 N 秒画面零增长"。
- **口径**：必须同区域对比，且声明它是代理指标（推断档）。

### S7 音频三层检测（audio_probe.py → audio.json）
- **交叉判断法**（单层不可下结论）：
  | 判断 | 停顿 RMS | 噪声底 | 频谱 |
  | --- | --- | --- | --- |
  | 纯干声 | 接近噪声底 | 很低（-53 或 -80dB） | 能量只在语频段 |
  | 有 BGM | 明显高于噪声底 | 偏高 | 语频外有持续能量（尤其 <500Hz） |
  | 有音效 | — | — | 短时宽频瞬态（对齐 changes.json 事件时刻看） |
- **停顿的位置语义**：停顿落在语义转折点（提问后/结论前/CTA 前）是节奏设计；均匀散布则多半是换气。

### S8 区域取色（palette.py --crop）
- **读什么**：saturated 列表 = 画面真实用色；dominant_any[0] 通常是背景色。
- **坑**：见证据纪律 R3——1×1 采样禁止；同片不同面板可能用同族相近色。

### S9 口径声明
所有"约"字时间点 = 抽帧精度 ±0.5s；模板文字见 references/证据纪律.md §1。

### S10 证据归档
evidence/ 分类目录 + 报告末尾索引；索引格式：

```
evidence/
├─ overview/     overview_01.jpg        # 0–7s 逐秒拼版（t_exact 见 data/frames_overview.json）
├─ subtitle-strip/ strip_01.jpg        # 全片字幕轨，一格一秒
├─ keyframes/    2_16.5s.jpg           # 巨量圈选定型（断言出处）
├─ crops/        2_字幕_20.5s_720x90_x6.png  # 字幕放大，核对漏字
└─ audio/        spectrogram_full.png  # 全片频谱
```

## 二、画面元素检查清单

**字幕**：漏字/多字；孤字折行；挂时长（长句>3s 不换块）；关键词高亮有无与规则统一；标点呈现；与口播的先后关系。
**标注（圈选/箭头/胶囊）**：口播提到的每个概念是否被画出；二元概念（阳/阴、进/出）是否画了两种；圈选时机与口播时序差；颜色语义是否统一（同一事件多色=问题）；标注退场时机；是否遮挡图例/刻度。
**图表类（K线/走势）**：画满时刻 vs 开头钩子的错位；参照线缺失（压力位/均量线/区间上下沿）；量价对应关系可见性；刻度可读性与单位；图例遮挡。
**版式**：分区占册（顶部标题是否剧透结论/承诺未兑现的方法论）；常驻元素（免责声明、CTA）；安全区（抖音底部 UI 遮挡区）。
**CTA**：口播说"点头像"画面有没有对应视觉引导；胶囊/箭头出现时刻。
**合规**：免责声明常驻与否；画面文字有无确定化暗示（口播不确定、画面框死一根=语义冲突）。

## 三、layout.json 口径（版式解剖）

模型基于 keyframes 目测 + crops 验证后写入 data/layout.json（可手工，非脚本产物）：

```json
{"zones": [
  {"name": "顶部标题区", "y_range": [40, 190], "share": 0.12,
   "content": "两行大字，结论常驻", "evidence": "keyframes/2_0.5s.jpg"}
]}
```

- y_range 用全分辨率帧目测，share = 高度占比；每个 zone 至少挂一张证据图。
- 分区边界存疑时：`palette.py --crop 全宽x窄条+0+候选y` 看亮度/颜色突变来定边界。

## 四、常见陷阱

1. **fps 偏移歧义**：一律以 data/frames_*.json 的 t_exact 为准，不靠心算"第几张是第几秒"。
2. **拼版黑块**：见 S1，padding 不是内容。
3. **音频-字幕先行/滞后误判**：字幕时间戳以 transcript.srt 为准；画面字幕出现时刻以帧差事件或定帧为准；两者差 >0.5s 才能写"滞后"。
4. **转写稿不是字幕**：转写含口播全部文字，画面字幕可能删改（漏字类问题恰恰来自这里）。
