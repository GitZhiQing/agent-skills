# 证据纪律 · 可执行规则

> 本文是**硬约束**：报告交付前逐条自检，任何一条不满足就不交付。每条规则都附上它防止的具体失真。

## 1. 表述分三档（报告中强制标注）

| 档位 | 允许的写法 | 前提 |
| --- | --- | --- |
| **实测** | "16.43s→20.37s 无画面变化" | 有 JSON 数据（changes.json 等）或精确定帧支撑 |
| **约** | "约 4.1–4.6s 绿框退场" | 1s 抽帧（±0.5s）推断，且报告已声明该精度 |
| **推断** | "推测作者想让观众先看红 K" | 必须显式写"推断/疑似"，不得混入实测句式 |

**口径声明模板**（放报告"方法与口径"节）：

> 1 秒抽帧只能定位到 ±0.5 秒，凡文中写"约"的时间点均为该精度；凡写具体秒数的均来自定帧（`evidence/keyframes`）或帧差 JSON（`data/changes.json`）的逐帧结果。

## 2. 硬规则

**R1 · 时间断言先取证**
任何带秒数的结论，落笔前必须有：一次直接定帧（grab_frames）或一条 JSON 数据。拼版里"看起来是"不算——采样偏移足以把"滞后"算成"超前"，凭印象写下的时间断言是报告里最容易被核对推翻的部分。

**R2 · 归档即校验**
每个脚本跑完读 `<OUT>/manifest.json`：status 必须为 ok；`missing` / `missing_files` 出现即停下修复。报告写完前抽查 1–2 张 evidence 图片确认内容与断言相符。归档链只要中途断一次，空目录就会被当成"没问题"。

**R3 · 取色只用区域众数**
取色一律 `palette.py --crop`（区域直方图众数），禁止 1×1 像素采样——单像素取到白底就会给出误导色。同时注意同一视频不同面板可能用相近色阶（如 #EE534C 与 #EE4A42 并存），对比结论写"同族红"而非硬拼 hex。

**R4 · 结论被质疑的处置**
客观结论被用户质疑时：给一次带数据的说明，然后把产出改写为"对两种可能都成立"的表述，继续推进主线。不与用户反复争论一个不关键的结论——赢了检测输了进度。

**R5 · 临时产物与可播放性**
渲染/抽帧类中间产物跑完即清（transcribe.py 已自动清 tmp）；凡是留下的产出媒体，校验非空、可打开（图片非零字节；视频要能解出首帧）。废帧与缺 moov 的坏 mp4 会悄悄留在工作区并污染下一次运行。

**R6 · 时间账前置**
有截止时间的任务，先算"各方案工时 vs 剩余时间"摆给用户，选完再动手。

**R7 · 交付形态对齐**
动手前复述交付形态并获认可。把该自己做的活推给下游工具的前提是质量不降级；否则必须在方案里写明代价，让用户选。**禁止静默降级**——形态错一次就是整轮返工。

**R8 · 分析深度不默选（HIL）**
档位（L1/L2）与交付形态同属用户的选择权：用户措辞明确时宣布档位与成本后执行；**不明确时必须提问并等回答**。无用户可问（批处理/子代理）时取 L1 执行，并在报告头部与 `manifest.json` 的 `declaration` 块显式声明"档位未确认"。实测 L2 成本约为 L1 的 3–8 倍，默选等于替用户做预算决策；同样禁止把 L1 的"要不要升级 L2"当成自问自答。
