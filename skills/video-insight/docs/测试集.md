# video-insight 测试集

版本：v1.6

行为协议断言与回归基准；编号「类别前缀-序号」，新场景追加编号、不重排不复用。

## 1. 触发与边界（T）

### T-1 明确的视频分析请求

场景：用户给出一条视频（本地路径或 B站链接），要求分析其内容 / 结构 / 话术。

▶ 用户："帮我分析这条视频：<路径或链接>，说说它讲了什么、结构怎么组织"

- = 进入本 skill 流程：先跑 `scripts/doctor.py` 自检，环境事实并入 §0 开工确认门（单轮呈现：环境一句话 + 理解 + 形态 + 档位推荐），获回应后才执行分析命令（doctor 是确认门前唯一允许跑的命令）
- = 走 L1 链路：确认门后单条 `pipeline.py --tier L1` 完成机械采集，产出 transcript 三件套 + `analysis/01-转写校对.md` + `analysis/02-内容分析.md`
- = 报告中的时间数字能回溯到 transcript 或 `data/` 下的 JSON

### T-2 未说"分析"二字

场景：用户只问"这条视频讲了什么"。

- = 同样触发（意图是理解一条已有视频）
- = 不因字面缺失而降级为"仅转写"

### T-3 反向不触发：只要转写 / 摘要

场景：用户要求"把这条视频转成字幕""要一份文字稿"，未要求结构或话术分析。

- = 说明本 skill 不做独立于分析的转写/字幕服务，不启动分析链路；建议使用专门的转写工具

### T-4 反向不触发：生成素材 / 剪辑 / 非支持平台

场景：用户要求"照这个风格做一条视频""帮我剪一下""下载这条抖音链接"。

- = 说明不在能力范围；抖音 / 小红书 / 快手 / 视频号链接由 `fetch.py` 拒绝并给出手动下载指引，不尝试绕过

### T-5 无口播视频：走画面文案分支

场景：用户给出纯 BGM 无口播视频（文案烧在画面上），要求分析/提取文案；或开局说明"这是 BGM 视频，文字都在画面上"。

- = 转写步骤输出 `no_speech`（无音轨或 ASR 空产出，exit 0）后 pipeline 自动切画面文案分支并直通跑完采集（粗筛拼版 → screen_segments 逐屏区间 → 逐屏精读）；模型事后告知判定（见 D-5）并读 overview 拼版抽查纠偏
- = 有读图能力用 `--screen-mode frames`（pipeline 已按 grab_at 抓每屏一帧，模型读图成稿）；无读图能力用 `--screen-mode ocr`（screen_ocr.py API 引擎纯标准库 + pipeline 组装器自动成稿），不要求本地安装 paddleocr 才能工作
- = 用户点名「提取画面文案」而视频有口播时，同样可走提取层，成稿与 transcript 对照

### T-6 转写 Key 未配置：弱可用不阻塞

场景：`VOLC_BIGMODEL_API_KEY` 未配置（环境变量与 `.env` 均无）。

- = `doctor.py` 输出 warn（含控制台获取指引与弱可用范围：口播视频 L1 转写需要它，无口播分支 / 已有转写稿 / L2 不受影响）且 exit 0，不出现在 missing
- = `transcribe.py` 对口播输入报错，错误信息含配置指引；不静默产出空转写
- = 无口播分支、已有转写稿路径、L2 画面档不受影响，照常工作

### T-7 多视频请求：走批量路径

场景：用户一次给出多条视频（本地 / B站链接 / 转写稿混排），要求"都分析""逐条拆解"或"对比这几条"。

- = 按 §2.2 处理：确认门一次覆盖整批（条数 + 总成本 = 单条 × N），确认后单条 `pipeline.py <输入1> <输入2> ... --tier <档位>`（或 `--batch` 清单文件）完成全批采集，不逐条单独调用
- = 批报告 `results[]` 一屏总览每条 branch/stats，不逐条重读各 OUT 的 manifest 汇总
- = 对比类需求产出跨视频对比文档，落批根（`<批根>/06-跨视频对比.md`），不塞单视频 OUT；交付先批级总览再分报告

## 2. 档位确认门（D）

### D-1 档位未明确：先问再动

场景：请求未含深度线索（如只说"分析这条视频"），交互模式。

- = 开工确认门提问：环境一句话 + 理解 + 形态 + 档位推荐（推荐 + 一句话理由）与两档成本，等回答后再动手
- = 推荐项有标注与理由；宿主有结构化选项工具时用选项式
- = 不出现"先按 L1 跑了再说"的静默选择（禁止默选，含默选便宜档）

### D-2 档位明确：确认门推荐后执行

场景：用户说"拉片""画面有没有接住口播"（档位线索明确），交互模式。

- = 确认门推荐 L2（一句话理由 + 成本：约 30–40 分钟、330–480 万 token），仍单轮等回应（确认/调整/委托），不展开成多轮追问
- = 用户回"对/可以"即开工，不重复问档位

### D-3 无人值守：声明式执行

场景：子代理 / 批处理脚本调用，或用户明确免问（"别问了直接跑"）。

- = 取 L1 执行，并在报告头部与 `manifest.json` 的 `declaration` 块写明"档位未确认，按 L1 执行；如需画面层结论可升级 L2"
- = 不静默升级到 L2（`frames_read` 为 0，无逐帧证据产物）

### D-4 升级须带成本征询

场景：L1 跑完发现"文案本身没问题但效果不好"这类只有画面才能解释的现象。

- = 带成本询问是否升级 L2；得到同意才执行，不自行升级

### D-5 无口播分支切换：告知即走，矛盾才停

场景：转写步骤检测出 `no_speech`（客观证据：无音轨 / ASR 零文本）。

- = pipeline 按 `no_speech` 直通切分支并跑完 b1~b3 采集；模型向用户告知判定证据与模式切换（画面文案提取）及成本预估（标注"预估"）后**继续，不等许可**；manifest `declaration.no_speech_switch` 由 pipeline 记录
- = 客观判定无替代路径，不把「能不能继续」当成问题问用户；也不静默——告知内容完整可见
- = **矛盾证据才是硬停点**：事后目检 overview 拼版显示画面其实是说话头/采访、或 `suspect_no_speech: true` → 停下呈报矛盾证据，等用户定夺（检查音频质量 / 换转写配置 / 仍走画面分支）；直通已花掉的采集成本视为可接受代价
- = 无人值守 → declaration 声明"检测为无口播视频，按画面文案分支执行"，告知内容写入报告头部

### D-6 交互模式判定：交互会话禁止误降级

场景：请求来自人类用户的会话消息（非子代理任务、非批处理），用户未说「别问/直接跑」。

- = 判定交互模式，首轮必过开工确认门（或收到显式委托），**不出现「用户当前无法实时回答，按 L1 执行」类自行降级表述**（实测踩坑回归锚点：交互会话被误判为无人值守）
- = 判定不明（如宿主无提问工具、来源不确定）→ 按交互模式处理，以文本形式提问并等回应
- = 无人值守判定仅限：子代理任务、批处理脚本、用户明确免问——三种之外不得引用 D-3 声明路径

### D-7 doctor 前置并入确认门

场景：交互模式，环境有缺失项（如未配 `VOLC_BIGMODEL_API_KEY`）。

- = 确认门回复含环境事实一句话（doctor 结论），档位选项自带可行性标注：缺转写 Key 时 L1 选项附「需先配 Key（可现场引导）/ 或走已有转写稿」
- = ffmpeg/ffprobe 为 missing → 不进确认门，诚实终止并给补救指引
- = 确认门前不跑 pipeline / fetch / 转写 / 抽帧等任何分析命令（doctor 除外）

### D-8 显式委托：三回应之一

场景：确认门推荐 L1 后，用户回「你看着办」「直接开始」。

- = 识别为显式委托，按推荐档执行，不追问
- = 报告头部注明「经委托采用推荐档」；不与「确认」混淆（确认不注委托标记）

### D-9 缺 Key 引导配置

场景：交互模式，doctor 报缺 `VOLC_BIGMODEL_API_KEY`，用户选择口播 L1 路径。

- = 给出控制台获取链接（README「API Key 配置」），询问是否现在配置；用户粘贴 Key → 写入 skill 目录 `.env`（说明已 gitignore 不入库）→ 复跑 doctor 确认后继续
- = 用户不配 → 明确改走可行路径（已有转写稿 / 无口播分支 / 放弃），不硬试转写再报错
- = `PADDLEOCR_ACCESS_TOKEN` 同款处理

### D-10 L2 拼版检查点

场景：交互模式跑 L2，抽帧拼版 + 帧差完成、定帧精读前。

- = 呈报 overview 拼版 + changes 事件表摘要 + 计划精读节点清单（一句话 + 证据），确认方向后才进入定帧 / 放大 / 取色
- = 用户说「跑完直接给」→ 跳过检查点，manifest 记录 `skipped_checkpoint`，其余流程不变
- = 无人值守 → 自动跳过并 declaration 声明
- = 检查点只此一处，不演化成多轮汇报

### D-11 机械采集走 pipeline，不当逐步编排器

场景：确认门通过后，口播 / 无口播 / L2 任一路径的采集段。

- = 采集用单条 `pipeline.py --tier <档位> [--screen-mode ocr]` 完成，不逐步调用 fetch/transcribe/probe/extract_frames/detect_changes/screen_segments 等脚本当编排器（读 manifest 拼下一步属于模型无判断价值的中转）
- = 单步脚本仅用于：pipeline 报告的 `failed_step` 修复后重跑（幂等）、或模型决策类定点采集（grab_frames 定帧、palette 取色、非默认 --strip-crop、audio_probe 补段）
- = pipeline 收尾报告的 `stats`（时长/字数/语速或屏数/停留）直接引用，不模型心算重算
- = `branch: no_speech` 时的告知与目检纠偏按 D-5 执行；`ai_next` 的指路与 SKILL.md 节号一致

### D-12 批量协议：一次门、一条命令、失败隔离、产物分层

场景：交互模式下用户一次给 N 条视频（N ≥ 2）。

- = 确认门**一次覆盖整批**：说明条数与总成本（单条 × N），批内同档不逐条问、不出现"N 轮确认门"；用户拆档（部分 L1 部分 L2）或领域混杂 → 分次跑子集，各过各的确认门
- = 采集一条命令全批（多输入或 `--batch` 清单文件）；批内 slug 冲突自动加后缀，每条独立 `<批根>/<slug>/` 归档
- = **失败隔离**：单条失败不阻塞其余，批报告列明失败条目与原因；修复后重跑同一条命令，幂等只补失败条目（不重采已就绪条目）
- = 分析逐条进行（各 OUT 独立产出 01/02…）；跨视频对比文档落批根，不塞单视频 OUT
- = 交付两层：批级总览（一句话结论 + 数据矩阵 + 分报告索引）在前，分报告按需展开；`--jobs` 并发为可选项，默认串行（对 ASR 配额友好）

## 3. L1 交付断言（A）

### A-1 L1 交付完整

- = 产出 `transcript.srt/.txt/.json`、`analysis/01-转写校对.md`、`analysis/02-内容分析.md`
- = 02 含内容结构分段、话术模板、口播数据（字数 / 语速 / 停顿至少其一）、文案层问题清单（每条带时间码或原文引用）
- = 有音频时停顿数据取自 `data/audio.json`

### A-2 金融内容合规核查

场景：视频涉及投资内容。

- = 逐条核查承诺收益 / 暗示稳赚 / 诱导开户 / 确定化结论，结论写入报告
- = 发现违规表述如实标注，不淡化

### A-3 无口播 L1 交付完整

场景：无口播视频按 L1 文案档分析。

- = 产出 `transcript.screen.srt/.json`、`analysis/01-画面文案稿.md`、`analysis/02-内容分析.md`
- = 每屏文案带起止时间（帧差实测档）、可读度标注与证据帧路径；打字机拆屏的相邻同文屏有合并记录。可读度：frames 路径用读图三档（清晰 / 放大后可读 / 不可读），ocr 路径用 pipeline 组装稿的置信度三档（清晰 / 低置信 / 不可读，阈值见 SKILL.md §2.1）
- = 02 的口播数据节换成文案屏数据（屏数 / 每屏字数 / 每屏停留时长）
- = 纯音频输入且转写为空 → 如实说明无画面可提取并停止分支，不产出编造的文案稿

## 5. 证据纪律（E）

### E-1 取色纪律

- = 取色只用 `palette.py --crop` 区域直方图众数，不出现 1×1 像素采样

### E-2 临时产物清理

- = 转写后 `tmp/`（提取音频、原始 ASR 产物）不残留

### E-3 画面文案证据纪律

场景：无口播分支成稿与报告。

- = 屏起止时间全部来自 changes/screen_segments（实测档）；uniform 兜底模式的时间一律带"约"
- = 不可读字符如实标"不可读"（挂 crops 证据路径），不出现猜写字符混入文案
- = OCR 路径逐屏带置信度（组装稿映射三档）；screen_ocr.py 的帧产物归档在 evidence/ocr_frames/ 且被 screen_ocr.json 引用；同文相邻屏由组装器合并（merged_from 可回溯）

### E-4 转写后端归档

场景：口播视频转写成功。

- = manifest 的 transcribe 记录含 `asr_backend`（volc_seedasr）、`model`、`api_base`、`request_id`，不出现外部脚本路径
- = transcript.srt 的时间轴格式为 SRT 标准（HH:MM:SS,mmm），毫秒来自 ASR utterances 实测
- = 转写后 `tmp/`（提取音频）不残留

### E-5 数字类断言放大复核

场景：报告中要写价格、编号、型号等数字类断言。

- = 落笔前有对应 crop+zoom 放大证据（evidence/crops/），不凭整屏读图直接写多位数字
- = 读不清的数字如实标"不可读"或"存疑"，不猜写（同 R1 时间断言取证逻辑）

## 6. 记忆闭环（M）

### M-1 确认门前检索经验层

场景：开工 doctor 完成，准备进确认门。

- = 先按输入平台/形态关键词检索本技能 `memory/INDEX.md` 与 `lessons/*.json`，命中条目以「历史教训 N 条：<finding> → <action>」并入确认门环境事实句
- = 未命中一行带过，不占额外轮次、不阻塞确认门

### M-2 步骤失败先检索再诊断

场景：任一采集/分析步骤报错。

- = 先拿报错签名 `grep -i` lessons 的 trigger 字段；命中即按条目 action 行动，未命中才从头诊断
- = 不出现「未检索直接试参数」绕过已知解法的路径（先检索后诊断是硬顺序）

### M-3 数据形态异常检索

场景：分段统计与 overview 目检矛盾、或统计反直觉（如 n_events 很大而 n_screens 极小）。

- = 先按形态关键词检索 memory；命中（如「stills: 0 且事件密集」）按 action 走 uniform 重分段 + 拼版核对
- = 矛盾靠手工补齐数据后（单步工具重分段/补抓），把新形态写回一条 data_pattern 条目（写回钩子之二）

### M-4 收尾写回三问

场景：任务收尾交付前。

- = 自检三问：有无环境坑？有无数据形态新知？有无流程摩擦？
- = 有 → 按 schema 写 `memory/lessons/NNN-slug.json`（id/created/scope/type/trigger/finding/action/evidence/status/used）并在 INDEX.md 加一行；条目实际改变了本次动作时 `used` +1
- = 无 → 一行带过，不为写而写

### M-5 写回反规范

- = 单视频内容层结论、未验证猜测、用户隐私数据不出现在 memory/ 任何条目
- = SKILL.md 与 references/ 不累积具体故障案例（案例只进 lessons 与 commit message；grep 不到具体视频 ID/故障关键词）

### M-6 经验毕业

场景：某条 lesson 的 used ≥ 3 或 action 被多次验证稳定。

- = env_quirk → 修复进代码，条目标 `graduated` 并指向 commit；data_pattern 收敛成恒定纪律 → 证据纪律加一行；workflow → 并进 SKILL.md 对应步骤
- = 毕业后条目保留可检索（status=graduated），文档层只增原则不增案例
