# video-insight · 设计规格

> 本文是 video-insight 技能的当前设计规格：定位、档位、流程、结构、决策理由、输出契约与验证方式。
> 行为约束见 `references/证据纪律.md`，画面方法见 `references/画面分析手册.md`，报告骨架见 `references/输出模板.md`；对外接口以 `SKILL.md` 为准。

## 1. 定位与边界

| 项 | 内容 |
| --- | --- |
| 做什么 | 把一条视频变成结构化洞察：内容结构、话术拆解、画面版式、节奏、音画对齐、问题清单 |
| 上游 | video-to-subtitle-summary（提供转写能力） |
| 与上游的分工 | 上游产出"字幕 + 浅摘要"；本技能消费字幕做深度分析。可直接跑本技能（自动调用上游转写脚本），也可复用已有转写稿 |
| 不做什么 | 生成素材、剪辑、下载（仅 B站 经 `fetch.py`，其余平台人工）、内置 ASR 模型代码 |

## 2. 两档模式

| | L1 · 文案档 | L2 · 画面档 |
| --- | --- | --- |
| 输入 | 视频 / 音频 / 已有转写稿 | L1 全部 + 视频文件本身 |
| 手段 | 转写 → 校对 → 分段 → 结构分析 | L1 + 抽帧 / 帧差 / 定帧 / 放大 / 音频检测 / 取色 |
| 产出 | 01-转写校对、02-内容分析 | 追加 03-画面分析、04-音画对齐、05-问题与优化清单 |
| 适用 | 拆解选题 / 话术 / 结构；快速了解视频讲什么 | 判断"画面有没有接住口播"、排版缺陷、节奏拖沓、标注时机 |
| 成本（实测） | 40–130 万 token、6–10 分钟 | 330–480 万 token、27–37 分钟（约为 L1 的 3–8 倍） |

**升级到 L2 的触发**：用户提到 画面 / 拉片 / 排版 / 节奏 / 音画 / 承接 / 标注 / 字幕样式；或 L1 发现"文案本身没问题但效果不好"这类只有画面才能解释的现象。触发只是建议——带成本问用户，得到同意再跑。

**档位确认（HIL）**：措辞明确时宣布档位与成本后执行；不明确时提问并等回答；无用户可问（批处理 / 子代理）时取 L1 并在报告头部与 `manifest.json` 的 `declaration` 块显式声明"档位未确认"。禁止默选。

## 3. 执行流程

```
输入识别（B站链接 / 本地视频 / 本地音频 / 已有转写稿）
        ↓
doctor 自检：ffmpeg · ffprobe · python · ASR helper · API Key · 磁盘 · 滤镜
        ↓
fetch（仅 B站链接）：yt-dlp → video.mp4 → ffprobe 可播放校验
        ↓
转写（火山引擎豆包 2.0 + 领域热词）→ transcript.srt / .txt / .json
        ↓
probe：ffprobe → meta.json
        ↓
┌─ L1 ────────────────────────────────┐
│ 术语校对 → 语义分段 → 口播数据统计    │
│ → 逻辑骨架 → 主张与准确性核查         │
│ → 01-转写校对.md / 02-内容分析.md     │
└─────────────────────────────────────┘
        ↓ （L2 追加）
抽帧拼版 → 字幕时间轴长条 → 帧差量化 → 定帧回查 → 局部放大 → 音频检测 → 取色
        ↓
逐段「文案 × 画面」对照 → 版式解剖 → 音画对齐分析 → 分级问题清单 → 优化动作清单
        ↓
产出 + manifest + 证据索引
```

每个脚本跑完更新 `manifest.json`，下一步前检查 status（不 ok 先修复）。

## 5. 关键设计决策

1. **转写能力用"发现 + 调用"，不复制脚本**：`resolve_asr.py` 按序查找（`VIDEO_INSIGHT_ASR_SCRIPT` → 同 skills 根目录的上游技能 → 本技能 `scripts/` 下的副本），三级都找不到则报错并给出指引。复制一份 ASR helper 必然与上游漂移；声明依赖 ≠ 复制代码。
2. **领域热词做成预设**：热词是转写准确率的决定因素（金融术语漏了热词必错）。`presets/hotwords/` 随技能分发，先判断领域再注入，判断不了用 `--domain none`。
3. **中间结果一律 JSON，不解析 ffmpeg 日志**：数字精确、可重复、可 diff、不烧上下文。
4. **抽帧即写时间戳**：每张拼版与字幕轨的每一格在 JSON 里记录精确秒数（取自 ffmpeg showinfo），从源头消灭"这张图是第几秒"的歧义。
5. **证据分档**：实测 / 约 / 推断三档，报告强制标注（`references/证据纪律.md`）。
6. **报告骨架固定**：结论速览 → 方法与口径 → 正文 → 分级问题清单 → 优化动作清单 → 证据索引（`references/输出模板.md`）。
7. **环境自检独立成脚本**：`doctor.py` 一次输出 JSON 判决，SKILL.md 只需一句"先跑 doctor，缺失项按提示补"。
8. **路径跨平台**：产物统一进 `<workdir>/video-insight/<slug>/`，可用 `--output-dir` 覆盖；不假设 `/tmp`。
9. **链接支持矩阵以实测为准**：B站（yt-dlp）为唯一支持平台；抖音 / 小红书 / 快手 / 视频号不支持，`fetch.py` 拒绝时返回原因与手动下载指引。恢复某平台的条件：可靠官方文档 + 真实链接实测通过。
10. **分析深度须用户确认（HIL）**：档位决定成本一个数量级（见 §2），未明确时提问，无用户可问时显式声明；禁止默选。

## 7. 触发设计

触发只走 `SKILL.md` 的 frontmatter `description`（该字符串是唯一来源），它必须同时写清三件事：

- **做什么**：两档模式各自的能力；
- **什么时候用**：分析 / 拆解 / 拉片 / 画面 / 音画 / 节奏 / 字幕等意图，包括"只问一条视频讲了什么"这类未明说"分析"的请求；
- **边界**：仅需转写或摘要走 video-to-subtitle-summary；生成素材不属于本技能。

边界写进 description 是为了不与上游技能抢触发。

## 8. 验证与回归

| 手段 | 内容 |
| --- | --- |
| 单测 | `python -m unittest discover -s tests`：49 条（解析函数与各脚本单元 + 合成视频全管线集成测试） |
| 已知答案回归 | 2.mp4（33.3s / 720×1280 / 30fps）：帧差事件 0.37 / 1.93 / 2.97 / 4.57 / 9.87 / 12.10 / 14.80…、五处停顿、LUFS −16.0 / TP −1.4 / LRA 1.7、L1 173 字 / 5.2 字每秒；2.mp4 与 3.mp4 取色 #EE534C 家族 / #25A87D |
| 归档校验 | 每次运行读 `manifest.json`：全部 status=ok、无 missing |
| 链接支持回归 | `fetch.py` 对 B站真实链接下载成功且可播放；对抖音 / 小红书 / 快手 / 视频号返回拒绝原因 |

改任一脚本或热词预设后，至少跑单测 + 受影响部分的已知答案回归。

## 9. 明确不做的事

- 不生成任何素材（图 / 视频）
- 不做视频下载（当前仅 B站 经 `fetch.py`，其余平台人工下载后用本地文件）
- 不内置 ASR 模型代码（只做发现与调用）
- 不追求"分析得更多"，追求"结论可信、可回溯、可重复"
