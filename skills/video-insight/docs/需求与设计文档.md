# video-insight · 设计规格

> 本文是 video-insight 技能的当前设计规格：定位、档位、流程、结构、决策理由、输出契约与验证方式。
> 行为约束见 `references/证据纪律.md`，画面方法见 `references/画面分析手册.md`，报告骨架见 `references/输出模板.md`；对外接口以 `SKILL.md` 为准。

## 1. 定位与边界

| 项 | 内容 |
| --- | --- |
| 做什么 | 把一条视频变成结构化洞察：内容结构、话术拆解、画面版式、节奏、音画对齐、问题清单 |
| 转写 | 内置火山引擎 Seed ASR 托管 API 客户端（`asr_volc.py`，纯标准库直连），配合领域热词预设；也可复用已有转写稿 |
| 不做什么 | 生成素材、剪辑、下载（仅 B站 经 `fetch.py`，其余平台人工）、独立于分析的转写/字幕服务、内置 ASR 模型（只内置托管 API 薄客户端） |

## 2. 两档模式

| | L1 · 文案档 | L2 · 画面档 |
| --- | --- | --- |
| 输入 | 视频 / 音频 / 已有转写稿 | L1 全部 + 视频文件本身 |
| 手段 | 转写 → 校对 → 分段 → 结构分析 | L1 + 抽帧 / 帧差 / 定帧 / 放大 / 音频检测 / 取色 |
| 产出 | 01-转写校对、02-内容分析 | 追加 03-画面分析、04-音画对齐、05-问题与优化清单 |
| 适用 | 拆解选题 / 话术 / 结构；快速了解视频讲什么 | 判断"画面有没有接住口播"、排版缺陷、节奏拖沓、标注时机 |
| 成本（实测） | 40–130 万 token、6–10 分钟 | 330–480 万 token、27–37 分钟（约为 L1 的 3–8 倍） |

**无口播形态**（纯 BGM 无人声、文案烧录画面，或无音轨）：画面是文案唯一来源，两档都必须先走 §3.1 画面文案提取。L1 = 提取 + 内容分析（成本预估 60–150 万 token，待实测回填）；L2 照常叠加，音画对齐变为「BGM 结构 × 文案屏切换」。

**升级到 L2 的触发**：用户提到 画面 / 拉片 / 排版 / 节奏 / 音画 / 承接 / 标注 / 字幕样式；或 L1 发现"文案本身没问题但效果不好"这类只有画面才能解释的现象。触发只是建议——带成本问用户，得到同意再跑。

**档位确认（HIL）**：措辞明确时宣布档位与成本后执行；不明确时提问并等回答；无用户可问（批处理 / 子代理）时取 L1 并在报告头部与 `manifest.json` 的 `declaration` 块显式声明"档位未确认"。禁止默选。

## 3. 执行流程

```
输入识别（B站链接 / 本地视频 / 本地音频 / 已有转写稿）
        ↓
doctor 自检：ffmpeg · ffprobe · python · ASR Key · 磁盘 · 滤镜 · OCR 回退
        ↓
fetch（仅 B站链接）：yt-dlp → video.mp4 → ffprobe 可播放校验
        ↓
转写（火山引擎 Seed ASR volc.seedasr.auc + 领域热词）→ transcript.srt / .txt / .json
        ↓ 无音轨或 ASR 空产出（no_speech）──┐
        ↓                                  ↓
probe：ffprobe → meta.json          ┌─ 无口播分支（§3.1）─────────────┐
        ↓                          │ 粗筛拼版确认文字卡形态            │
┌─ L1 ──────────────────────┐      │ → 帧差 → screen_segments 逐屏区间 │
│ 术语校对 → 语义分段 → 口播数据统计│      │ → 逐屏定帧读图 / OCR 回退         │
│ → 逻辑骨架 → 主张与准确性核查     │      │ → transcript.screen.* 成稿        │
│ → 01-转写校对.md / 02-内容分析.md │      │ → 01-画面文案稿 / 02-内容分析     │
└───────────────────────────┘      └─────────────────────────────────┘
        ↓ （L2 追加）
抽帧拼版 → 字幕时间轴长条 → 帧差量化 → 定帧回查 → 局部放大 → 音频检测 → 取色
        ↓
逐段「文案 × 画面」对照 → 版式解剖 → 音画对齐分析 → 分级问题清单 → 优化动作清单
        ↓
产出 + manifest + 证据索引
```

每个脚本跑完更新 `manifest.json`，下一步前检查 status（不 ok 先修复；唯一例外是 transcribe 的 `no_speech`——那是分支信号不是故障）。

### 3.1 无口播分支（画面文案提取）

适用：纯 BGM 无人声、文案烧录在画面上的视频（含整条无音轨）。判定链是客观信号而非猜测：无音轨（ffprobe 预检）或 ASR 正常完成但零文本（`transcribe.py` 输出 `no_speech`）为主信号，overview 拼版目测确认文字卡形态后正式切换；粗筛若发现画面其实是说话头/采访（ASR 漏检嫌疑），如实报告不硬切。有口播但用户点名「提取画面文案」也走本分支，成稿与 transcript 对照。

提取层四步（先粗后精）：粗筛拼版 → `screen_segments.py` 把帧差事件/静止期合成逐屏区间（换屏=事件、停留=静止期，时间轴为帧差实测）→ 逐屏定帧精读 → 模型成稿 `transcript.screen.srt/.json`。精读双引擎：多模态模型读图为主路线（`grab_frames.py` 每屏一帧，读不清 crop+zoom 放大）；无读图能力时回退 `screen_ocr.py`（PADDLEOCR_ACCESS_TOKEN 接官方托管 API——纯标准库 urllib 直连，或本地 paddleocr）。连续动画无静止期的视频自动落 uniform 均匀采样兜底，时间精度降为"约"。

## 5. 关键设计决策

1. **转写能力内置为托管 API 薄客户端**（0.3.0 起取代"发现 + 调用上游脚本"）：`asr_volc.py` 用纯标准库 urllib 直连火山 Seed ASR 录音文件识别 API（`submit` + `query` 轮询、`X-Api-Key` 认证、utterances 毫秒时间戳直接转 SRT），领域热词经 `request.corpus.context` 上下文纠偏传入。变更原因：上游 `video-to-subtitle-summary` 不随本仓分发，实际环境经常缺失，三级发现全部落空 → 转写链路整体不可用；"声明依赖 ≠ 可用"。薄客户端不复制上游脚本，行为契约（transcript.srt/.txt/.json、no_speech 判定、tmp 清理）保持不变，且与 `screen_ocr.py` 的托管 API 直连范式对齐。
2. **API Key 配置统一为 env > .env 双通道**：`_common.get_config()` 先读环境变量、再读 skill 目录 `.env`（模板 `.env.example`）；转写（`VOLC_BIGMODEL_API_KEY`）与 OCR 回退（`PADDLEOCR_ACCESS_TOKEN`）两个 Key 走同一逻辑，脚本与 doctor 一致。此前 ASR 侧依赖上游 skill 的 `.env`、OCR 侧只读环境变量，两套范式漂移。
3. **doctor 把"Key 未配置"降为 warn**：无口播分支、已有转写稿、L2 画面档都不需要转写 Key，缺 Key 不应让整份自检 exit 1 阻塞开工（0.2.0 的 missing 语义曾直接卡住 L1 流程）；warn 文案带控制台获取指引与弱可用范围说明，与 OCR 回退的 warn 先例一致。ffmpeg / ffprobe 等硬依赖仍为 missing。
4. **领域热词做成预设**：热词是转写准确率的决定因素（金融术语漏了热词必错）。`presets/hotwords/` 随技能分发，先判断领域再注入，判断不了用 `--domain none`。
5. **中间结果一律 JSON，不解析 ffmpeg 日志**：数字精确、可重复、可 diff、不烧上下文。
6. **抽帧即写时间戳**：每张拼版与字幕轨的每一格在 JSON 里记录精确秒数（取自 ffmpeg showinfo），从源头消灭"这张图是第几秒"的歧义。
7. **证据分档**：实测 / 约 / 推断三档，报告强制标注（`references/证据纪律.md`）。
8. **报告骨架固定**：结论速览 → 方法与口径 → 正文 → 分级问题清单 → 优化动作清单 → 证据索引（`references/输出模板.md`）。
9. **环境自检独立成脚本**：`doctor.py` 一次输出 JSON 判决，SKILL.md 只需一句"先跑 doctor，缺失项按提示补"。
10. **路径跨平台**：产物统一进 `<workdir>/video-insight/<slug>/`，可用 `--output-dir` 覆盖；不假设 `/tmp`。
11. **链接支持矩阵以实测为准**：B站（yt-dlp）为唯一支持平台；抖音 / 小红书 / 快手 / 视频号不支持，`fetch.py` 拒绝时返回原因与手动下载指引。恢复某平台的条件：可靠官方文档 + 真实链接实测通过。
12. **分析深度须用户确认（HIL）**：档位决定成本一个数量级（见 §2），未明确时提问，无用户可问时显式声明；禁止默选。
13. **无口播用客观信号判定，空产出不是故障**：无音轨（ffprobe 预检）或 ASR 正常完成但零文本 → `no_speech` 分支信号（manifest 状态与退出码 0）；API 调用失败（网络/鉴权/配额）仍是 fatal。极少量幻听文本只附 `suspect_no_speech` 提示。分支切换前必须拼版目测确认文字卡形态，防止 ASR 漏检被误判。
14. **画面文案时间轴由帧差事件驱动，不做均匀暴力采样**：文字卡视频的画面签名就是"静止期 + 换屏事件"（`detect_changes.py` 已有产物），`screen_segments.py` 纯 JSON 变换把它合成逐屏区间——每屏只读一帧，时间轴天然是实测档；连续动画无静止期才落 uniform 兜底（"约"档）。宁可多拆（打字机拆屏、同文合并交给模型读图后处理），不漏内容。
15. **OCR 只做回退，且优先在线 API 而非本地重依赖**：多模态读图是既定架构（脚本产证据、模型做理解）；无读图能力的 agent 才回退 OCR。`screen_ocr.py` 的 api 引擎用纯标准库 urllib 直连官方托管服务（星河社区免费 Access Token，`PADDLEOCR_ACCESS_TOKEN`），不破坏"零第三方依赖"；本地 paddleocr（经 uv 临时环境）仅作离线备选。doctor 对两者均做 warn 级探测（缺失不阻塞主流程）。

## 7. 触发设计

触发只走 `SKILL.md` 的 frontmatter `description`（该字符串是唯一来源），它必须同时写清三件事：

- **做什么**：两档模式各自的能力；
- **什么时候用**：分析 / 拆解 / 拉片 / 画面 / 音画 / 节奏 / 字幕等意图，包括"只问一条视频讲了什么"这类未明说"分析"的请求；
- **边界**：仅需转写字幕或浅摘要（不要结构化分析）不触发；生成素材不属于本技能。

边界写进 description 是为了与"只要转写/字幕"类需求划清触发范围。

## 8. 验证与回归

| 手段 | 内容 |
| --- | --- |
| 单测 | `python -m unittest discover -s tests`：102 条（解析函数与各脚本单元 + 合成视频全管线集成 + 无口播文字卡集成；真实托管 API 用例设 `VOLC_BIGMODEL_API_KEY` / `PADDLEOCR_ACCESS_TOKEN` 后才会执行，否则跳过） |
| 已知答案回归 | 2.mp4（33.3s / 720×1280 / 30fps）：帧差事件 0.37 / 1.93 / 2.97 / 4.57 / 9.87 / 12.10 / 14.80…、五处停顿、LUFS −16.0 / TP −1.4 / LRA 1.7、L1 173 字 / 5.2 字每秒；2.mp4 与 3.mp4 取色 #EE534C 家族 / #25A87D |
| 无口播回归 | 合成 3 屏文字卡（无音轨）：transcribe 输出 `no_speech/no_audio_track` 且 exit 0；帧差恰 2 个事件（≈2.0s/4.0s）；screen_segments 切 3 屏、边界 ±0.2s；OCR（有 Token 时）三屏全识别 |
| 归档校验 | 每次运行读 `manifest.json`：全部 status=ok、无 missing（transcribe 为 no_speech 亦合法） |
| 链接支持回归 | `fetch.py` 对 B站真实链接下载成功且可播放；对抖音 / 小红书 / 快手 / 视频号返回拒绝原因 |

改任一脚本或热词预设后，至少跑单测 + 受影响部分的已知答案回归。

## 9. 明确不做的事

- 不生成任何素材（图 / 视频）
- 不做视频下载（当前仅 B站 经 `fetch.py`，其余平台人工下载后用本地文件）
- 不内置 ASR 模型，也不做独立于分析的转写/字幕服务（内置的只是托管 API 薄客户端，作为分析链路的内部分步）
- 不做通用"图片转文字"服务（OCR 仅限无口播分支的画面文案回退）
- 不追求"分析得更多"，追求"结论可信、可回溯、可重复"
