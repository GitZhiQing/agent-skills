# video-insight · 设计规格

> 本文是 video-insight 技能的当前设计规格：定位、档位、流程、结构、决策理由、输出契约与验证方式。
> 行为约束见 `references/证据纪律.md`，画面方法见 `references/画面分析手册.md`，报告骨架见 `references/输出模板.md`；对外接口以 `SKILL.md` 为准。

## 1. 定位与边界

| 项 | 内容 |
| --- | --- |
| 做什么 | 把一条视频变成结构化洞察：内容结构、话术拆解、画面版式、节奏、音画对齐、问题清单 |
| 转写 | 内置火山引擎 Seed ASR 托管 API 客户端（`asr_volc.py`，纯标准库直连），配合领域热词预设；也可复用已有转写稿 |
| 不做什么 | 生成素材、剪辑、下载（仅 B站 经 `fetch.py`，其余平台人工）、独立于分析的转写/字幕服务、内置 ASR 模型（只内置托管 API 薄客户端） |

### 1.1 职责分层与判定规则

| 层 | 载体 | 职责 | 不做什么 |
| --- | --- | --- | --- |
| 工具层 | `scripts/*.py` | 机械采集、数据变换、能力开关（flags）、事实统计 | 不做判定、不放场景阈值、不内置「兜底策略」的触发逻辑 |
| 记忆层 | `memory/` | 判断类经验、数据形态识别、环境观察、平台行为 | 不存单视频内容结论、不存未验证猜测 |
| 文档层 | `SKILL.md` + `references/` | 机制说明、接口契约、恒定原则（确认门、证据纪律） | 不累积具体故障案例（案例全在记忆层） |

一条新经验该落到哪，按序自问：①环境兼容或数据管道缺陷、修复对所有输入普适 → **修代码**；②纯能力缺口（想做某事但没有接口）→ **加能力开关**；③判断类知识（症状→含义→动作）、不适合作硬编码 → **写记忆**；④单条视频的内容层观察 → **哪都不进**，留在该视频产物目录。检验口诀：改一行代码前问「这是能力扩展还是场景判断？」；写一条教训前问「这该毕业成代码吗？」。

## 2. 两档模式

| | L1 · 文案档 | L2 · 画面档 |
| --- | --- | --- |
| 输入 | 视频 / 音频 / 已有转写稿 | L1 全部 + 视频文件本身 |
| 手段 | 转写 → 校对 → 分段 → 结构分析 | L1 + 抽帧 / 帧差 / 定帧 / 放大 / 音频检测 / 取色 |
| 产出 | 01-转写校对、02-内容分析 | 追加 03-画面分析、04-音画对齐、05-问题与优化清单 |
| 适用 | 拆解选题 / 话术 / 结构；快速了解视频讲什么 | 判断"画面有没有接住口播"、排版缺陷、节奏拖沓、标注时机 |
| 成本（实测） | 40–130 万 token、6–10 分钟 | 330–480 万 token、约 30–40 分钟（实测 27–37；约为 L1 的 3–8 倍） |

**无口播形态**（纯 BGM 无人声、文案烧录画面，或无音轨）：画面是文案唯一来源，两档都必须先走 §3.1 画面文案提取。L1 = 提取 + 内容分析（成本预估 60–150 万 token，待实测回填）；L2 照常叠加，音画对齐变为「BGM 结构 × 文案屏切换」。

**升级到 L2 的触发**：用户提到 画面 / 拉片 / 排版 / 节奏 / 音画 / 承接 / 标注 / 字幕样式；或 L1 发现"文案本身没问题但效果不好"这类只有画面才能解释的现象。触发只是建议——带成本问用户，得到同意再跑。

**档位确认（HIL）**：先跑 doctor（只读）判环境，环境事实并入单轮确认门（环境一句话 + 理解 + 交付形态 + 档位推荐与理由），以等待用户回应结束。交互模式判定有操作定义（人类会话消息且未明说免问 → 必问；**禁止以「用户无法实时回答」为由跳过**）；合法回应只有确认 / 调整 / 显式委托（委托按推荐档执行并注明）。无人值守（子代理 / 批处理 / 明确免问）才走声明式执行。禁止默选。

## 3. 执行流程

```
输入识别（B站链接 / 本地视频 / 本地音频 / 已有转写稿）
        ↓
doctor 自检：ffmpeg · ffprobe · python · ASR Key · 磁盘 · 滤镜 · OCR 回退
        ↓
开工确认门（交互模式单轮：环境事实 + 理解 + 形态 + 档位推荐；无人值守 → declaration）
        ↓
════ pipeline.py 一键采集（幂等可重跑）════
fetch（仅 B站链接）→ probe → transcribe ── ok ──→ L1 材料就绪（stats 已算）
        │                                    ↑
        └─ no_speech（无音轨/ASR 零文本）       │
            ↓                                  │
        无口播分支直通：粗筛拼版(0.5fps) → 帧差 → screen_segments │
            → frames：每屏一帧抓取（待模型读图成稿）        │
            → ocr：screen_ocr + 组装器自动成稿 transcript.screen.* │
        （manifest 记 declaration.no_speech_switch）          │
        ────────────────────────────────────────────────────┘
        ↓ （--tier L2 追加：基础证据 extract_frames / detect_changes / audio_probe）
════ 以下是模型工作 ════
L1：术语校对 → 语义分段 → 口播数据(stats 引用) → 逻辑骨架 → 主张核查
    → 01-转写校对.md / 02-内容分析.md（无口播：b1 事后目检纠偏 → b4 读图成稿）
L2：【拼版检查点·交互模式】→ 定帧回查 / 局部放大 / 取色（模型定点单步调用）
    → 逐段「文案 × 画面」对照 → 版式解剖 → 音画对齐 → 分级问题清单
        ↓
产出 + manifest + 证据索引 + 交付后回路（升级 L2 / 存疑核查 / 质疑走 R4）
```

pipeline 收尾输出一份 JSON 报告（branch / steps / ready / stats / ai_next / notes），模型按 `ai_next` 指路进入分析段；`manifest.json` 仍是权威状态账本（pipeline 的每步子脚本各自记账）。**多视频**：同一命令给多个输入（或 `--batch` 清单文件）即批语义——每条走一遍上图（独立 `<批根>/<slug>/` 归档），失败隔离，收尾多一层批报告（§2.2）。

### 3.1 无口播分支（画面文案提取）

适用：纯 BGM 无人声、文案烧录在画面上的视频（含整条无音轨）。判定链是客观信号而非猜测：无音轨（ffprobe 预检）或 ASR 正常完成但零文本（`transcribe.py` 输出 `no_speech`）为主信号，pipeline 据此直通切分支（declaration 记 `no_speech_switch`），模型事后读 overview 拼版抽查纠偏；粗筛若发现画面其实是说话头/采访（ASR 漏检嫌疑），如实报告不硬切。有口播但用户点名「提取画面文案」也走本分支，成稿与 transcript 对照。

提取层四步（先粗后精，b1~b3 由 pipeline 自动串接）：粗筛拼版（0.5fps）→ `screen_segments.py` 把帧差事件/静止期合成逐屏区间（换屏=事件、停留=静止期，时间轴为帧差实测）→ 逐屏定帧精读 → 成稿 `transcript.screen.srt/.json`。精读双引擎：多模态模型读图为主路线（`--screen-mode frames`：pipeline 按 grab_at 自动抓每屏一帧，读不清模型再 crop+zoom 放大）；无读图能力时回退 `--screen-mode ocr`：`screen_ocr.py`（PADDLEOCR_ACCESS_TOKEN 接官方托管 API——纯标准库 urllib 直连，或本地 paddleocr）+ pipeline 内置组装器自动成稿（同文屏合并、置信度三档）。连续动画无静止期的视频自动落 uniform 均匀采样兜底，时间精度降为"约"。

采集后的矛盾决策：分段统计事实（summary 的 n_events / n_stills / n_screens / mean_screen_s 等计数字段，pipeline 原样透传进报告 stats）与拼版目检屏数矛盾时，模型决策重分段——连续画面吃掉静止期（典型：stills 为 0 且事件密集）→ `--mode uniform`；锚点超限被拒（`--mode event` exit 2 报计数，不静默降级）→ 调 `--min-screen-gap` 或升 `--max-screens`；uniform 段的 `events_in_segment` 事件锚点是补抓候选，配合 `grab_frames --range T1:T2 --step S` 等步扫窗定点补齐被采样跳过的短屏。成稿分工：frames 路径模型只写 `transcript.screen.json`，SRT 由 `screen_srt.py` 机械渲染（与 OCR 组装稿同 schema，两路可互渲染）。

### 3.2 记忆闭环

判断类经验的流动回路：doctor 后按平台/输入形态检索 `memory/INDEX.md` 与 `lessons/*.json`，命中条目并入确认门环境事实句 → 任一步骤失败先拿报错签名 grep trigger（命中按 action 行动，未命中才从头诊断——硬顺序）→ 数据形态异常（统计反直觉、机械结论与目检矛盾）按形态关键词检索 → 收尾三问（有无环境坑 / 数据形态新知 / 流程摩擦）有则写回新条目 → `used ≥ 3` 或 action 多次验证稳定即毕业（env_quirk 修代码、data_pattern 进证据纪律一行、workflow 并进 SKILL.md 步骤，条目标 graduated）。单条一个文件便于 grep 与 git diff；entry schema 见 `memory/INDEX.md` 头注与设计决策 23。

## 5. 关键设计决策

1. **转写能力内置为托管 API 薄客户端**：`asr_volc.py` 用纯标准库 urllib 直连火山 Seed ASR 录音文件识别 API（`submit` + `query` 轮询、`X-Api-Key` 认证、utterances 毫秒时间戳直接转 SRT），领域热词经 `request.corpus.context` 上下文纠偏传入。薄客户端不依赖上游 skill，行为契约（transcript.srt/.txt/.json、no_speech 判定、tmp 清理）保持不变，且与 `screen_ocr.py` 的托管 API 直连范式对齐。
2. **API Key 配置统一为 env > .env 双通道**：`_common.get_config()` 先读环境变量、再读 skill 目录 `.env`（模板 `.env.example`）；转写（`VOLC_BIGMODEL_API_KEY`）与 OCR 回退（`PADDLEOCR_ACCESS_TOKEN`）两个 Key 走同一逻辑，脚本与 doctor 一致。
3. **doctor 把"Key 未配置"降为 warn**：无口播分支、已有转写稿、L2 画面档都不需要转写 Key，缺 Key 不应让整份自检 exit 1 阻塞开工；warn 文案带控制台获取指引与弱可用范围说明，与 OCR 回退的 warn 先例一致。ffmpeg / ffprobe 等硬依赖仍为 missing。
4. **领域热词做成预设**：热词是转写准确率的决定因素（金融术语漏了热词必错）。`presets/hotwords/` 随技能分发，先判断领域再注入，判断不了用 `--domain none`。
5. **中间结果一律 JSON，不解析 ffmpeg 日志**：数字精确、可重复、可 diff、不烧上下文。
6. **抽帧即写时间戳**：每张拼版与字幕轨的每一格在 JSON 里记录精确秒数（取自 ffmpeg showinfo），从源头消灭"这张图是第几秒"的歧义。
7. **证据分档**：实测 / 约 / 推断三档，报告强制标注（`references/证据纪律.md`）。
8. **报告骨架固定**：结论速览 → 方法与口径 → 正文 → 分级问题清单 → 优化动作清单 → 证据索引（`references/输出模板.md`）。
9. **环境自检独立成脚本**：`doctor.py` 一次输出 JSON 判决，SKILL.md 只需一句"先跑 doctor，缺失项按提示补"。
10. **路径跨平台**：产物统一进 `<workdir>/video-insight/<slug>/`，可用 `--output-dir` 覆盖；不假设 `/tmp`。
11. **链接支持矩阵以实测为准**：B站（yt-dlp）为唯一支持平台；抖音 / 小红书 / 快手 / 视频号不支持，`fetch.py` 拒绝时返回原因与手动下载指引。恢复某平台的条件：可靠官方文档 + 真实链接实测通过。
12. **分析深度须用户确认（HIL）**：档位决定成本一个数量级（见 §2），未明确时提问，无用户可问时显式声明；禁止默选。
13. **无口播用客观信号判定，空产出不是故障**：无音轨（ffprobe 预检）或 ASR 正常完成但零文本 → `no_speech` 分支信号（manifest 状态与退出码 0）；API 调用失败（网络/鉴权/配额）仍是 fatal。极少量幻听文本只附 `suspect_no_speech` 提示。分支切换后由 b1 拼版目检确认文字卡形态，防止 ASR 漏检被误判。
14. **画面文案时间轴由帧差事件驱动，不做均匀暴力采样**：文字卡视频的画面签名就是"静止期 + 换屏事件"（`detect_changes.py` 已有产物），`screen_segments.py` 纯 JSON 变换把它合成逐屏区间——每屏只读一帧，时间轴天然是实测档；连续动画无静止期才落 uniform 兜底（"约"档）。宁可多拆（打字机拆屏、同文合并交给模型读图后处理），不漏内容。
15. **OCR 只做回退，且优先在线 API 而非本地重依赖**：多模态读图是既定架构（脚本产证据、模型做理解）；无读图能力的 agent 才回退 OCR。`screen_ocr.py` 的 api 引擎用纯标准库 urllib 直连官方托管服务（星河社区免费 Access Token，`PADDLEOCR_ACCESS_TOKEN`），不破坏"零第三方依赖"；本地 paddleocr（经 uv 临时环境）仅作离线备选。doctor 对两者均做 warn 级探测（缺失不阻塞主流程）。
16. **交互模式分级判定**：「无用户可问」有操作定义——人类会话消息且未明说免问 → 交互模式必问；子代理 / 批处理 / 明确免问 → 无人值守声明式执行；判定不明按交互处理。交互会话**禁止以「用户无法实时回答」为由跳过提问**。范式对齐 deep-research 的强制确认门（确认 / 调整 / 显式委托三回应，无默认执行路径）；差异点：video-insight 保留无人值守声明路径（常被 agent 链式调用，完全阻塞会断该用法），deep-research 选择阻塞。
17. **doctor 前置并入确认门**：确认门从「先于一切命令」改为「doctor 之后、分析命令之前」——环境事实（Key 有无、ffmpeg 可用）进确认门，选项自带可行性标注；缺 Key 时引导配置（粘贴 → 写 .env → 复检）成为标准动作。
18. **b0 无口播门改为「告知即走，矛盾才停」**：客观证据（无音轨 / ASR 零文本）无替代路径（文案只能来自画面），问许可是过度门禁——告知 + declaration 记录后继续；矛盾证据（粗筛显示说话头嫌疑 / `suspect_no_speech`）才硬停等用户定夺。
19. **L2 拼版检查点**：L2 全程 30–40 分钟，跑偏要等交付才发现；在定帧 / 放大 / 取色等重投入步骤前设一次检查点（拼版 + 事件表摘要 + 精读节点清单），确认方向再继续。用户可显式跳过（manifest 记 `skipped_checkpoint`），无人值守自动跳过并声明；只此一处，不演化成多轮汇报。范式对应 deep-research 高档的「大纲确认 → 分节汇报」。
20. **机械采集段整体下沉为 pipeline.py**：`pipeline.py` 以 subprocess 复用全部既有脚本（不重复实现采集逻辑），按 manifest 状态幂等推进，自动消费 `no_speech` 分支信号直通无口播链（ocr 路径连 b4 成稿也由内置组装器完成），收尾输出 branch/stats/ai_next/notes 报告。**边界**：HITL 门（确认门 / 告知门 / 检查点）、读图成稿（frames 路径 b4）、L1/L2 内容分析、定帧时刻与取色区域等视觉决策仍归模型；pipeline 属分析命令，确认门前禁止调用。**代价权衡**：b1 目检安排在采集后抽查（而非切换前目测）——异常场景（ASR 漏检的说话头）下 b2/b3 采集成本白花，但远低于常态下省掉的模型编排轮次，且矛盾证据仍硬停。
21. **批量化：一条命令覆盖多视频**：pipeline 支持多输入（位置参数或 `--batch` 清单文件，本地文件 / B站链接 / 转写稿混排）：每条独立归档 `<批根>/<slug>/`（批内同名 slug 加 `-2` 后缀），**失败隔离**（单条失败不阻塞其余，批报告列明，重跑同命令幂等只补失败条目），收尾输出批级汇总报告（每条 branch/stats/ready 一屏总览）并落盘 `batch-report.json`。**批级确认门语义**：批内同档一次确认（成本 = 单条 × N），不逐条问——预算决策在批级做一次即可，逐条确认是假勤奋；拆档/领域混杂用「分次跑子集」表达而非 per-item 参数（CLI 保持简单，幂等保证分次跑不重复采集）。**并发取舍**：`--jobs N` 可选、默认 1 串行——转写是轮询等待型，并发显著缩墙钟时间，但默认值对 ASR 配额友好；并发为纯 subprocess 无共享状态（manifest 各自独立），线程池即可。**产物分层**：跨视频对比文档落批根（批级），不塞单视频 OUT——单视频产物可整体复用/拷走，批级汇总按批丢弃。
22. **函数 = 能力，不是策略**：脚本层只做机械采集与数据变换，把「能做什么」以正交、可组合的开关暴露；「何时用、用哪个」归模型。专项启发式（魔法阈值自动降级、按背景形态的专用检测分支）一律不进代码——那是对单次经验的过拟合，换一类输入就是误伤源。`screen_segments --mode {auto,event,uniform}`（默认 auto）把 uniform 作为正面入口，而不是簇数超限时的降级副作用；event 模式锚点超限 exit 2 报计数（拒绝静默降级也不静默截断）；summary 补统计事实字段（n_events / n_stills / mean_screen_s / max_screen_s / longest_still_s）只报数不判定；`grab_frames --range T1:T2 --step S` 等步扫窗（--at 的自动展开）；pipeline `--include-event-anchors`（默认关）把 events_in_segment 事件锚点按 max_screens 预算并入 grab 列表、计数进 stats。
23. **记忆层：经验靠闭环流动，不靠文档堆叠**：判断类经验（症状→含义→动作）不硬编码也不堆 SKILL.md——写进 `memory/lessons/NNN-slug.json`（单条一个文件，便于 grep 与 git diff），`memory/INDEX.md` 一行一条做检索入口；随技能仓库 git 追踪跨机共享，含本机路径的条目标 `scope: machine`。写回三钩子：修复失败步骤之后、统计与目检矛盾靠手工补齐之后、收尾三问（环境坑 / 数据形态新知 / 流程摩擦）。检索三入口：doctor 后并入确认门环境事实句；任一步骤失败先 grep trigger 再诊断（硬顺序）；数据形态异常按形态关键词检索。反规范：单视频内容结论、未验证猜测、用户隐私不写回。毕业机制：`used ≥ 3` 或 action 多次验证稳定 → env_quirk 修代码 / data_pattern 收敛成纪律进证据纪律一行 / workflow 并进 SKILL.md 对应步骤，条目标 graduated 并指向去处——记忆有出有进，文档层只增原则不增案例。
24. **SRT 渲染下沉为 screen_srt.py**：frames 路径 b4 成稿只写 `transcript.screen.json`，SRT 由脚本机械渲染（与 OCR 组装器同一 schema，两条路径的成稿可互渲染）。机械渲染属数据管道，无任何判断。
25. **分段统计事实原样透传**：pipeline 把 screen_segments summary 的计数字段原样放进报告 stats，不加「suspect_segmentation」之类的判定性 notes——判定性提示会诱导模型跳过独立思考（看见是工具的事，决策是模型的事）；配套 ai_next 只加一条对任何异常统计都成立的机械性工具指引（统计与目检矛盾 → 重分段 → 锚点补抓）。
26. **数字类断言 crop+zoom 复核（证据纪律 R9）**：价格/编号/型号类数字整屏读图误读率高（0/6、1/7、缺角标），落笔前必须放大复核一次。通用部分进证据纪律一行；单视频的版式坐标常量不进任何层（预设坐标是对单视频版式的过拟合）。

## 7. 触发设计

触发只走 `SKILL.md` 的 frontmatter `description`（该字符串是唯一来源），它必须同时写清三件事：

- **做什么**：两档模式各自的能力；
- **什么时候用**：分析 / 拆解 / 拉片 / 画面 / 音画 / 节奏 / 字幕等意图，包括"只问一条视频讲了什么"这类未明说"分析"的请求；
- **边界**：仅需转写字幕或浅摘要（不要结构化分析）不触发；生成素材不属于本技能。

边界写进 description 是为了与"只要转写/字幕"类需求划清触发范围。

## 9. 明确不做的事

- 不生成任何素材（图 / 视频）
- 不做视频下载（当前仅 B站 经 `fetch.py`，其余平台人工下载后用本地文件）
- 不内置 ASR 模型，也不做独立于分析的转写/字幕服务（内置的只是托管 API 薄客户端，作为分析链路的内部分步）
- 不做通用"图片转文字"服务（OCR 仅限无口播分支的画面文案回退）
- 不做分段自动降级启发式（「簇数/事件比 ≤ 魔法阈值就自动切 uniform」之类）——场景判断硬编码会误伤真一屏长图类视频；改由统计事实可见性 + 模型决策替代
- 不做按背景形态的专用检测分支（如「动态背景检测」）——uniform 本来就是通用兜底，缺的只是正面入口与事件锚点数据，不需要按背景形态分类讨论
- 不入库单视频版式坐标常量（如价格条裁剪预设）——通用的「数字断言先放大复核」进证据纪律 R9，坐标本身不进任何层
- 不把单视频内容观察机制化（福利时间轴截断、系列卡不齐等）——写进该视频的 02-内容分析.md 即终结，不进 memory 也不进文档
- SKILL.md 不累积具体故障案例——案例只进 `memory/lessons/` 与 commit message，文档层只增原则不增案例
- 不追求"分析得更多"，追求"结论可信、可回溯、可重复"
