# find-my-xp 需求与设计文档

文档版本：v0.5.0
日期：2026-11-19
实现版本：0.5.0

## 1. 问题与目标

帮用户看清自己真正被什么打动（XP / 心仪类型 / 性癖）、以及为什么。痛点：口头理想型预测不了真实心动（Eastwick & Finkel 2008；Joel 2017），固定题库测试得到社会期望答案，玄学许愿与市场评估都不解决"自我认识"。

目标：证据驱动的深度访谈，产出**适度标签化 + 血肉细节 + 深层解读**的画像；尊重 XP 的 plural（一个人并存几套吸引模式），不压成单一类型；防脸谱化、防美化、可证伪、非评判、非诊断。

非目标：配对兼容性分析、心理治疗/诊断、固定题库娱乐测试、市场可行性评估、违法内容。

## 2. 方案

纯提示词核心 + 可选 HTML 渲染脚本（仓库 PEP 723 先例）。

- 访谈引擎：标本先行（ZMET）→ 三元对比提双极建构（rep grid）→ 阶梯下钻（laddering）→ 强制取舍 → 反差探针（瓦解条件/相反标本）→ 性脚本与情感基调（lovemap）→ 可选深挖（四成分）→ 聚类成原型 + 回映验证。
- 纪律：一次一问、2:1 反映比、模糊熔断、矛盾不静默消解、防美化、跳过权、证据优先。
- 交付：1 元地图 + N 原型档案（2-4），各含三层 + 层间错位 + 激活情境 + XP 链 + 雷区 + 角色卡；可选私密档案风 HTML。
- 安全硬骨架：成人 gate、硬拒绝、危机协议、隐私本地（`references/safety.md`）。

## 3. 关键决策

- **D1 · 成人向完整 XP 版**（用户拍板）：默认含性吸引/性癖维度，开场成人确认；合法成人癖好正常探索，未成年/非自愿/违法硬拒绝。安全是硬骨架不是附录。
- **D2 · 多轨自述**（用户拍板）：不预设异性恋；他/她/ta/不限/自述，纸片人合法，代词跟随。
- **D3 · 标准深度**（用户拍板）：约 20-30 问 / 30-45 分钟，含可选深挖，可中断续访（日志 resume-first）。
- **D4 · 多份结果的组合轴**（用户拍板）：并存原型为主交付单位；吸引层面为每个原型内部纵深（表面/互动/内核 + 层间错位）；情境/阶段为激活标签 + 元地图切换图。避免"原型×层面×情境"文件爆炸，交付 N+1 份。
- **D5 · 老练松弛同行者**（用户拍板）：见多识广、不扭捏不大惊小怪，证据面前温和而坚定，不评判不说教。
- **D6 · Markdown + 可选 HTML**（用户拍板）：私密档案风（暗色暖灰 + 黄铜 + 衬线标题 + 等宽标签）；PEP 723 仅 markdown-it-py；uv 缺失降级；默认不自动渲染（尊重私密），用户要才渲染。
- **D7 · 纯提示词核心**：访谈与合成全由提示词承担；渲染脚本只做确定性 Markdown→HTML，不进入上下文。
- **D8 · 词表只作备用探针**：标签从用户标本原话长出；词表仅卡住时给选项 + 归一化参考，不当评分量表。
- **D9 · 方法论取舍**：借 lovemap 描述性三层、rep grid、ZMET、laddering、四成分；**不借** Money 病理化框架与创伤决定论（其理论与本人有重大争议）。
- **D10 · 防脸谱化**：三层标签反差 + 瓦解条件（XP 是标签瓦解的方式）+ 可验证行为细节 + 矛盾面 + 不完美变体。
- **D11 · 诚实性**：防美化（至少一条不光彩动机）、矛盾保留、回映验证、置信度标注、可证伪；报告是假设地图不是预测引擎。
- **D12 · category: psychology**：新增领域标签（现有 web/git/research/workflow/media/document/system 均不贴合），已按规范 §3 先更新 CONVENTIONS 值集再使用。
- **D13 · 描写语料来自人类创作文本**（0.2.0，用户指出模型自写描写有 AI 味）：具体描写（外貌/语言/行为/语气示例）从人类文本提取（游戏角色档案/个性语音/喜好/心声、网文、人类角色卡）+署名，模型只选择/匹配/编排不发明；"有人在场"检验 + 反 AI 味清单约束模型连接文字；voice-consistency（语气示例须该角色真实语音）；版权纪律（运行时短引用+署名，不打包受版权语料进仓库，仓库仅公版示例）；无来源降级公版借喻/留空不发明。依据：AI 味=概率分布抹平的平均数、"人做树干 AI 做枝叶"（阿里云/36Kr/腾讯云去 AI 味研究）；游戏 wiki 价值在故事/语音/签名/喜好而非数值（库街区/HoYoWiki/米游社/萌娘百科/百度百科实测）。
- **D14 · 四介质角色档案库**（0.3.0，用户要求沉淀网文/日漫/虚拟歌手/RPG 高人气角色的原始描写+社区评价成档案库帮 AI 认知）：新增 corpus-novel/anime/virtual/game 四卷（约 80 条目），每条=短引用（适当引用）+精确署名+来源指针+分析标签（外在/内在反差/XP 标签）；版权纪律 refined 为"仓库档案库只收短引用+分析为主，不整篇搬运"（D13 的"仅公版"放宽为"公版可稍长+受版权仅短引用"）；档案库定位=认知辅助/反差原型索引，非固定题库，匹配用户建构才引用、借喻须标注；虚拟卷提炼两类机制（空白容器共创 / 官方人设 vs 中之人真实）。来源：原著转引/官方档案语音/萌娘百科/社区（NGA/豆瓣/贴吧/知乎/PTT/bilibili）。
- **D15 · 来源质量分级 + 原文确认 + RPG 扩覆盖 + 深度赏析**（0.4.0，用户不满百家号等自媒体、要求萌百/NGA/官方wiki/论坛、网文确认原文、RPG 覆盖全人气角色、参考深度赏析）：corpus-sourcing 增来源四级优先序（官方档案语音 > 百科wiki > 论坛深析 > 媒体自媒体-避免百家号/头条/搜狐/快资讯）+ 原文确认规则（百科引原著带参考编号/赏析直引，标"原文"；二手标"转述/待补"）+ §10 深度赏析来源表（知乎江南十二钗/贴吧/NGA/豆瓣/bilibili专栏/赤坂访谈/江南随笔/PTT）；重写四卷：网文换百科引原著+知乎直引原文（薰儿清莲初绽/云韵素衣雍容/千仞雪金色宫装/夏弥婴儿肥虎牙/绘梨衣巫女服+占有欲标签），RPG 扩至约 60 条目（新增八重神子/朱鸢/青衣/月城柳/耀嘉音/凯撒/赛琳娜/薇拉/卡列尼娜/崩3御三家/原神崩铁鸣潮蔚蓝NIKKE roster），未检索到原文者标"外在待补"+官方/萌百指针不模型仿写；日漫换论坛/官方/萌百+bilibili深析锐评。ddgs(bing+代理)与ds双通道调研。
- **D16 · 设计审查修复①-⑨**（0.5.0，自审"精巧/完整/稳定/有趣"后用户批准+补充"用户会主动说喜欢某角色"）：①熔断≤2次/矛盾每轮≤1优先核心+逃逸记日志；②档案库与elicitation硬隔离（采集期不读不报角色名），**用户主动报角色=合法标本**（记出处+追问用户戳点，档案语料仍合成期取）；③吸引类型分离(性/浪漫/审美/感官,无性恋包容)+性脚本可整段跳过；④线性9阶段→固定骨架+5可循环move(标本/对比/下钻/取舍/反差;性脚本/深挖可选)+自适应pacing；⑤报告核心节+可选节瘦身、空节删除不填充；⑥取舍游戏化(淘汰赛/盲测)+幽默许可+metaphor probe+可选趣味收尾；⑦续访POINTER块+目录即session；⑧fast-path(直接给材料跳move池);⑨信念计数五条/语料徽章嵌套括号/空输入无h1测试。minor（行为协议变化）。

- SillyTavern 角色卡导出未做（用户未选）；角色卡速写为通用 Markdown 段落，留作扩展。
