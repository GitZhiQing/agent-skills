## 1. 为什么不用模型自写描写

- AI 味来自概率分布被抹平：模型选"最安全、最中庸、最不出错"的表达，结果是平均数，读完脑子里什么都不留。
- **有人在场就是人味，没有人在场就是 AI 味。** 人类写的句子里站着一个做事/说话的人（"不推荐，最近总是卖光缺货我都买不到了!!!"）；AI 句子里找不到主语（"为用户提供了更好的体验"）。
- 人味 = 具体细节、意料之外的妥帖比喻、新奇搭配、毛边、不整齐、偏颇、真实生命痕迹。这些模型模仿不了"我真的在这里活过"。
- 结论（人机分工）：**人做树干，AI 做枝叶。** 描写语料（树干）来自人类创作文本；模型（枝叶）只做选择、匹配到用户建构、编排与解读。让模型自写外貌/语气 = 用枝叶冒充树干，必露 AI 味。

## 2. 来源目录

运行时按需用 web 工具检索/抓取，或读用户提供的文本。**只取有价值 section，跳过数值噪声。**

**来源质量分级（优先序）**：
1. **官方档案/语音/设定**（游戏官方 wiki/图鉴/PV/角色故事/个性语音；作者随笔/访谈）——最权威，直引。
2. **百科/wiki**（萌娘百科、百度百科、维基百科、HoYoWiki、米游社、库街区、PRTS）——相貌/性格/萌点/语录节常引原著，标"百科引原著"。
3. **论坛/社区深析**（NGA、贴吧、豆瓣、知乎、PTT、KDays、bilibili 专栏/视频锐评）——深度角色赏析与社区共识，直引其锐评/原文直引段。
4. **媒体/自媒体**——仅当无以上来源时谨慎转引并标"转引"；**避免百家号/头条/搜狐/快资讯等低质自媒体**作为描写来源。

**原文确认规则**：网文/原作描写优先取"百科引原著（带参考文献编号）"或"深度赏析直引原文段落"，署名标"原文（百科引原著）"/"原文（赏析直引）"并给作品+章节指针；仅二手转述者标"原文转述/待补"，不冒充直引。

## 3. 提取规则

- **短引用 + 署名**：每条引用标 `（语料：作品·角色·条目）`，如 `（语料：鸣潮·莉莉·角色语音）`。署名到条目级，可回溯。
- **voice-consistency**：角色卡语气示例必须出自**该角色**的真实语音或同作品同角色第一人称文本；不跨角色拼凑、不模型仿写"像 TA 会说的话"。
- **具体细节优先**：选 quirky 的具体细节，不选抽象形容词。例：莉莉"我的颜料是看不见的，只能靠嗅觉去捕捉与权衡"、卡芙卡"爱好是购买及整理大衣"、莉莉发间百合"仅有五片花瓣"（发育异常/外力破坏的暗示）。这些是 human idiosyncrasy，AI 编不出。
- **保留毛边**：保留原文省略号、口语、不整齐、偏颇；不"润色"成平滑 AI 腔。
- **匹配用户建构**：每条语料标注它锚定用户哪个标签/双极建构/原型；语料服务于用户的 XP，不是堆砌素材。
- **外形用清单不用概括**：取"紫粉色眼眸 / 及腰粉紫长发扎麻花辫 / 黑色宽大头纱带蕾丝 / 百合花环 / 铆钉项圈"这类可验证元素，不取"温柔美丽的少女"。

## 4. 版权纪律

- 运行时**短引用 + 署名**、个人自我探索使用；单条短句/短段，不整篇搬运。
- **仓库内档案库（§9）只收短引用**：每条仅短句/短语（适当引用，用于介绍/评论/说明）+ 精确署名 + 来源指针 + 分析标签；分析为主、引用为辅，不整篇搬运、不构成对原作的替代。公版示例（§6）可稍长。
- 本文件 §7 的莉莉引文为**适当引用示例**（说明提取格式，短句、署名），非语料库。
- 用户提供的私有文本（自己写的/已购小说摘录）仅本地使用，不外传。

## 5. 反 AI 味清单（模型连接/解读文字）

内核层解读、元地图关系等**模型必须自写**的连接文字，过以下清单（负面约束比正面指令有效）：

- **有人在场检验**：每句能找出"谁在做/谁说"。找不出主语的句子重写。
- **禁用词/句式**：首先其次最后 / 综上所述 / 总而言之 / 值得注意的是 / 不难发现 / 本质上 / 换句话说 / 赋能 / 深度剖析 / 旨在提升 / 不可或缺 / 双刃剑 / 仿佛 / 宛如 / 映入眼帘 / 心中暗道 / 不由得 / 稳稳地接住 / 情绪价值。
- **禁用套路**：否定式煽情（"这不是X而是Y"连用）、虚假范围（"从X到Y"硬凑）、过度拔高（平凡事说成分水岭）、排比三连、对称结构、总—分—总、每段均匀 3-4 行、句长被尺子量过。
- **具体替代抽象、行动替代状态**：不写"气氛紧张"，写紧张的具体动作/声音；不写"内心挣扎"，写挣扎的行为。
- **保留不整齐**：允许口语、转折、插入语、局部不完整、长短句交错、一句话独立成段；保留真实的不确定（"这条我没把握"）。
- 解读可以平滑（它是分析），但**描写必须 sourced**（它是语料）。两者不混。

## 6. 公版示例库（离线兜底）

无 web 工具且用户未提供文本时，用公版（作者逝世逾百年、无版权）人类描写作**craft 示例 / 借喻**，并明确标注"公版示例借喻，非用户标本原话"。不模型发明。

外貌 / 神态（红楼梦·第三回）：

- 王熙凤："一双丹凤三角眼，两弯柳叶吊梢眉。身量苗条，体格风骚。粉面含春威不露，丹唇未启笑先闻。"（语料：红楼梦·王熙凤·出场）
- 林黛玉："两弯似蹙非蹙罥烟眉，一双似喜非喜含情目。态生两靥之愁，娇袭一身之病。泪光点点，娇喘微微。闲静时如姣花照水，行动处似弱柳扶风。"（语料：红楼梦·林黛玉·出场）

语言 / voice（未见其人先闻其声）：

- 王熙凤："我来迟了，不曾迎接远客！"（语料：红楼梦·王熙凤·出场）

外貌 / 体格（水浒传·鲁达）：

- "生得面圆耳大，鼻直口方，腮边一部貉臊胡须。身长八尺，腰阔十围。"（语料：水浒传·鲁达·出场）

**用法**：这些示"具体清单 + 矛盾面 + 声音先行"的 craft（威不露/笑先闻 = 表里反差；似蹙非蹙 = 不整齐毛边），供模型理解何为人类描写；借喻到用户原型时标注借喻，不冒充用户标本。

## 7. worked example：莉莉

以用户举例的鸣潮·莉莉示提取格式（引文为适当引用示例，署名到条目）：

- **外形**（sourced 清单，锚定"清冷/易碎/治愈"建构）：
  > 紫粉色眼眸，及腰粉紫长发扎麻花辫；黑色宽大头纱带蕾丝纹理；百合花环点缀发丝；黑色铆钉项圈；黑白拼接露肩连衣裙。
  > （语料：鸣潮·莉莉·角色外形）
- **语气示例**（sourced 第一人称，voice-consistent）：
  > "这个味道，嗯……希望这次，是个好梦。"
  > （语料：鸣潮·莉莉·角色语音）
  > "在调香台前，面对数以百计的精油瓶，有时我觉得自己像极了面对调色盘的画家——只不过我的颜料是看不见的，只能靠嗅觉去捕捉与权衡。"
  > （语料：鸣潮·莉莉·喜好）
- **内核线索**（sourced 心声，供四成分分析）：
  > "星星落地变成了我触手可及的人，我不用再抬头，不用再流着眼泪思念。"
  > （语料：鸣潮·莉莉·心声）
- **trivia 毛边**（human idiosyncrasy，锚定"易碎/短暂"）：发间百合仅五片花瓣（正常六片，五片暗示发育异常/外力破坏）；玩家外号"忧郁小葡萄"。（语料：鸣潮·莉莉·角色相关）

注意：外形是清单不是概括；语气是莉莉自己说的话不是仿写；trivia 是社区观察不是模型编造。模型的工作是把它们匹配到用户的建构，而非重写。

## 8. 降级规则

- 有 web 工具 → 运行时检索/抓取来源（§2），短引用+署名。
- 无 web 但用户提供文本（小说摘录/角色卡/截图转写）→ 从用户文本提取+署名"用户提供"。
- 两者皆无 → 先查**角色档案库（§9）**取已沉淀的短引用+分析；仍无匹配 → 公版示例借喻（§6，明确标注）或留空标"待补人类语料"。**不模型发明描写。**
- 渲染/检索失败不阻塞访谈与 Markdown 交付；描写缺口如实标注。
