# zero-coding

从零启动一个个人项目并维持稳定开发工作流：让想法自由落地 → 固化为范围契约 → 搭可运行骨架 → 进入稳定迭代。核心信念是 agent 能力越强，过多的文档越是束缚——只维护代码与 git 历史推导不出的信息。

## 何时触发

- 用户带着新想法从空目录开始（"我想做个……"）、需要固化需求、搭建项目骨架，或想防止文档膨胀；
- 不触发：项目已有成熟的文档体系与开发规范，或用户只是临时求助并不打算立项。

## 工作方式（四阶段 + 收尾）

| 阶段 | 做什么 | 完成标志 |
| --- | --- | --- |
| 0 捕获 | 想法原话追加进 docs/ZERO.md（灵感本，格式零约束）；首次进入工作流时以 3~5 句开局说明交代全程与两道硬门槛 | 用户明确"开始规划" |
| 1 固化 | 设计树结构化访谈：逐轮问完整条前沿，事实自己查、决策留给用户 | SPEC 草案获用户确认 |
| 2 骨架 | 可运行空壳 + AGENTS.md（每条命令须真实执行过）+ 最小 README + DECISIONS | AGENTS.md 命令全部验证 |
| 3 稳定开发 | 按 SPEC 顺序实现 → 测试绿 → 提交；不可逆选型当场记 DECISIONS | MVP 交付 |
| 收尾 | SPEC 收缩为一节并入 README 后删除；README 完善至"一屏"标准 | — |

## 最小文档集（5 个，不增不减）

| 文件 | 一句话定位 | 生命周期 |
| --- | --- | --- |
| docs/ZERO.md | 自由灵感本，格式零约束 | SPEC 确认后降级为档案 |
| docs/SPEC.md | 灵感的固化，范围契约 | MVP 交付后并入 README 并删除 |
| docs/DECISIONS.md | 轻量 ADR，只追加 | 永久 |
| AGENTS.md | 会话级上下文，保持克制 | 持续维护 |
| README.md | 给人看：是什么、怎么跑 | 收尾时完善 |

两条核心原则：

- **产物快照**：所有产物按"从一开始就是这样"书写，演进过程交给 git 与 DECISIONS；判据是**新读者测试**——一年后首次打开文件的人，读到的每个字仍须成立；
- **两道硬门槛**：SPEC 未获用户确认前不写任何产品代码；决策由用户拍板，agent 只推荐。
