# zero-coding 测试集

版本：v0.3.0（2026-09-13 新增 Z-11 开局说明断言，随 skill 0.2.0；v0.2.0 新增 Z-10 产物快照断言；v0.1.0 随 skill 首版创建）。行为协议断言，人工会话执行；
编号采用「类别前缀-序号」（前缀 Z），新场景追加不重排。

## 1. 工作流场景（Z）

### Z-1 新想法捕获（Phase 0）

场景：空目录会话中，用户口述一个新想法。

▶ 用户：“我想做个读书笔记自动整理工具”

- = 将用户原话追加进 docs/ZERO.md，空行分隔，不加格式包装、不改写措辞
- = 可围绕想法自由讨论，但不做技术判断
- = 除 ZERO.md 外不创建任何项目文件（不建 SPEC / 骨架代码）
- = 用户明确表示“开始规划”前，停留在 Phase 0

### Z-2 已有 ZERO.md 只读不整理

场景：用户已自行写好 docs/ZERO.md（内容可能矛盾、无格式）。

- = 通读理解，不整理、不重构、不修正、不总结该文件
- = 除非用户要求，不代为改写 ZERO.md
- = ZERO 与后续 SPEC 冲突时，以 SPEC 为准

### Z-3 结构化访谈按前沿推进（Phase 1）

场景：ZERO.md 存在且用户决定立项。

- = 把待定决策建模为设计树，每轮一次问完整条前沿
- = 每个问题带编号与推荐答案（❓ Qn + ➡️ 推荐），等回答再进下一轮
- = 能自行调研的事实（环境、工具、资料）不问用户，必要时派子 Agent；调研未返回只阻塞其下游，其余前沿照常进行
- = 决策留给用户：Agent 只推荐不拍板
- = 前沿为空才结束，没有任何决策被默默假设
- = 结束时把全部已定决策整理为 SPEC 草案（问题 / MVP 范围 / Non-goals 四节）交用户确认

### Z-4 SPEC 未确认不写产品代码

场景：Phase 1 进行中或 SPEC 草案尚未获用户明确确认。

- = 不写任何产品代码
- = 用户确认 SPEC 后才进入 Phase 2

### Z-5 骨架可运行（Phase 2）

场景：SPEC 已确认。

- = 初始化代码骨架至“可运行空壳”（hello-world 级）
- = AGENTS.md 中每条命令都真实执行过才写入，写完逐条验证
- = README 只写最小版（怎么跑）；本阶段全部选型逐条记入 DECISIONS.md（一行式）
- = 使用环境变量则创建 .env.example

### Z-6 文档纪律（Phase 3）

场景：稳定开发迭代中。

- = 不可逆选型拍板 → 当场追加 DECISIONS（Agent 起草、用户只确认理由）
- = 决策被推翻时追加新条目并注明“取代 Dn”，不删不改旧条目
- = 与生效决策冲突的改动先向用户提出，不擅自更改
- = Agent 犯重复错误才把纠正追加进 AGENTS.md，保持 <100 行
- = 范围变化 → 修订 SPEC；永久放弃同时追加一条 Decision
- = ZERO.md 降级为档案，不再影响开发决策；新想法走 SPEC 修订
- = 不新增文档集 5 个文件之外的持久文档（能从代码 + git 推导的不写）

### Z-7 收尾（MVP 交付）

场景：MVP 交付收尾。

- = SPEC 收缩为一节并入 README 后删除原文件
- = README 完善至“一屏”标准
- = ZERO.md 保留为历史档案（或按用户意愿删除）
- = DECISIONS 与 AGENTS 继续服役，进入下一个循环

### Z-8 冲突裁决

场景：开发中出现代码与文档、或文档间的不一致。

- = 代码与文档冲突 → 以 DECISIONS.md 为准，并提醒用户
- = 文档间冲突 → SPEC（范围）> DECISIONS（约束）> ZERO（仅历史）
- = 用户当面指示优先于一切文档

### Z-9 反向不触发

场景：用户在已有成熟文档体系与开发规范的项目里求助，或只是临时提问、并不打算立项。

▶ 用户（在既有项目内）：“帮我看下这个函数为什么慢”

- = 不启动 zero-coding 工作流，不创建 ZERO / SPEC 等文件，仅按提问作答

### Z-10 产物快照

场景：任一阶段产出代码、注释、文档或提交说明。

- = 产物按“从一开始就是这样”书写，通过新读者测试：未参与对话的人一年后首次打开，每个字仍成立
- = 注释只写非显然的 why，无复述代码、无“修复了 X”“改为 Y”“不再使用”等变更叙事
- = SPEC / README 用现在时描述现状；需求变更按“新需求从一开始就是这样”重写，不追加变更说明
- = 变更历史只出现在 commit message（what + why）与 DECISIONS，不在产物里留痕
- = 输出前扫描历史引用（之前 / 原来 / 已移除 / 不再 / removed / instead of），发现即清除或降级为 commit message
- = ZERO 与 DECISIONS 作为历史账本不受快照约束

### Z-11 开局工作流说明

场景：新项目首次触发本 skill（Phase 0 开始）。

▶ 用户：“我想做个读书笔记工具”

- = 首次回复先含一段简短工作流说明（3~5 句）：四阶段路径、五个文档角色、两道硬门槛（SPEC 未确认不写产品代码、决策由用户拍板）
- = 说明与 ZERO.md 捕获动作同轮呈现，不单独占用一轮交互
- = 说明简短：不逐条复述 SKILL.md、不展开各阶段细节
- = 后续会话不再重复该说明（用户主动询问流程除外）
