## 1. 交接场景（H）

### H-1 多轮开发会话的典型交接

场景：连续多轮实现 + 调试后会话收尾，工作区含已提交与未提交变更，会话中出现过失败尝试与未决问题。

▶ 用户："交接一下" / "生成交接提示词"

- = 全文仅一个 markdown 代码块，块外没有任何解释、总结或寒暄
- = 含全部 7 个必含节，标题与骨架一致；以第二人称对下一个 Agent 说话
- = 变更清单含真实文件路径，进度行含分支名与未提交状态，与 `git status` / `git diff --stat` 实测一致
- = 失败尝试写明"试了什么、为什么失败"；未验证结论标（待验证）、未决问题标（未决）

### H-2 AGENTS.md 已覆盖内容不重复

场景：项目根有 AGENTS.md（含运行命令、目录说明、代码约定），本会话未改动这些内容。

▶ 用户："会话快满了，给下个会话交接"

- = 不逐条搬运 AGENTS.md 已覆盖的内容（运行命令、目录地图、通用约定不重抄）
- = 第 8 节「补充（AGENTS.md 未覆盖）」无内容时整节省略，且其余节不因此缺项
- = 若确有偏差（如本会话新立约定、新环境变量），写入第 8 节

### H-3 无 AGENTS.md 项目回退补全

场景：项目没有 AGENTS.md（或已知目标会话不会自动注入）。

▶ 用户："把这次会话交接给下一个 agent"

- = 环境与运行方式、重要文件地图、约定与禁忌在第 8 节（或相应节）补回
- = 交接提示词自身即可让接手方独立开工

### H-4 确定与不确定分离

场景：会话中存在未经运行验证的猜测性结论，以及用户尚未拍板的开放问题。

- = 前者标（待验证），后者标（未决），不混入确定表述
- = 不出现编造内容：会话与仓库均无从佐证的"事实"不得写入

### H-5 敏感信息剔除

场景：会话中转述过 API Key / token / 数据库连接串。

- = 交接词中一律为 `<占位符>`，原文不出现

### H-6 反向不触发

场景：用户只说"总结一下这次会话"（要复盘要点，不打算换会话继续）。

- = 不进入交接提示词流程，按普通总结作答，不强行套 7 节骨架

## 2. 触发校准（静态评审）

日期：2026-11-11。方法：仅对照 `SKILL.md` 的 description 逐条做静态判定，**未发起新会话、不统计触发率**；真实触发率待后续会话回填。判定口径：明确要把当前会话交给新会话继续的请求为应触发；只要本会话总结 / 复盘、常规收尾或其他任务为不应触发。

### 2.1 应触发（8 条，静态判定）

| # | 查询 | 判定 |
| --- | --- | --- |
| 1 | 交接一下，我换个会话继续 | 应触发（交接 + 换会话） |
| 2 | 把这次会话交接给下一个 agent | 应触发（交接给下一个 agent） |
| 3 | 生成交接提示词，我要粘贴到新会话 | 应触发（生成交接提示词） |
| 4 | 会话快满了，帮我交接 | 应触发（会话收尾交接） |
| 5 | session handoff for this task | 应触发（英文 session handoff） |
| 6 | hand off this session to a new agent | 应触发（英文 hand off） |
| 7 | 换会话继续开发，先给我一段交接词 | 应触发（换会话继续） |
| 8 | 把当前进度和待办打包给接手的人 | 应触发（打包给接手方） |

### 2.2 不应触发（8 条，近邻反例）

| # | 查询 | 判定 |
| --- | --- | --- |
| 1 | 总结一下这次会话 | 不应触发（只要复盘） |
| 2 | 复盘一下我们做了什么 | 不应触发（复盘） |
| 3 | 写一份项目周报 | 不应触发（周报） |
| 4 | 记录一下今天的开发日志 | 不应触发（日志） |
| 5 | 这个任务已经完成了，帮我收个尾 | 不应触发（常规收尾） |
| 6 | 解释一下刚才那段代码 | 不应触发（问答） |
| 7 | 帮我提交这些改动 | 不应触发（提交任务） |
| 8 | 继续刚才的开发 | 不应触发（同一会话继续） |
