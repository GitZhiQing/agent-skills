# theme-commit 提交信息规范

按需加载：写提交信息，或项目对 footer / `BREAKING CHANGE` / scope 有额外约定时读取。默认格式已摘要进 `SKILL.md`；本文件是完整版。

默认遵循 Conventional Commits；项目有 commitlint / 模板 / hook 时以其为准。本仓库规范见 `docs/开发与维护规范.md` §10。

## Subject

- `type(scope): 摘要`，ASCII 冒号。
- `type` 取 `feat` / `fix` / `docs` / `refactor` / `test` / `chore` / `build`（项目另有 `perf` / `ci` / `style` / `revert` 等时按项目规范）。
- `scope` 用 skill / 模块 / 目录，跨模块用 `repo`。
- 摘要中文声明式动词开头，≤50 字，不加句号，**不写版本号**。

## Body

- subject 后空一行，用 `- ` 列表逐条说明，每条一个变更。
- 写清做了什么、为什么；版本变更放 body。
- 禁止"更新代码""修复问题"这类零信息摘要。

## Footer

- 可选：`BREAKING CHANGE: <说明>`、`Closes #123`、`Refs: #123`。
- 不自动添加 `Co-authored-by`。
- 破坏性变更：subject 加 `!` 或 body / footer 写 `BREAKING CHANGE:`，并按项目版本规则升 major。

## 示例

```text
feat(deep-research): 增加源码调研协议

- 阶段 1 识别源码调研，确认门列出源码获取计划
- 阶段 4 clone 到 sources/ 并固定完整 commit SHA
- 版本升至 0.6.0
```
