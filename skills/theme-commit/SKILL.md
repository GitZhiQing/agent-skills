# theme-commit：按主题分批提交

多轮开发后的工作区常混杂互不相关的变更，一次全量提交会让历史难以回溯与回滚。任务是把这些变更拆成多次干净的主题提交。

1. 通读全部变更（`git status`、`git diff`，untracked 文件直接读内容），归纳出逻辑主题，如：功能 A、依赖升级、格式化、文档。
2. 按主题逐个提交：`git add <该主题涉及的文件>` → `git commit -m "<该主题的一句话摘要>"`，直至所有变更归组完毕。
3. 单文件混入多个主题时直接整体提交，归入其主要主题的那次；不使用 `git add -p` 等 hunk 级拆分——对 agent 而言这类操作易错且收益低。
4. 结束前 `git status` 确认工作区干净，向用户汇报各次提交的主题清单。
