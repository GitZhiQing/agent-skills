# theme-commit 测试集

版本：v1.0（2026-09-10，随规范化补建）

行为协议断言，人工会话执行；编号「类别前缀-序号」，新场景追加不重排。

## 1. 提交场景（C）

### C-1 多主题工作区分批提交

场景：连续多轮开发后，工作区混杂 ≥3 个互不相关主题的变更（如功能实现 + 依赖升级 + 文档/格式化），含已跟踪与 untracked 文件。

▶ 用户："把这些改动分开提交" / "整理一下提交历史"

- = 按逻辑主题分组，产出多次提交，每次提交的文件全部属于同一主题
- = 每次提交信息为该主题的一句话摘要
- = untracked 文件按内容归组，不遗漏不误归
- = 结束时 `git status` 干净，并向用户汇报各次提交的主题清单

### C-2 单文件混入多主题

场景：某文件同时包含两个主题的改动。

- = 整体归入其主要主题的那次提交，不做文件内拆分
- = 全程不出现 `git add -p` 等 hunk 级操作

### C-3 单主题变更不强行拆分

场景：工作区变更只涉及一个主题。

▶ 用户："提交一下"

- = 正常单次提交，不产生无意义的空拆分

### C-4 反向不触发

场景：用户只是查看改动（"看下 diff"）或询问变更内容，未要求提交。

- = 不进入分批提交流程，仅按提问作答
