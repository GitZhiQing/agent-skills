# theme-commit

按主题分批提交：工作区混杂了多轮不同主题的变更时，把它们拆成多次干净的主题提交，而不是一次全量提交——让历史可回溯、可回滚。

## 何时触发

- 用户要求"提交一下""把改动分开提交""整理提交历史"，且变更明显涉及多个互不相关的主题（如功能 A、依赖升级、格式化、文档）；
- 单主题的常规提交不经过本 skill。

## 工作方式

1. **通读归纳**：`git status` + `git diff`（untracked 文件直接读内容），归纳出逻辑主题分组；
2. **逐主题提交**：每个主题 `git add <该主题文件>` → `git commit -m "<一句话摘要>"`，直至全部归组；
3. **单文件不拆分**：单文件混入多主题时整体提交、归入其主要主题，不做 hunk 级拆分（`git add -p` 对 agent 易错且收益低）；
4. **收尾确认**：`git status` 确认工作区干净，向用户汇报各次提交的主题清单。

## 边界

- 只做分组与提交，不改写历史、不碰远端；
- 单文件混多主题不做文件内拆分（见工作方式第 3 条）。
