## 1. 背景与目标

### 1.1 背景

AI coding agent 在回答问题时经常需要两类外部信息能力：

1. **联网搜索**：查找最新资料、验证事实、搜索代码与文档；
2. **网页抓取**：获取某个 URL 的正文内容用于阅读与总结。

本项目基于 Python 库 [deedy5/ddgs](https://github.com/deedy5/ddgs)（当前版本 **9.15.0**，多引擎元搜索库），封装为可供 coding agent 调用的 Skill，暴露两个工具：

- `ddgs_web_search` —— 文本搜索；
- `ddgs_web_fetch` —— 网页内容抓取。

### 1.2 设计定位（核心原则）

| 原则 | 含义 |
| --- | --- |
| **极简** | 功能只做"搜索 + 抓取"两件事，不堆特性；代码单文件、参数最少化 |
| **原生** | 仅用 Python 标准库 + `ddgs` 一个第三方依赖，不引入框架、不做 MCP server |
| **少依赖** | 依赖面 = ddgs（primp / lxml / httpx / click / fake-useragent）+ markdownify（含 bs4，`--curl` 模式 HTML 转换，v0.4 起引入） |
| **uv run 调用** | 通过 `uv run --project <skill_dir> <command>` 执行（`bin/` 启动器为等价封装，自动定位仓库），无需安装到系统环境，天然隔离、可移植 |
| **HTTP 代理支持** | 命令行 `--proxy` 与 `DDGS_PROXY` / `HTTPS_PROXY` / `HTTP_PROXY` 环境变量 |
| **纯文本输出（token 经济）** | 工具输出为紧凑纯文本而非 JSON，为 agent 上下文节约 token |

### 1.3 非目标（明确不做）

- 不做 MCP server（ddgs 官方已提供 `ddgs mcp`，但本项目按需求走 `uv run` CLI 路线）；
- 不做 images / news / videos / books 等其他类别搜索（列为未来扩展）；
- 不做 AsyncDDGS / 并发（ddgs 9.x 已移除 AsyncDDGS，且 agent 场景为串行调用）；
- 不做搜索缓存；网页抓取提供小型磁盘缓存（默认项目 `.cache/`，TTL 15 分钟，见 §4.2）；
- 不内嵌浏览器自动化（抓取用 ddgs 的 `extract()`，非 200 页面不伪装绕过）；
- 不写独立 Python 包发布到 PyPI（作为 skill 仓库随用随取）。

## 2. ddgs 现状调研结论（决策依据）

以下结论均直接核实自 ddgs 9.15.0 源码（`main` 分支）、PyPI 元数据与 README（2026-08-20）。

### 2.1 版本与依赖

- 最新版本 **9.15.0**（PyPI 发布于 2026-08-16），要求 **Python >= 3.10**，许可证 **MIT**。
- 依赖（`pyproject.toml` / PyPI `requires_dist`）：
  - `click>=8.1.8`（内置 CLI 使用，为传递依赖）；
  - `primp>=1.2.3` —— HTTP 客户端，deedy5 维护的 curl_cffi（curl-impersonate）分支；
  - `lxml>=4.9.4` —— HTML 解析；
  - `httpx[http2,socks,brotli]>=0.28.1` —— 源码注释标注 *"temporarily"*（仅 async API server 使用）；
  - `fake-useragent>=2.2.0`。
- 注意：v4.x 时代的 `curl_cffi` 已替换为 `primp`；9.x 中无 `bs4`（lxml 取代）。

### 2.2 API 映射（关键决策）

ddgs 在 v9.0.0 重写为多引擎元搜索后，**旧的 Web 搜索相关 API 已移除**，本项目两个工具直接映射到当前 API：

| 本项目工具 | ddgs 9.x 方法 | 说明 |
| --- | --- | --- |
| `ddgs_web_search` | `DDGS().text(query, ...)` | 多引擎文本搜索，返回 `list[dict]`，每项为 `{title, href, body}` |
| `ddgs_web_fetch` | `DDGS().extract(url, fmt)` | 抓取 URL 并转换格式，返回 `{"url": url, "content": content}` |

**已移除的历史 API**：`web_search()`、`get()`（原 `return_text` / `return_html` 参数）、`AsyncDDGS`、`DuckDuckGoSearchException`、`curl_cffi` 依赖。

**`text()` 实际签名**（`ddgs/ddgs.py`）：

```python
def text(self, query: str, **kwargs: Any) -> list[dict[str, Any]]:
    # 内部 _search_sync:
    def _search_sync(
        self, category: str, query: str,
        keywords: str | None = None,          # query 的废弃别名
        *,
        region: str = "us-en",                # 如 us-en / uk-en / ru-ru
        safesearch: str = "moderate",         # on | moderate | off
        timelimit: str | None = None,         # d | w | m | y（日/周/月/年）
        max_results: int | None = 10,
        page: int = 1,
        backend: str = "auto",                # 引擎名或逗号分隔列表
        **kwargs: str,
    ) -> list[dict[str, Any]]
```

文本结果 dict 固定三个字段：`title`、`href`、`body`（源码 `ddgs/results.py` TextResult）。

**`extract()` 实际签名**：

```python
def extract(self, url: str, fmt: str = "text_markdown") -> dict[str, str | bytes]:
```

- `fmt` 取值：`text_markdown`（默认，HTML→Markdown 保留链接/标题/列表）、`text_plain`、`text_rich`、`text`（原始 HTML）、`content`（原始字节）。
- **任何非 200 状态码都会抛 `DDGSException(f"Failed to fetch {url}: HTTP {status}")`** —— 没有容错返回。

**backend 可选引擎**（README "Engines" 表）：`auto`（默认，全部引擎打乱，文本类优先 wikipedia/grokipedia）、`all`、`bing`、`brave`、`duckduckgo`、`google`、`grokipedia`、`mojeek`、`startpage`、`yandex`、`yahoo`、`wikipedia`。注意 9.15.0 发布说明：**google、yandex 引擎当前处于禁用状态**。

### 2.3 代理机制（重要事实）

- `DDGS()` 构造签名：`DDGS(proxy: str | None = None, timeout: int | None = 5, *, verify: bool | str = True)`。
- **ddgs 只读 `DDGS_PROXY` 环境变量，不会自动读取 `HTTP_PROXY` / `HTTPS_PROXY`**：

  ```python
  self._proxy = _expand_proxy_tb_alias(proxy) or os.environ.get("DDGS_PROXY")
  ```

- 代理协议：底层 primp 支持 `http` / `https` / `socks5`（仓库自带示例用 `socks5h://127.0.0.1:9150`；特殊别名 `"tb"` = Tor）。
- 结论：**我们的薄 CLI 必须自己做环境变量翻译**（`HTTPS_PROXY`/`HTTP_PROXY` → 构造参数），这是设计中的必做项。

### 2.4 异常与限流现状

`ddgs/exceptions.py` 仅有三个异常类：

```python
class DDGSException(Exception):      # 基类
class RatelimitException(DDGSException):  # 限流 —— 9.x 已定义但未在任何代码路径抛出
class TimeoutException(DDGSException):    # 超时（primp.TimeoutError 包装）
```

- `TimeoutException`：HTTP 层超时、或引擎错误信息含 "timed out"。
- `DDGSException`：空查询（"query is mandatory."）、`extract()` 非 200、引擎失败、以及**全引擎无结果时抛 "No results found."**。
- **限流识别陷阱**：9.x 中引擎对非 200 响应静默返回 `None`，429 实际表现为 `DDGSException("No results found.")`，不会抛 `RatelimitException`。因此 CLI 必须把 "No results found." 当作**正常空结果**处理（exit 0），同时在 SKILL.md 中提示"连续空结果可能是被限流，应退避重试"。
- 库本身无自动节流；官方 AGENTS.md 要求测试间至少 **2 秒**停顿以防引擎限流。SKILL.md 使用规则须写入该纪律。

### 2.5 内置 CLI / MCP 的对比（为什么不用官方 CLI）

ddgs 自带 click CLI（`ddgs` 命令：`text`/`extract`/`images`/`videos`/`news`/`books`/`mcp`/`api`，支持 `-pr/--proxy`、`-o json|csv`）和 MCP server（`ddgs mcp`，工具 `search_text`/`extract_content` 等）。

**本项目弃用官方 CLI、自研薄 CLI 的理由**：

1. 官方 CLI 的 JSON 输出必须写文件（`-o results.json`），agent 需要"执行 + 读文件"两步，且文件名/路径管理繁琐；
2. 默认 stdout 是彩色 key/value 文本，非 TTY 下虽自动去色，但格式对 agent 解析不友好；
3. 官方 CLI 错误信息与退出码语义不可控（`safe_entry_point` 统一 try/except）；
4. 自研薄 CLI 约 150 行即可给出"stdout=纯文本结果、stderr=错误、退出码 0/1/2"的稳定契约，且可内置代理环境变量翻译。

弃用 MCP 的理由：需求明确"工具通过 `uv run` 调用"，不引入 MCP 协议栈；MCP 需要 agent 客户端支持 MCP 通道，通用性低于 Bash 调用 CLI。

## 3. 需求规格

### 3.1 功能需求（FR）

| 编号 | 需求 | 验收标准 |
| --- | --- | --- |
| FR-1 | `ddgs_web_search`：按关键字搜索网页文本结果 | 输入 `query` 必填；输出为有序结果列表，每项含标题、URL、摘要；`exit 0` |
| FR-2 | `ddgs_web_fetch`：抓取一个或多个 URL 正文 | 输入 `url` 必填（可多个，批量抓取）；输出页面转换后内容（默认 Markdown），批量时以 `===== <url> =====` 分隔；全部成功 `exit 0`，任一失败 `exit 1`（其余照常输出）；默认模式失败时**自动回退**系统 curl 抓取（404/410 死链除外），`--curl` 参数为强制 curl 模式（输出契约一致，Markdown/纯文本为尽力转换） |
| FR-3 | 纯文本输出，节约 token | 搜索结果采用紧凑块格式（见 §4.1），不输出 JSON 键名；抓取内容默认截断 5000 字符（社区实践参考：MCP fetch server 默认 max_length=5000）；stderr 与 stdout 分离 |
| FR-4 | HTTP/HTTPS/SOCKS5 代理支持 | `--proxy <url>` 优先级最高；未指定时依次回退 `DDGS_PROXY` → `HTTPS_PROXY` → `HTTP_PROXY` 环境变量 |
| FR-5 | 稳定的错误契约 | 退出码：`0` 成功（含空结果）、`1` 运行错误、`2` 参数错误；错误信息只写 stderr，含异常类型 |
| FR-6 | 限流友好 | "No results found." 捕获为空结果（exit 0 + stderr 提示）；SKILL.md 规定调用间隔 ≥2s 与退避重试策略 |
| FR-7 | 超时可控 | CLI 暴露 `--timeout`（默认 10s，透传 `DDGS(timeout=)`），超时以 `TimeoutException` 语义报错（exit 1）；搜索路径对瞬时异常自动重试一次（间隔 2s，stderr 提示 `retrying`），仍失败才 exit 1 |
| FR-8 | 结果量可控 | `--max-results` 默认 10；`--timelimit`（d/w/m/y）与 `--region`、`--safesearch`、`--backend` 透传给 ddgs |
| FR-9 | 抓取磁盘缓存 | 抓取结果按 URL+格式缓存到项目 `.cache/`（TTL 15 分钟，与常见 agent 内置 WebFetch 工具一致）；`--no-cache` 绕过（同时跳过读与写），`--cache-dir` / `DDGS_WEB_ACCESS_CACHE` 换目录；命中时 stderr 提示 `cache hit`，不发网络请求 |

### 3.2 非功能需求（NFR）

| 编号 | 需求 | 指标 / 约束 |
| --- | --- | --- |
| NFR-1 | 极简 | 实现代码为**单个 Python 文件**（`ddgs_web_access.py`）；依赖 `ddgs>=9.15,<10` + `markdownify` |
| NFR-2 | 原生 | 仅 Python 标准库（`argparse`、`os`、`sys`）+ ddgs；无框架、无 async 复杂度 |
| NFR-3 | 环境要求 | Python >= 3.10；uv >= 0.5；Windows / macOS / Linux 均可（uv 抽象了解释器差异） |
| NFR-4 | 性能 | 冷缓存首次调用（含安装依赖）目标 ≤ 60s（视网络）；热缓存单次搜索 ≤ 15s（ddgs 多引擎并发）；超时兜底 10s |
| NFR-5 | Token 效率 | 搜索结果输出为每结果 ≤ 3 行紧凑文本，无 JSON 结构开销；抓取内容支持 `--max-chars` 截断（默认 50000 字符 ≈ 1.2 万 token） |
| NFR-6 | 可靠性 | 任何异常不产生 Python traceback 泄漏到 stdout；退出码语义稳定（0/1/2）；错误信息含异常类名便于 agent 决策 |
| NFR-7 | 可维护性 | CLI 参数名与 ddgs 官方 CLI 保持一致（`-q/-r/-s/-t/-m/-pr` 等），降低学习成本；单文件便于整体替换升级 |

### 3.3 约束与假设

1. **联网**：搜索与抓取需要外网访问；首次 `uv run` 需从 PyPI 拉取依赖，网络受限时可通过 `UV_INDEX_URL` 指向镜像（如 `https://pypi.tuna.tsinghua.edu.cn/simple`），**不在 pyproject 中硬编码镜像**。
2. **不依赖系统 Python**：不假设宿主机装有系统级 Python / `py` 启动器，一切通过 uv 托管的解释器运行 —— 这是选择 `uv run` 的根本原因。
3. **ddgs 版本锁定**：依赖声明 `ddgs>=9.15.0`（保持 <10 的隐式约束？）。因 9.x 仍在快速演进，设计按 9.15 源码为准；升级 ddgs 后需回归 §9 冒烟用例。建议实现时用 `ddgs>=9.15,<10` 锁定大版本。
4. **ddgs 免责声明**：官方 README 声明 "This library is for educational purposes only"，本项目按"工具提供方不承担搜索内容合规责任"处理，见 §7。

## 4. 工具规格

### 4.1 `ddgs_web_search` 工具规格

**命令**：`ddgs-web-search`

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `query` | 位置参数 | ✅ | — | 搜索关键字，原样透传 `DDGS().text(query=...)` |
| `-r, --region` | str | | `us-en` | 区域，如 `us-en` / `uk-en` / `ru-ru` / `wt-wt` |
| `-s, --safesearch` | str | | `moderate` | `on` / `moderate` / `off` |
| `-t, --timelimit` | str | | 无 | `d`（天）/ `w`（周）/ `m`（月）/ `y`（年） |
| `-m, --max-results` | int | | `10` | 1–50，透传 `max_results` |
| `-b, --backend` | str | | `auto` | 引擎或逗号列表（`bing`/`brave`/`duckduckgo`/`wikipedia` 等） |
| `--timeout` | int | | `10` | `DDGS(timeout=)`，秒 |
| `--proxy` | str | | 环境变量 | http/https/socks5 URL，优先级最高 |
| `--format` | str | | `text` | `text`（默认）/ `json`（逃生口，输出 JSON 数组） |
| `--urls` | flag | | 关 | 只输出每行一个 `href`，与 `--format` 互斥；适合串联批量抓取 |

**输出格式（默认 `text`，纯文本块）**：

```
1. <title>
   <href>
   <body 摘要文本……>

2. <title>
   <href>
   <body 摘要文本……>
```

- 每条结果 3 行：序号 + 标题 / 缩进 URL / 缩进摘要；结果块之间空行分隔；
- 无结果：stdout 无内容，stderr 输出一行 `ddgs-web-search: no results found.`（提示可能被限流），`exit 0`；
- `--format json`：输出 `[{"title": ..., "href": ..., "body": ...}, ...]`（保留为结构化逃生口，默认不使用）。

**示例**：

```
$ uv run --project <skill_dir> ddgs-web-search "python 3.13 asyncio" -m 3 -t m

   The "What's New in Python 3.13" article explains the new features in this release ...

3. asyncio in Python 3.13
   https://docs.python.org/3/library/asyncio.html
   Source code: Lib/asyncio/ ...
```

### 4.2 `ddgs_web_fetch` 工具规格

**命令**：`ddgs-web-fetch`

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `url` | 位置参数（可多个） | ✅ | — | 目标 URL（支持批量），逐个透传 `DDGS().extract(url=...)` |
| `-f, --format` | str | | `text_markdown` | `text_markdown`（默认）/ `text_plain` / `text_rich` / `text`（原始 HTML）/ `content`（二进制，输出到文件） |
| `--max-chars` | int | | `5000` | 截断内容长度（字符）；默认值参考 MCP fetch server 社区实践（5000 字符分块阅读），长文按需调大；`0` = 不截断 |
| `--start` | int | | `0` | 跳过内容前 N 字符，与 `--max-chars` 配合分段读长文；`-f content` 二进制模式忽略 |
| `--timeout` | int | | `10` | `DDGS(timeout=)`，秒 |
| `--proxy` | str | | 环境变量 | 同 `ddgs_web_search` |
| `--cache-dir` | path | | 项目 `.cache/` | 抓取缓存目录（`DDGS_WEB_ACCESS_CACHE` 环境变量亦可） |
| `--no-cache` | flag | | 关 | 绕过缓存，强制网络抓取 |
| `--curl` | flag | | 关 | 强制使用系统 curl 抓取（跳过 ddgs extract）；默认模式下 ddgs 抓取失败（403、超时等，404/410 死链除外）会**自动回退**到 curl（stderr 提示 `retrying with curl`），遵循同一输出契约，text_markdown/text_plain 为 stdlib 尽力转换 |

**输出**：`extract()` 返回的 `content` 直接写 stdout（Markdown/纯文本原样）；`fmt=content`（二进制）时写文件并在 stdout 打印文件路径；**批量抓取**（多个 url）时每个页面以 `===== <url> =====` 行分隔（单 URL 保持无分隔符输出），任一 URL 失败不影响其余页面输出，但整体退出码为 1。

- 截断发生时在 stderr 提示一行 `ddgs-web-fetch: <url>: truncated at N chars (continue with --start M)`（M 为续读偏移），stdout 保持纯内容；`--start` 超出内容长度时 stderr 提示 `beyond end of content`、stdout 为空、exit 0。
- 非 200 或网络错误：该 URL 的错误以 `<url>: <type>: <message>` 格式写到 stderr，整体 `exit 1`，其余 URL 继续处理。
- 缓存：命中时 stderr 提示 `ddgs-web-fetch: <url>: cache hit`；缓存键为 `sha256(mode|fmt|url)`（mode 区分 ddgs/curl 两种抓取来源，避免结果混淆），TTL 15 分钟。

**curl 回退（自动 + 强制）**：默认模式下 ddgs extract 失败（403、超时、5xx、网络错误等）时自动改走系统 curl，stderr 提示 `<url>: <type>: <msg>; retrying with curl`，curl 也失败才报错 exit 1；404/410 死链不回退（curl 结果相同，避免对死链发两次请求）。`--curl` 为强制模式：直接用系统 curl，不先试 ddgs。curl 参数（`-sS -f -L --compressed --max-time <timeout>`，`-x` 透传解析后的代理，浏览器 UA）与内容转换（markdownify / bs4 + 样板剥离）不变。缓存方面：回退成功的结果存 `mode="curl"` 键；默认模式的缓存查找先查 `ddgs` 键、未命中再查 `curl` 键（避免回退后仍重复发请求）。跨平台差异处理：`shutil.which("curl")` 定位（Windows 10+ 自带 curl.exe、Git Bash 亦带、macOS/Linux 预装），缺失时明确报错；子进程捕获原始字节，避开 Windows 控制台文本模式对二进制的污染；`--compressed` 自动解压 gzip；`-f` 使非 2xx 与 ddgs 路径一致地映射为错误（curl exit 22），超时映射 exit 28。内容解码按页面 `<meta charset>` 声明（无声明则 utf-8 → gbk → latin-1 回退）；`text_markdown` / `text_rich` 用 markdownify（ATX 标题、`-` 列表）转换，`text_plain` 用 bs4 `get_text` 提取；转换前统一用 bs4 剥离样板内容（nav/header/footer/aside 等标签 + breadcrumb/related/sidebar 等 class/id 提示词，启发式同 readability）。

**示例**：

```
$ uv run --project <skill_dir> ddgs-web-fetch "https://docs.python.org/3/whatsnew/3.13.html" -f text_plain --max-chars 20000
Python 3.13 documentation
This article explains the new features in Python 3.13, compared to 3.12 ...
```

### 4.3 通用 CLI 约定（两个工具共用）

| 通道 | 内容 |
| --- | --- |
| stdout | 仅结果纯文本（或 `--format json` 的结构化输出）；成功路径无任何日志/警告 |
| stderr | 一切提示与错误：`<tool>: <type>: <message>` 或 `<tool>: <message>` 单行格式 |
| 退出码 | `0` 成功（含空结果）；`1` 运行错误（DDGSException / TimeoutException / 网络错误）；`2` 参数错误（argparse 默认，自动提示 usage） |
| 代理 | `--proxy` > `DDGS_PROXY` > `HTTPS_PROXY` > `HTTP_PROXY`（CLI 完成翻译，ddgs 本身只认 `DDGS_PROXY`） |
| 帮助 | 两命令均提供 `--help`，参数说明与 ddgs 官方 CLI 一致 |

不创建 `src/` 包、不建 `uv.lock` 提交策略另行约定（uv 自动生成）。

### 5.2 调用链路

```
coding agent
   │  (按 SKILL.md 指引)
   ▼
Bash: bash "<skill_dir>/bin/ddgs-web-search" "query" -m 5 [--proxy http://...]
     （等价：uv run --project "<skill_dir>" ddgs-web-search "query" -m 5）
   │
   ▼
pyproject.toml [project.scripts]
   │  ddgs-web-search → ddgs_web_access:web_search_main
   │  ddgs-web-fetch  → ddgs_web_access:web_fetch_main
   ▼
ddgs_web_access.py（argparse 解析 → 代理解析 → 调用 DDGS()）
   │
   ▼
ddgs 9.x 库（primp HTTP 客户端 → 多引擎并发 / extract）
   ▼
stdout=纯文本结果 / stderr=错误 / exit code
```

关键点：

- **不依赖 cwd**：SKILL.md 使用 `<skill_dir>` 占位（本 skill 目录即仓库根），推荐经 `bin/` 自定位启动器调用（等价 `uv run --project <skill_dir>`，见 §8.1），任何工作目录、任何安装位置均有效；
- **无 `--with` 临时依赖**：ddgs 声明在 pyproject `dependencies` 中，`uv run` 自动解析并复用锁定的虚拟环境，比每次 `uv run --with ddgs` 更稳定、缓存更优；
- **首次调用**：uv 自动创建 `.venv` 并安装依赖（联网），后续调用直接命中缓存。

### 5.3 薄 CLI 详细设计（`ddgs_web_access.py`）

结构（约 150 行，纯标准库）：

```
ddgs_web_access.py
├── resolve_proxy(args) -> str | None
│     --proxy > DDGS_PROXY > HTTPS_PROXY > HTTP_PROXY
├── default_cache_dir() / cache_get() / cache_put()
│     默认项目根 .cache/（editable 安装时模块与 pyproject 同目录，可直接定位）；
│     key = sha256(fmt|url)，TTL 15 分钟，best-effort 不抛错
├── build_ddgs(proxy, timeout) -> DDGS        # DDGS(proxy=..., timeout=...)
├── curl 回退（--curl）
│     _curl_fetch(): 系统 curl，-sS -f -L --compressed --max-time -A -x
│     _decode_html(): <meta charset> 声明优先，utf-8/gbk/latin-1 回退
│     _drop_boilerplate(): bs4 剥离样板（标签 + class/id 提示词）
│     _markdown_text / _plain_text: markdownify / bs4 转换
├── web_search_main(argv) -> int
│     argparse: query, -r/-s/-t/-m/-b/--timeout/--proxy/--format
│     DDGS().text(...)
│     捕获 DDGSException("No results found.") → stderr 提示 + 0
│     渲染纯文本块或 JSON
├── web_fetch_main(argv) -> int
│     argparse: url, -f/--format/--max-chars/--timeout/--proxy
│     DDGS().extract(url, fmt)
│     截断、渲染（fmt=content 写文件）
└── 公共错误处理
      except TimeoutException → exit 1
      except DDGSException  → exit 1
      except Exception      → exit 1（含异常类名，不泄漏 traceback）
```


### 5.4 代理解析设计

```
解析顺序（第一个非空生效）：
1. --proxy 命令行参数
2. DDGS_PROXY 环境变量（ddgs 官方约定，含 "tb" 别名 = socks5h://127.0.0.1:9150）
```

- 结果传给 `DDGS(proxy=...)`，协议 http/https/socks5 均可（由 primp 支持）；

### 5.5 错误处理与退出码（汇总）

| 场景 | 退出码 | stdout | stderr |
| --- | --- | --- | --- |
| 搜索成功（≥1 结果） | 0 | 结果块 | 空 |
| 搜索无结果（含被限流伪装） | 0 | 空 | `no results found.` |
| 抓取成功 | 0 | 内容 | 空（截断时提示 `truncated at N chars`） |

### 5.6 SKILL.md 设计要点（草案见 §6）

- **触发策略**：description 写"主动触发"场景（联网搜索、找资料、抓网页、验证事实），并给出非触发场景（本地文件、已有内容不需要正文）；

- **故障处置**：首次调用较慢属正常（安装依赖）；反复失败提示检查网络/代理。

## 7. 安全与合规

1. **免责声明**：ddgs 官方 README 声明库"仅供教育目的"；本项目作为其薄封装，README 与 SKILL.md 中保留该声明，提示使用者遵守目标网站服务条款与 robots 协议；

## 8. 安装与集成（多 agent / 多项目分发）

### 8.1 核心机制：自定位启动器（bin/）

- `bin/ddgs-web-search` / `bin/ddgs-web-fetch`（bash）+ 同目录 `.cmd` 变体（Windows cmd/PowerShell）：脚本用 `dirname $0` 推导仓库根，再 `uv run --project <仓库根> <命令>`——**不依赖 cwd、不依赖安装位置**（复制、链接、移动均有效）；
- Git Bash 下用 `cygpath -w` 将仓库路径转为 Windows 形式传给 uv，避免 MSYS 路径歧义；
- SKILL.md 只引用 `<skill_dir>`（本 skill 所在目录），不再硬编码任何绝对路径。

### 8.2 一键安装（scripts/install.sh）

- 自动在本机已安装 agent 的 skills 目录下创建指向本仓库的链接：Windows 用 junction（`mklink /J`，免管理员权限），Unix 用符号链接；
- 目标目录按存在性探测，默认覆盖采用 Agent Skills 格式的主流 agent 全局位（ZCode、Claude Code、Cursor、Codex、Copilot、Gemini CLI、opencode、Windsurf、Cline、Roo、Qwen、Kilo、Junie、Trae 及跨端通用目录 `~/.agents/skills`）；也可传位置参数显式指定目录（含某个项目的 `.agents/skills`）；完整清单与依据见仓库根 `docs/开发与维护规范.md` §6，与根脚本 `scripts/lib.sh` 的内置清单保持一致；
- **单一来源**：所有 agent 指向同一仓库，更新（git pull）后全端生效；抓取缓存（仓库 `.cache/`）跨 agent、跨项目共享；
- 幂等（已存在链接跳过，创建后校验存在性）；`scripts/uninstall.sh` 仅删除**指向本仓库**的链接（readlink 校验目标），不触碰其他内容；
- 勘误记录：`MSYS2_ARG_CONV_EXCL="*"` 会禁用 `//c` 折叠，cmd 调用必须用单斜杠 `cmd /c`，否则 cmd 进入交互模式、mklink 静默不执行。

### 8.3 其他安装方式

| 方式 | 做法 | 适用场景 |
| --- | --- | --- |
| 手动复制 | 把仓库复制到 agent skills 目录（如 `~/.claude/skills/ddgs-web-access/`） | 无法建链接的环境 |
| PATH 模式 | `export PATH="<skill_dir>/bin:$PATH"` 后直接 `ddgs-web-search ...` | 仅命令行、无需 agent 集成 |
| uv run 直接调用 | `uv run --project "<skill_dir>" ddgs-web-search ...` | 调试与等价验证 |

### 8.4 权限配置

- `allowed-tools` 同时声明 `Bash(uv run *)` 与 `Bash(bash *bin/ddgs-web-search *)` / `Bash(bash *bin/ddgs-web-fetch *)`，覆盖两种调用形态；
- 若 agent 环境有命令白名单，加入 `uv run --project * ddgs-web-search *`、`ddgs-web-fetch *` 及 `bin/ddgs-web-*`。

## 10. 风险与开放问题

| 风险 / 问题 | 影响 | 对策 / 开放决策 |
| --- | --- | --- |
| PyPI 网络不可达（受限网络环境） | 首次安装失败 | README 提供 `UV_INDEX_URL` 镜像示例（清华源）；不硬编码进 pyproject |
| ddgs 9.x 仍在快速演进（httpx 依赖标注 temporary、引擎列表变化） | 未来升级可能破坏契约 | 锁定 `ddgs>=9.15,<10`；升级后回归 §9 全部用例 |
| google / yandex 引擎当前禁用 | 少两个引擎来源 | 接受现状；backend 透传设计天然兼容 |
| RatelimitException 已不抛出 | 限流表现为 "No results found." 难以区分 | 已设计为空结果 + stderr 提示；SKILL.md 规定退避重试 |
| `extract()` 对非 200 一律报错 | 部分站点（403 反爬）无法抓取 | 接受现状；后续可评估底层 `HttpClient` 自定义 user-agent 的可行性（开放问题） |
| 抓取内容长度 | 大页面可能膨胀上下文 | `--max-chars` 默认 5000（参考 MCP fetch server 社区实践），长文按需调大或 `0` 不限；阈值可继续实测调优 |
| 抓取缓存陈旧 / 明文 | 页面内容可能过期；缓存文件为明文 | TTL 15 分钟；敏感页面用 `--no-cache`；缓存目录可用 `--cache-dir` / `DDGS_WEB_ACCESS_CACHE` 迁移 |
| `--format json` 逃生口 | 默认文本下结构化场景受限 | 保留但默认不用；是否移除视实际使用反馈 |
| Windows 路径 / 引号 | Git Bash 向原生程序传路径有 MSYS 转换歧义（如 `//c` 折叠、路径重写） | `bin/` 启动器统一用 `cygpath -w` 转 Windows 路径；SKILL.md 只用 `<skill_dir>` 占位；cmd 调用必须用单斜杠 `cmd /c`（见 §8.2 勘误记录） |
| 未来扩展 | images/news/videos/books、MCP 模式 | 列为后续迭代项，不影响当前极简架构 |
