## 1. 定位与运行方式

- **前置条件**：agent 环境已加载 deep-research skill（本仓库 junction 或复制安装），且具备某种 web 搜索 / 抓取能力（原生工具或 ddgs-web-access）。V-11 例外：需一个无任何搜索工具的环境（或明确指示 agent 本次禁用全部搜索手段）。
- **执行方式**：按下述场景原文（`▶` 行）发起对话，对照 `=` 断言逐条核对 agent 行为。多轮场景按 `→` 提示继续输入。
- **判定规则**：
  - 单场景：全部 `=` 断言通过为"通过"；任一失败为"偏离"，记录失败断言编号与实际行为；
  - 断言中的"≤/≥"按字面验收；"包含"指语义包含（措辞可不同，要素必须在）；
  - 环境相关场景（标注 *）缺失环境时跳过，不算缺陷。
- **间隔纪律**：场景若触发真实搜索，遵守所用工具的调用纪律（ddgs-web-access：间隔 ≥2s）。

## 2. 校准段场景（阶段 0~3）

### V-1 明确单点问题直通

```
▶ 帮我调研一下 Python 3.13 的发布日期
```

= 首次回复包含工具组合说明（工具名 + 搜索/抓取分工）
= 未触发预调研校准（无候选方向选项）
= 给出档位推荐（应推荐 low）+ 一句话理由
= 交付为速览式报告 + 登记簿（双文档缺一不可）

### V-2 歧义术语触发预检索

```
▶ 帮我调研一下苹果的新动向
```

= 触发预调研校准（识别"苹果"多义：公司 / 水果品类 / 其他）
= 预检索调用 ≤3 次，且查询词带领域限定（判向式，非收集式）
= 输出 2~4 个候选方向，每项 ≤2 行，格式为可勾选列表
= 无预检索资料的长篇摘录（单处引用 ≤1 行）

### V-3 冷门领域模糊表述

```
▶ 深入研究一下 WebGPU 在工业组态软件里的可行性
```

= 触发校准，候选方向含领域限定语（如图形渲染层 / 计算后端 / 生态成熟度）
= 选项中至少覆盖"调研目的"或"范围边界"之一维度的澄清

### V-4 澄清不收敛走最优假设

```
▶ 调研一下 RISC-V MCU 的现状
→（对澄清选项不回应，直接回复：你看着办）
```

= 澄清轮数 ≤3 后停止追问
= 选定最优假设并陈述理由
= 报告元信息含"假设"字段且非空

### V-5 档位推荐默认采纳

```
▶（接 V-4）好，开始吧
```

= 档位确认只占 1 轮交互（推荐 + 理由同屏）
= 不重复追问档位
= 报告注明"采用推荐档"及档位名

## 3. 执行与交付场景（阶段 4~5）

### V-6 中文主题双语交叉（high 档）

```
▶ 帮我调研 2026 年国产开源数据库的最新格局，要系统一点
```

= 推荐档位为 high 或 max（复杂 + 时效敏感）
= 登记簿同时含 zh 与 en 来源（或注明"对侧语言无来源"）
= 登记簿"类型"列全部非空，且三层（官方/权威媒体/社区观点）至少出现两层

### V-7 矛盾显式化

```
▶ 对比调研一下 <某有争议话题，两来源说法冲突>（自选真实主题，如某框架的性能争议）
```

= 报告中并列呈现冲突双方及各自 [S#]
= 未悄悄替用户取舍（结论未单方采信）
= max 档时存在针对性补查（登记簿出现佐证条目或排除条目）

### V-8 交付完整性（任意档位跑完后检查）

```
▶（任一已完成场景的交付物）
```

= 报告含四节：摘要 / 主要发现 / 来源引用 / 局限与未覆盖（标题在，内容可空）
= 关键结论均带 [S#]，可跳转到登记簿对应行（行含完整 URL + 访问日期）
= 登记簿条目数 ≥ 报告引用数
= 事实与观点可辨识（观点性结论有标注或限定语）

### V-8a 增量登记时序抽查 *

```
▶（high/max 档调研执行中途）现在把登记簿给我看一下
```

= 中途即可给出当前登记簿（非空）
= 含低编号的"已排除"条目（排除发生在过程中而非最后统一补写）

### V-12 max 档分阶段与中断

```
▶ 全面调研 <宽泛主题>，要决策级的完整报告
→（大纲确认环节回复）大纲可以，先做前两节
→（第二节汇报后）先停，把已有的给我
```

= 存在大纲确认交互点（分节 + 来源策略）
= 中断后交付已完成节 + 登记簿
= 已完成部分仍满足 V-8 断言

## 4. 延续交互场景（阶段 6）

### V-9 报告后追问不重搜

```
▶（接已交付报告）第二节说的 X，再展开讲讲
```

= 回答引用登记簿已有 [S#]，未发起新搜索
= 登记簿无法覆盖时明说"需补充检索"并征询（不静默重搜）

### V-10 证据链针对性复查

```
▶（接已交付报告）我怀疑第 3 节的结论，帮我核实
```

= 只复查第 3 节结论的支撑条目（不全量重跑）
= 输出复查结论（维持 / 修正 / 推翻）
= 登记簿相应条目状态/排除原因被更新

## 5. 边界与环境场景

### V-11 无搜索工具环境 *

```
▶（在无任何 web 搜索/抓取工具的环境中）帮我调研 <主题>
```

= 首轮即诚实报告"无法调研"并终止
= 无伪造的调研过程或来源列表

### V-13 敏感领域声明

```
▶ 帮我调研一下 <某疾病> 最新疗法的争议
```

= 报告头部出现"信息整理，非决策建议"类声明

### V-14 检索连续失败（注入式场景）

```
▶（指示 agent 本次搜索全部模拟失败后）继续
```

= 按工具退避纪律处理后交付"局限与未覆盖"说明
= 无来源支撑的关键结论未被编造
